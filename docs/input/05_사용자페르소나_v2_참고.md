# **거산케미칼 AI 영업지원 AGENT** **사용자 페르소나 v2.0**

현장 업무 시나리오 · 사용성 검증 기준 · 협업 흐름

작성 기준: 2026.10.15  |  성격: 개발·파일럿 검증용 개선안

# **문서 사용 안내**

본 문서는 기존 「거산케미칼 사용자 페르소나」와 「AI 영업지원 AGENT 페르소나 검토 및 개선 피드백」을 통합·보완했다. 실무자별로 “무엇을 보여줄지”뿐 아니라 “실제로 업무가 끝나는지”를 판단하기 위한 검증 기준을 추가했다.

근거 구분: \[면담 기반\]은 기존 문서에 수록된 2026.09.10 면담 요지, \[기존 가정\]은 원문에서 가정으로 밝힌 설정, \[v2 제안\]은 구현·검증을 위해 새로 정의한 항목이다. 아래 시간·클릭·성공률 목표는 실측 결과가 아닌 파일럿 목표치다.

# **1\. 한눈에 보는 4개 페르소나**

| 역할 | 첫 질문 | 핵심 행동 | 하지 않는 행동 |
| :---- | :---- | :---- | :---- |
| **영업담당자 / 박 담당** | 오늘 어디에 연락하고 무엇을 물어볼까? | 이력 확인·재접촉·판단·후속 기록 | 기술·인증 최종 검수 |
| **대표 / 이 대표** | 무슨 일이 막혔고 누가 풀어야 하나? | 요약 확인·자료 제공·우선순위 정리 | 일상 영업 입력 |
| **신입사원 / 최 신입** | 어디까지 진행됐고 내가 해도 되나? | 조회·문의 접수·내부 전달 | 접촉 승인·미확인 정보 외부 발송 |
| **기술·품질 / 검수자** | 고객 요구에 실제로 대응 가능한가? | 공정·인증 검토·근거·회신 | 근거 없는 기술 보증 |

기본 원칙: 기존 고객의 재접촉·납기·품질·미처리 업무를 신규 발굴보다 우선하되, 신규/재접촉 프로필의 평가표와 점수를 한 줄 순위로 섞지 않는다. AGENT는 ERP 복제가 아닌 “근거와 다음 행동을 제안하는 판단 지원 도구”여야 한다.

# **2\. 페르소나별 업무 정의와 사용성 검증**

## **2.1 영업담당자 — 박 담당 (가명)**

\[면담 기반\] 영업·납품·고객 응대가 결합된 업무. 소개·입소문 및 기존 거래처 관리가 중요하며, 문의는 전화·메일·도면 또는 사진으로 들어온다. PC 자료는 개인별로 흩어져 있다. \[기존 가정\] 48세/15년 근속, 전화 중 1\~2분 사용.

핵심 목표: 통화 중 이전 이력과 다음 질문을 빠르게 이해하고, 통화 뒤 최소 입력으로 후속 약속을 남긴다.

* 첫 화면: 재접촉 기한 초과 → 오늘 연락 대상 → 제안/다음 행동. 점수 E·P는 기본 접기.  
* 기회 상세: 제안 → 확인 질문 최대 3개 → 근거 상태 → 활동 이력 → 사람의 판단(의견·접촉 결정·실행·결과).  
* 실행: 선택 3회와 한 줄 메모로 기본 기록, 다음 연락일 설정, 필요 시 기술 확인 요청.  
* 모바일 390px 폭에서 주요 내용 읽기·기록 가능. 전략보고서는 “내부용·고객 제출용 아님” 표시.

### **시나리오 S1. 기존 고객 재접촉**

상황: 납품 이동 중 지난주에 다시 연락하기로 한 거래처의 기한이 지났다.

1. 홈의 기한 초과 항목을 찾는다.  
2. 최종 상담·약속과 AI 제안 이유 및 확인 질문을 읽는다.  
3. 고객에게 연락하고 결과·후속 일자를 간단히 기록한다.  
4. 기한 초과 목록에서 처리 상태가 갱신됐는지 확인한다.

합격 관찰 포인트: 60초 안에 직전 상담 맥락 파악, 기본 기록 3회 선택+한 줄 메모 이내, 기한 초과가 누락되지 않음.

### **시나리오 S2. 도면 없는 신규 견적 문의**

상황: 기존 거래처가 사진만 보내며 백색 도금 견적을 문의한다.

5. 고객/기회를 검색하고 관련 이력을 본다.  
6. 백색 일반/무광, 두께, 수량(월/연), 도면 유무, 납기를 확인한다.  
7. 미확인 공정 조건은 기술·품질 검토를 요청한다.  
8. 고객에 대한 회신 약속일과 내부 메모를 남긴다.

합격 관찰 포인트: AI 추정치를 확정된 공정 가능 여부로 전달하지 않고 누락 요구사항을 표시함.

## **2.2 대표 — 이 대표 (가명)**

\[면담 기반\] 작은 디지털 성과부터 단계적으로 검증하기 원하며, 보안·기록의 지속성·회사 자료 확보에 관심이 크다. 기존 시안이 ERP처럼 보인다는 의견이 있었다. \[기존 가정\] 주 1회, 약 5분 사용.

핵심 목표: 상세 분석 없이 막힌 업무와 필요한 자료, 담당자, 다음 조치를 파악한다.

* 요약 한 장: 이번 주 접촉 후보, 판단 대기, 재접촉 지연, 이번 달 기록, 인증·공정 상태, 가상 데이터 수(6개).  
* “거산이 줄 것”: 인증서/공정 범위/고객 요구 등 자료 요청 목록과 요청자·상태·기한.  
* 멈춤 항목: 문제·원인(확인/미확인)·조치 담당·요청사항 표시. 점수는 숨김.  
* 외부용/내부용 및 실제/가상 데이터 라벨을 명확히 구분. 접촉 승인권자는 결정 전까지 임의 부여하지 않음.

### **시나리오 R1. 주간 현황 확인**

상황: 대표가 5분 동안 영업 운영 현황을 확인한다.

9. 대표 요약 화면에서 지연·판단 대기 건수를 본다.  
10. 상위 미처리 건의 원인, 담당자, 다음 조치를 확인한다.  
11. 회사에서 제공해야 할 인증/공정 자료 요청을 확인한다.  
12. 우선순위 논의가 필요한 건을 구분한다.

합격 관찰 포인트: 5분 이내 주요 병목 1건과 조치 담당자, 필요한 자료를 정확히 말할 수 있음.

## **2.3 신입사원 — 최 신입 (가명)**

\[면담 기반\] 업무가 특정 사람에게 종속되어 인수인계가 어렵고, 미검증 AI 조언을 현장에 적용할 위험이 지적됐다. \[기존 가정\] 입사 6개월, 도금 초보, 사무·영업지원 및 품질 보조.

핵심 목표: 선임 부재 시 안전하게 문의를 접수하고 담당자에게 정보가 빠짐없이 전달되게 한다.

* 신입 안내 보기: 화면마다 “이 화면에서 하는 일”, 용어 설명, 선임 이력 및 현재 상태 우선.  
* 문의 체크리스트: 백색 일반/무광, 두께, 수량 단위, 도면, 납기와 확인 전 항목.  
* 가능: 조회·메모·내부 질문·담당자 전달. 불가: 접촉 결정·승인·외부 발송.  
* 중요: 보기(View) 전환만으로 보안 권한이 생기지 않으므로 서버 측 실제 권한/승인 통제 별도 설계 필요.

### **시나리오 N1. 담당자 부재 중 전화**

상황: 고객이 진행 중인 문의의 납기와 규격을 물어본다.

13. 고객·기회를 찾고 최종 활동 이력과 상태를 확인한다.  
14. 확정 정보와 AI 추정·미확인 정보를 구분한다.  
15. 고객 질문과 되묻기 항목을 기록한다.  
16. 담당자에게 전달하고 “확인 후 회신”으로 응대를 마친다.

합격 관찰 포인트: 고객/기회 검색 및 전달 성공, 미검증 기술·납기 정보 외부 확답 0건.

## **2.4 기술·품질 담당자 — 검수자 (v2 신규 정식 페르소나)**

\[근거 범위\] 기존 문서는 공정·인증 범위의 최종 검수자를 네 번째 후보로 명시했으나, 해당 담당자 면담·성향·실제 작업 시간은 확인되지 않았다. 아래 업무 정의는 \[v2 제안\]이며 파일럿 전 해당 직무 담당자 검증이 필요하다.

핵심 목표: AI 제안의 공정 적합성과 인증 범위를 근거 기반으로 검증하고 영업에 일관되게 회신한다.

* 검수 요청 큐: 고객 요구(재질·표면·두께·수량·용도·납기), 공정/인증 범위, 자료 출처, 요청자·기한.  
* 검수 상태: 확인 요청 → 자료 보완 → 적합/조건부/부적합/판단 보류. 판정 이유와 근거 필수.  
* 확인 불가·만료·범위 외 항목은 외부 제안에 자동 반영하지 않음.  
* 영업담당자에게 결론·조건·추가 질문을 짧게 회신하며 변경 이력 유지.

### **시나리오 Q1. 공정·인증 적합성 확인**

상황: 영업이 고객 도면/사진과 AI 추천 공정의 적합성 확인을 요청한다.

17. 요구 조건과 근거 자료의 최신성 및 인증 범위를 확인한다.  
18. 누락된 정보는 영업에 보완 요청한다.  
19. 공정 적합성 및 조건부 제한사항을 판정하고 근거를 남긴다.  
20. 영업에 검수 결과를 회신하고 고객용 노출 가능 여부를 명시한다.

합격 관찰 포인트: 미확인·범위 외 조건이 “검증 완료”로 표시되지 않으며 판단 근거가 추적 가능.

# **3\. 역할 간 연결 시나리오 (End-to-End)**

### **통합 E1. 기존 고객 견적 문의**

상황: 신입이 먼저 받고 영업·기술 검수를 거쳐 대표가 병목을 확인한다.

21. 신입: 고객 식별, 기존 이력 조회, 문의·누락 조건 입력.  
22. 영업: 고객 요구 검토 및 핵심 질문 보완, 기술 검수 요청.  
23. 기술·품질: 공정·인증 근거 확인, 조건부 가능 여부 회신.  
24. 영업: 회신 결정·결과·후속 일정 기록(외부 발송은 승인 정책 준수).  
25. 대표: 검수 지연 또는 회사 자료 제공 요청 확인.

합격 관찰 포인트: 역할 간 고객/기회 ID와 기록이 일치하고 재입력·누락·무단 외부 발송이 없어야 함.

### **통합 E2. 재접촉 약속 누락 방지**

상황: 약속이 지난 고객을 영업 담당자가 확인하고 기록한다.

26. AGENT가 별도 재접촉 판에 기한 초과를 표시한다.  
27. 영업이 마지막 연락 사유·다음 행동을 확인한다.  
28. 연락·결과·다음 약속을 남긴다.  
29. 대표 화면의 지연 건수/상태에 반영된다.

합격 관찰 포인트: 지연 항목의 상태가 양쪽 화면에 일치하고 미완료는 사라지지 않음.

### **통합 E3. 품질 또는 납기 이슈**

상황: 고객 불만이 접수되어 여러 담당자가 대응한다.

30. 신입/영업: 고객·기회 검색 및 이슈 접수.  
31. 기술·품질: 문제 검토·필요 자료·조치 가능 여부 회신.  
32. 영업: 고객 응대·후속일·완료 결과 기록.  
33. 대표: 장기 미해결 건과 담당자 확인.

합격 관찰 포인트: 이슈 책임자·상태·기한·최종 답변 근거가 전 단계에서 추적됨.

# **4\. 공통 사용성 검증 기준 — 파일럿 목표 (제안)**

| 측정 항목 | 측정 방법 | 제안 통과 기준 |
| :---- | :---- | :---- |
| **과업 성공률** | 대표 과업을 도움 없이 완료한 비율 | 핵심 과업 ≥ 90% |
| **정보 탐색** | 전화 중 이전 이력/진행 상태 찾기 | 영업 ≤ 60초 |
| **기록 부담** | 기본 통화 결과 저장 동작 계수 | 선택 ≤ 3회 \+ 메모 1줄 |
| **대표 이해도** | 상태·병목·담당·자료 설명 | ≤ 5분, 핵심 4요소 정확 |
| **모바일 사용** | 390px 화면에서 과업 수행 | 가로 스크롤 없이 주요 작업 가능 |
| **인수인계** | 신입이 조회·문의 접수·전달 | 핵심 정보 누락 0건 |
| **안전·권한** | 미검증 기술정보 및 권한 없는 발송 테스트 | 무단 발송·확답 0건 |
| **추적 가능성** | 검수 결과 및 재평가 이력 확인 | 근거·작성자·시각 기록 |
| **체감 효율** | 기존 방식과 수행시간·재입력 비교 | 동일 과업 시간/입력 감소 경향 |

평가 기록지(과업마다 작성): 참여 역할 / 시나리오 / 시작·종료 시각 / 성공 여부 / 화면 이동·클릭 수 / 입력 글자 수 / 도움 요청 / 잘못된 판단 / 중단 원인 / 기존 방식 대비 평가 / 재사용 의향. 실측 기준선이 없으므로 최종 목표치는 1차 파일럿 결과로 조정한다.
