# 백업·되돌리기 절차 한 쪽 (#214, 계약 C8)

거산 영업지원 프로그램의 모든 자료는 SQLite 파일 하나(`GEOSAN_DB_PATH`, 기본 `data/geosan.db`)에 있습니다. 그래서 **백업 = 그 파일을 한 벌 복사해 두는 것**, **되돌리기 = 복사해 둔 파일을 제자리에 다시 넣는 것**입니다. 명령 두 개(`geosan backup`, `geosan restore`)가 이 일을 안전하게 해 줍니다.

## 1. 언제 백업하나

- 새 버전을 배포하기 **직전** (`main`에 합치기 전).
- `geosan init-db`로 DB를 갱신(마이그레이션)하기 **직전**.
- 사례 파일을 다시 투입하거나 `review-set --all`처럼 값을 한꺼번에 바꾸기 **직전**.
- 거산에 전달한 뒤에는 **주 1회** 정기 백업을 권합니다(담당 PM).

## 2. 백업하기 — 서버를 켜 둔 채로 해도 됩니다

```
geosan backup                      # 현재 폴더의 backups/ 에 저장
geosan backup --to /data/backups   # 배포 서버(Railway)에서는 영구 저장 공간 안 폴더로
```

- 결과 예: `백업 저장: /data/backups/geosan-2026-11-10-1800.db (1.2MB). 원본 geosan.db은 그대로이고, 서버가 켜져 있어도 됩니다.`
- 파일 이름은 `geosan-<날짜>-<시각>.db`. 같은 분에 또 하면 `-2`, `-3`이 붙습니다.
- SQLite의 온라인 복사 방식(`VACUUM INTO`)이라 담당자가 쓰는 중에도 일관된 사본이 나오고, 아직 본 파일에 합쳐지지 않은 기록(WAL)도 들어갑니다.
- 배포 서버에서는 **볼륨이 붙은 실행 환경 안에서** 실행합니다(`init-db`와 같은 자리). 컨테이너 안 임시 폴더에 두면 재배포 때 사라집니다.

## 3. 되돌리기 — 서버를 멈춘 상태에서만

문제가 생겼을 때 순서입니다. 명령은 세 개이고, 그 사이에 서버를 멈추고 다시 켭니다.

1. **서버를 멈춥니다.** 로컬이면 `geosan serve` 창에서 Ctrl+C, Railway면 서비스를 잠시 중지합니다. 켜진 채로 복원하면 명령이 거부합니다(아래 5장).
2. **복원합니다.**
   ```
   geosan restore /data/backups/geosan-2026-11-10-1800.db
   ```
   - 먼저 백업 파일이 멀쩡한 거산 DB인지 검사합니다(아니면 종료 코드 1).
   - "계속할까요?" 확인 질문에 `y`를 넣어야 진행합니다. `n`이면 아무것도 바꾸지 않습니다.
   - 지금 쓰던 DB는 **덮기 전에** 같은 폴더에 `geosan-before-restore-<날짜시각>.db`로 자동 보관합니다. 되돌린 뒤 "방금 쌓인 기록"이 필요해지면 이 파일에서 찾습니다.
   - 결과 예: `복원 완료: /data/geosan.db ← geosan-2026-11-10-1800.db. 복원 전 DB는 /data/backups/geosan-before-restore-2026-11-11-0930.db에 보관했습니다.`
3. **마이그레이션을 맞춥니다.** `geosan init-db` — 백업이 옛 버전 코드로 만든 것이면 필요한 마이그레이션만 적용하고, 최신이면 "이미 최신입니다"가 나옵니다.
4. **서버를 다시 켭니다.** `geosan serve` (Railway는 서비스 재시작).
5. **확인합니다.** 브라우저로 목록 화면을 열어 회사 수와 최근 기록이 백업 시점과 맞는지 봅니다.

## 4. 배포 버전 자체를 되돌릴 때

코드가 문제면 Railway·Vercel의 "이전 배포로 되돌리기(Rollback)"를 누르고, 자료가 문제면 위 3장을 합니다. 코드 되돌리기 뒤 DB가 코드보다 새 버전이면 서버가 뜨지 않을 수 있으니 그때는 배포 직전 백업으로 3장을 함께 합니다.

## 5. 자주 묻는 것

- **"서버가 켜져 있습니다 (pid …, 포트 …)"라고 나와요.** `geosan serve`가 도는 동안 DB 옆에 `geosan.db.serving` 표식 파일을 둡니다. 서버를 멈추면 지워집니다. 강제 종료돼 파일이 남아도 그 pid가 죽어 있으면 명령이 알아서 지우고 진행합니다.
- **백업 파일을 팀 PC로 가져와도 되나요?** 백업에는 담당자가 적은 영업 메모·회사 대표번호가 들어 있습니다. 거산 실사용 DB의 백업은 거산이 지정한 자리(볼륨)에만 두고, 외부 AI·메일·이슈로 보내지 않습니다(CON-11·CON-13).
- **공장현황 원본 파일(22MB)도 백업하나요?** 아니요. 다시 받을 수 있는 공개 자료라 DB만 백업합니다(#213 안내 참고).
- **`backups/` 폴더가 Git에 올라가나요?** 저장소 루트의 `backups/`는 `.gitignore`에 있어 올라가지 않습니다.
