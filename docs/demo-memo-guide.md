# 10/29 시연용 맞춤 메모 작성 안내 (프롬프트 틀·점검표, Step 34)

10/29(목) 거산 방문에서 보여 줄 **상위 5곳 기업별 1쪽 메모**를 팀원이 AI 채팅(Claude·ChatGPT 등)으로 쓰는 방법입니다. 이슈 #26, 코드 생성 계획 Step 34. 제품 기능으로 메모를 자동 생성하는 것은 P2(11/15 이후, 이슈 #27)이고, 이번에는 **사람이 AI 채팅에 재료를 넣어 초안을 쓰고 PM이 점검표로 검토**합니다.

## 0. 한 줄 요약

`geosan demo-report`가 뽑은 **사실표**(`facts/<순위>-<회사명>.md`) + 상대 회사 공개 자료 + 거산 공개 홈페이지 + 회사소개서(허용 범위)를 AI 채팅에 넣고, 아래 **프롬프트 틀**로 메모 초안을 받은 뒤 **점검표**로 걸러 PM에게 냅니다. 메모 머리에는 반드시 **"시연용 초안·거산 확인 전"**을 적습니다.

## 1. 넣어도 되는 것 / 넣지 않는 것 (AGENTS.md 도구 사용 규칙, 거산 확인 2026-10-21)

| 넣어도 되는 것 | 넣지 않는 것 |
|---|---|
| `demo-report`가 만든 **사실표**(`facts/*.md`)·근거(`companies/*.md`) | 회사소개서의 **연락처**(전화·이메일·담당자 이름) |
| 상대 회사 **공개 홈페이지 본문**, 공고(나라장터 등), 보도자료 | 거산 **내부 이력**·실제 거래 이력·재접촉 입력값 |
| 거산 **공개 홈페이지** 본문 | 채용 사이트·유료 기업 DB에서 가져온 내용(CON-08) |
| **회사소개서**: 공정·소재·인증 범위, 주요 거래처명(방산 관련 기업명·현대로템 포함), 인증서·승인서의 종류·**번호·유효기간** | 거래 금액·납품 세부(소개서에 적힌 범위를 넘는 것) |

- 사실표는 이미 연락처 검사를 통과한 파일입니다. 그래도 붙여 넣기 전에 한 번 더 눈으로 봅니다.
- 상대 회사 홈페이지에서 담당자 이름·전화·이메일이 보여도 **옮겨 적지 않습니다**(CON-11).

## 2. 프롬프트 틀 (복사해서 쓰기)

아래 틀의 `[ ]` 칸만 채웁니다. 재료는 틀 뒤에 통째로 붙입니다.

```
너는 표면처리 전문기업 거산케미칼의 영업 담당을 돕는 보조자다. 아래 재료만 근거로 삼고, 재료에 없는 사실은 지어내지 말고 "확인 필요"라고 적어라.
한국어로, A4 1쪽 안에, 비전공자가 읽어도 이해되게 써라. 머리에 "시연용 초안·거산 확인 전"을 적어라.

다음 다섯 영역으로 나눠 써라.
1. 상대 회사 요약 — 무엇을 만드는 회사이고, 이번 기회(품목·공고)가 무엇인지 3줄 이내.
2. 왜 추천하는가 — 사실표의 분류·추천 이유·근거(제품·소재·처리 목적·시점 신호)를 사실 위주로. 점수는 "참고 점수"라고 적어라.
3. 거산이 제공할 수 있는 것 — 사실표 3장(맞는 거산 공정·소재·인증)과 회사소개서 범위 안에서만. 소개서 기준 값에는 "(소개서 기준·거산 확인 전)"을 붙여라.
4. 확인할 질문 — 사실표 4장의 질문을 상대에게 묻는 문장으로 다듬어라. 예/아니요로 답할 수 있게.
5. 다음 할 일 — 사실표 5장을 바탕으로 담당자가 할 행동 1~3개.

절대 적지 말 것: 단가·견적 금액·할인, 납기 약속, 경쟁사 비교·경쟁사 이름, 자동 발송·"이 메일을 보냅니다" 같은 발송 문구, 상대·거산의 담당자 이름·전화·이메일, 재료에 없는 인증·실적.

[회사명]: 
[순위·분류 (사실표 머리)]: 

--- 재료 1: 사실표 (facts/NN-회사명.md 전체) ---
[붙여넣기]

--- 재료 2: 상대 회사 공개 자료 (홈페이지 본문·공고 원문, 출처 주소 포함) ---
[붙여넣기]

--- 재료 3: 거산 공개 홈페이지·회사소개서 (허용 범위) ---
[붙여넣기]
```

- 한 번에 1곳만 씁니다. 5곳을 한 채팅에 넣으면 섞입니다.
- 결과가 길면 "1쪽으로 줄여 줘"라고 다시 시킵니다. 내용을 보태 달라고 하지 않습니다(재료 밖 내용이 들어옵니다).

## 3. 금지 항목 점검표 (내기 전에 하나씩 체크, CON-23·CON-11)

- [ ] 머리에 **"시연용 초안·거산 확인 전"** 이 있다.
- [ ] 단가·견적 금액·할인·원가 이야기가 **없다**.
- [ ] 납기·리드타임을 **약속하는 문장이 없다**("2주 안에 납품 가능" 등).
- [ ] 경쟁사 이름·경쟁사 비교가 **없다**.
- [ ] "메일을 보냅니다", "자동 발송" 같은 **발송 문구가 없다**(메모는 담당자가 읽는 자료다).
- [ ] 상대·거산의 **담당자 이름·전화·이메일이 없다**.
- [ ] 재료에 없는 인증·실적·거래처가 **없다**. 소개서 값에는 "(소개서 기준·거산 확인 전)"이 붙어 있다.
- [ ] 점수를 적었다면 "참고 점수"라고 적혀 있고, 접촉 후보가 아닌 회사를 "지금 연락"처럼 쓰지 않았다.
- [ ] 가상 사례(A정밀 등)면 "가상·거산 실제 사양 아님"이 있다.
- [ ] 1쪽 안이다.

하나라도 걸리면 그 문장을 지우거나 고친 뒤 다시 점검합니다. AI에게 "점검표에 걸리는 문장을 고쳐 줘"라고 시켜도 됩니다(점검표를 같이 붙임).

## 5. 제출 방법

- 파일 이름: `demo/memos/<순위>-<회사명>.md` (예: `demo/memos/01-B정밀.md`). 사실표 파일 이름과 같은 번호를 씁니다.
- 가지 `이름/26-memo-<회사명>`에서 PR로 올리거나, PR이 어려우면 팀 공유 폴더에 올리고 이슈 #26에 댓글로 알립니다. 어느 쪽이든 **연락처·단가가 없는지 점검표를 끝낸 뒤**에 올립니다.
- PR 본문의 "무엇을 바꿨나요?"에는 회사명·순위·분류와 점검표 10개를 모두 확인했다는 한 줄을 적습니다.

## 6. 자주 하는 실수

- 홈페이지에 적힌 대표 전화를 "회사 정보"라며 넣는다 → 넣지 않는다. 필요하면 거산 담당자가 홈페이지에서 직접 본다.
- 소개서에 없는 인증(예: Nadcap)을 "보유"로 쓴다 → 사실표의 "확인할 질문"으로 옮긴다.
- 접촉 후보가 아닌 회사(기다리는 중·준비 중)를 "바로 연락"으로 쓴다 → "거산 확인 뒤 재평가" 로 쓴다.
- 여러 회사를 비교해 "가장 유망"이라고 쓴다 → 순위는 순위표에만 있고, 메모는 한 회사씩만 다룬다.
