# 막힌 AI 사용 기록 푸는 법

**응답을 못 받았다고 무료 사용은 아닙니다. 제공사에서 확인한 기록만 정리합니다.**
이 명령은 OpenAI를 호출하지 않습니다. 확인하지 못한 기록은 남겨 두고 PM에게 문의합니다.

## 준비와 권한

- 서버에서 거산 명령을 실행하고 해당 DB를 읽고 쓸 권한이 필요합니다. `GEOSAN_DB_PATH`가 대상 DB인지 운영자가 확인하고, 기존 백업 절차에 따라 백업한 뒤 `geosan init-db`로 정산 이력 열을 추가합니다.
- OpenAI 조직의 사용량 조회 권한이 있는 계정이 필요합니다. 조직 소유자 또는 Usage 읽기 권한을 부여받은 역할을 사용하고, 메뉴가 안 보이면 조직 관리자에게 요청합니다. API 키만 가지고 있다고 사용량 화면 권한이 생기지는 않습니다. [공식 권한 안내](https://developers.openai.com/api/docs/guides/rbac)
- 정리할 때 `--by`에는 앱 설정에 있는 담당자 키를 씁니다. 기본 예시의 운영 담당은 `choi-pm`이며 `viewer`는 거부합니다. 이 키는 처리자 기록용이며 서버 접속 권한을 대신하지 않습니다.

## 1. 대상 조회

```sh
geosan transfer-unblock
geosan transfer-unblock --older-than 30m
```

기본은 10분 이상 지난 미확정 실제 호출을 **조회만** 합니다. 기록 번호·검색/본문 추출·경과 시간·한국 시각·모델을 확인합니다. 예: `정리 대상 1건(조회만 했습니다)`. 10분은 자동 정산 시점이 아니라 대상에 포함될 최소 시간입니다.

## 2. OpenAI에서 확인

[OpenAI 사용량 화면](https://platform.openai.com/settings/organization/usage)에 로그인해 실제 호출에 사용한 조직·프로젝트와 해당 날짜를 선택합니다. 표시 시간대와 명령의 한국 시각(KST)을 맞추어 입력·출력 토큰, 웹 검색 횟수와 USD 비용을 확인하고 필요하면 내보내기 자료를 대조합니다. 토큰 사용량을 확인하는 공식 경로는 [운영 안내](https://developers.openai.com/api/docs/guides/production-best-practices#managing-costs)에 있습니다.

**화면의 합계를 기록 1건의 사용량으로 넣지 마세요.** 제공사 사용량·비용 자료는 시간 구간·프로젝트·모델 등에 따른 집계입니다. 우리 기록 번호는 OpenAI 요청 번호가 아닙니다. 같은 구간에 호출이 여러 개여서 해당 기록의 토큰·검색 횟수·비용을 분리할 수 없으면 정리하지 말고 PM·조직 관리자에게 확인을 요청합니다. 공란·시간 초과·아직 집계되지 않음은 0이라는 뜻이 아닙니다. [공식 사용량·비용 자료 구조](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage)

## 3. 확인된 값 입력

```sh
geosan transfer-unblock --log-id <조회한-기록-번호> --input-tokens <입력-토큰> --output-tokens <출력-토큰> --web-search-calls <검색-횟수> --cost-usd <실제-USD-비용> --by choi-pm
geosan transfer-unblock
geosan cost --month <원래-호출-월-YYYY-MM>
```

꺾쇠 부분을 확인한 값으로 바꾸고 기록 한 건씩 실행합니다. 토큰·검색 횟수는 0 이상 정수, 비용은 0 이상 숫자이며 기존 DB에는 소수 10자리까지 저장됩니다. 본문 추출 기록의 웹 검색 횟수는 0입니다. 모든 항목이 실제로 0이라고 확인된 경우에만 각각 0을 넣습니다.

성공하면 `막힌 기록 1건을 정리했습니다`가 나옵니다. 원래 호출 횟수·발생 월·요청자·허용 기록은 유지하고 처리자·정산 시각을 남깁니다. 재실행·이미 정상 응답으로 확정된 기록·10분 미만·거부 기록은 변경하지 않습니다. 다른 미확정 기록이나 호출·비용 한도가 남아 있으면 조사는 계속 막힐 수 있습니다. 조회를 다시 확인한 뒤 조사 요청을 재개합니다.

종료 코드: `0` 조회/정리 성공(대상 0건 포함), `1` 입력·대상·처리자 오류, `2` DB 처리 실패. 실패 때는 임의로 DB 값을 고치지 말고 문의 번호를 운영자에게 전달합니다. 안내서는 공식 문서를 2026-11-04 확인했으며, 실제 계정의 메뉴·과금 기록 열람은 별도 운영 검증이 필요합니다.
