# 요구사항 (Requirements) — 거산케미칼 AI 영업지원 에이전트 2차

이 문서는 첫 버전(2차)이 "무엇을 해야 하는지"를 검증 가능한 문장으로 적은 기준입니다. 의도 문서(`../../ideation/intent-capture/intent-statement.md`), 범위 문서(`../../ideation/scope-definition/scope-document.md`)와 백로그(`../../ideation/scope-definition/intent-backlog.md`), 제약 목록(`../../ideation/feasibility/constraint-register.md`), 러프 화면(`../../ideation/rough-mockups/wireframes.md`, `user-flow.md`), 팀 실천 방식(`../practices-discovery/team-practices.md`)을 받아, `requirements-analysis-questions.md`의 확인된 답변(Q1~Q10)으로 미결 사항을 확정했습니다.

출처 표기: `[scope P0-3]`은 범위 문서 항목, `[B-03]`은 백로그 항목, `[CON-09]`는 제약 ID, `[Q4]`는 이 단계 질문 답변, `[intent]`는 의도 문서, `[mockup]`은 러프 화면, `[team]`은 팀 실천 방식, `[v0.15 F.8]`은 사용자가 참고용으로 지정한 기획서 v0.15 부록 F 절입니다. 기획서·설계서·회사소개서 본문의 주장은 위 답변이나 확정 범위를 거친 것만 적었습니다.

우선순위는 범위 문서의 P0(10/30 초기 동작, 11/6 첫 흐름) / P1(11/15) / P2(11/27) / P3(여유 시)를 그대로 씁니다. 기획서 5장·부록 F의 판단 규칙 수치는 바꾸지 않았고, 부록 F 요약에 없는 세부 규칙은 Q10에 따라 v0.15 부록 F.7~F.10을 첫 버전 기본값으로 채택하되 모두 "기업 승인 전 가설"로 표시하며 규칙 설정 파일의 설정값으로 둡니다.

## 1. 의도 분석 (Intent Analysis)

- **목표**: 거산의 공정 9종 역량과 인증·승인 조건을 고객의 영업기회와 대조해, 영업 담당자에게 "어떤 기회를 왜 검토하고, 연락 전에 무엇을 확인하고, 다음에 무엇을 할지"를 보여준다. 실제 연락·견적·수주는 사람이 한다. [intent]
- **1차 사용자**: 거산 영업 담당자. 기술·품질 담당자는 추천의 근거가 되는 공정 사양·인증 범위를 검수한다. 대표·상무는 실제로 쓰이는 결과물과 도면·노하우 유출 방지를 본다. [intent]
- **성공 기준(측정 가능)**: 10/30에 가상 사례 1건(A정밀)이 입력 → 필터 → 점수 → 분류 → 추천 목록·근거 상세 → 담당자 의견 저장까지 끊김 없이 통과한다 [scope Q2]. 11/15에 P0+P1이 완료되어 거산 담당자가 접속해 추천을 확인하고 의견을 기록한다 [intent] [scope 4절]. 거산의 소개서 확인이 11/15까지 오지 않으면(FR4.14 소개서 묶음) 이 기준은 "거산 담당자가 접속해 '거산 확인 전' 참고 추천과 확인 대기 질문 목록을 보고 의견을 기록한다"로 대신하며, 접촉 승인은 열리지 않는다 [Q11]. 11/27 통합 인수에서 시나리오 S01~S14가 통과한다 [scope 4절]. **(갱신 2026-10-21, PM 지시)** 10월 말에는 완성품이 아닌 **부분 시연**을 더한다: 공정 1~2개로 실제 신규 기업 10~20곳을 팀이 공개 자료로 투입 파일을 만들어(연락처 없음, U2·U3 자동화 없이 뼈대의 파일 투입 경로) 소개서 묶음(FR4.14)으로 평가한 참고 순위·근거를 뼈대 화면(목록·상세·의견)으로 보여 주고 거산의 피드백을 받는다. 화면과 자료에 "부분 시연·거산 확인 전"을 표시하고 접촉 승인은 열리지 않는다. 방문 날짜는 거산과 연락 후 정한다. [delivery-planning b1-change-proposal-20261021]
- **핵심 가치 흐름**: 후보 찾기 → 기회 정리 → 근거 확보 → 평가·분류 → 추천 확인 → 의견·승인·결과 기록 → 재평가. 뼈대(B-06)는 이 흐름을 A정밀 1건으로 끝까지 한 번 통과시키는 것이다. [B-06] [team]
- **기업 요구와의 연결**: 거산이 원한 회사소개서·공정 정리 방향은 이번 범위 밖이지만, 검수된 공정·인증 역량 데이터(FR1)가 그 근거로 이어진다는 연결고리를 유지한다. [intent]

## 2. 기능 요구사항 (Functional Requirements)

### FR1. 거산 역량 데이터 (P0) — [B-01] [scope P0-1] [S01]

- **FR1.1** 시스템은 공정 9종(아연도금, 아노다이징, 흑착색(알카리흑착), 크로메이트, 전해연마, 크롬도금, 무전해니켈, 인산염피막, 부동태)을 각각 하나의 공정으로 등록하고, 공정마다 등록 상태(소개서 표기 / 공식 명칭 확정)를 기록해야 한다. 공정 이름은 회사소개서 표기로 '검수 대기' 상태로 등록하며, 흑착색과 알카리흑착을 같은 공정으로 다루는 것은 거산 확인 전 가정(A11)이다. [B-01] [Q9] [Q12]
- **FR1.2** 공정마다 역량 항목(사양·시험·설비)을 종류 구분과 함께 저장해야 하며, 숫자 비교가 필요한 사양(예: 두께 범위)은 최소·최대·단위를 나눠 저장해야 한다. 설비는 설명용이며 생산능력 판정에 쓰지 않는다. [B-01] [CON-23]
- **FR1.3** 거산의 모든 역량·자격 값은 필드별 검수 상태(미확보 / 검수 대기 / 검수 완료 / 재확인)와 검수자·검수일·근거를 가져야 하며, '검수 완료' 값만 추천의 가점 근거와 필수조건 통과 근거로 쓸 수 있어야 한다. [B-01] [Q4] [CON-20]
- **FR1.4** 자격(인증·승인)은 종류·공식 명칭·번호·보유 주체·사업장·유효기간을 저장하고, 적용 범위(공정·고객·기회 단위)와 상태 이력(정상 / 정지 / 취소 / 만료 / 미확인, 확인일·근거)을 별도 행으로 저장해야 한다. 공정 ID가 비어 있는 범위를 "모든 공정에 적용"으로 해석해서는 안 된다. [S11] [Q9]
- **FR1.5** 회사소개서(2026-09-21판)에서 가져온 공정·소재·두께·인증 범위·유효기간 값은 모두 '검수 대기' 상태로 등록하고, 거산이 메일로 확인한 뒤에만 '검수 완료'로 바꿀 수 있어야 한다. [Q9]
- **FR1.6** ISO 9001·AS9100D(LRQA) 인증의 적용 범위는 아노다이징·크로메이트·전기아연도금·부동태 4개 공정으로 등록하며, 그 밖의 공정 연결에서는 이 인증을 필수조건 통과 근거로 쓰지 않아야 한다. [Q9 ①]
- **FR1.7** 한화시스템 특수공정 승인서는 상태 '미확인'으로 등록해야 하며, 갱신본이 확인되기 전까지 통과 근거로 쓰지 않아야 한다. [Q9 ②]
- **FR1.8** 가상 검수 데이터와 실제 검수 데이터를 행 단위로 구분하는 표시(실데이터/가상)를 저장하고, 화면과 출력물에서 가상 데이터가 섞여 있으면 "가상·거산 실제 사양 아님" 띠를 항상 보여야 한다. [CON-10] [scope P1-4] [mockup]

**완료 기준**: 9종이 모두 등록되고 각 값에 검수 상태 넷 중 하나가 표시된다(S01). 회사소개서 값이 '검수 대기'로 조회된다.

### FR2. 고객·영업기회 기록과 병합 (P0) — [B-02] [scope P0-2] [S02] [S04] [S06]

- **FR2.1** 고객은 이름·확인된 사업자번호(없으면 빈값 허용)·식별 근거와 관계 상태(신규 확인 / 기존 관계 확인 / 관계 미확인, 확인일)를 가져야 한다. 담당자 이름·이메일·전화 같은 연락처 열은 두지 않는다. [CON-11] [B-02]
- **FR2.2** 영업기회는 고객에 속하며 품목·프로젝트·대응 목적(신규 제안 / 기존 제안 후속 / 재발주 확인)·담당자·진행 상태를 가져야 한다. 같은 고객의 다른 프로젝트 이력은 이 기회의 점수에 들어가지 않아야 한다. [S04] [B-02]
- **FR2.3** 발견 경로(공정 수요 / 인증 조건 / 거래·상담 이력)는 기회당 여러 건을 저장하되, 같은 프로젝트를 다른 경로로 찾아도 기회 ID는 하나여야 한다. [S02]
- **FR2.4** 기업 병합은 사업자번호가 있으면 사업자번호로, 없으면 정규화한 상호명+주소로 후보를 찾고, 자동 병합은 정규화 결과가 정확히 같을 때만 하며 그 밖의 유사 후보는 "확인 필요"로 표시해 사람이 확정해야 한다. 상호명만으로 자동 병합하지 않는다. [CON-05] [B-07] [v0.15 F.5]
- **FR2.5** 기회-공정 연결은 (기회, 공정) 쌍당 하나이며, 현재 결과(통과 / 확인 대기 / 제외)와 사유·적용 소재·확인일을 조회용 파생값으로 보여주되, 원본은 평가 기록이어야 한다. [B-02]
- **FR2.7** 접촉 이력은 고객에 속하고 해당 기회에 연결할 수 있으며, 이력 종류(거래 / 견적 / 상담 / 제안 / 메모)·발생일·허용된 내용 요약·확인/추정·입력자를 가져야 한다. P0에서는 팀이 가상 사례 파일로 넣고(A정밀: 2024년 아연도금 "견적", 기회 연결 없음), P1에서는 재접촉 입력 ①(FR8.1)에서 이력 종류를 함께 고른다. 접촉 승인 목적 "기존 제안 후속 확인"(FR7.4)은 이 기회에 연결된 이력 종류가 '견적' 또는 '제안'일 때만 고를 수 있고, 재접촉 프로필 선택(FR4.1)은 이 기회에 연결된 이력이 1건 이상 있을 때만 가능하다. [B-02] [S05] [v0.15 F.8]
- **FR2.6** 회사소개서의 주요 거래처(한화시스템, 한화에어로스페이스, ㈜한화, 현대로템, LIG넥스원, KAI, 삼성전자, 세메스, 오엔, 제닉스, 두원정공, 휴니드테크놀러지스, 세트렉아이)는 관계 상태 '기존 관계 확인'(이력 종류: 거래, 근거: 회사소개서, 검수 대기)으로 등록할 수 있어야 하며, 이 값은 외부 LLM에 보내지 않는 '내부 구조화만' 등급이어야 한다. [Q9 ③] [CON-09]

**완료 기준**: 같은 프로젝트를 두 경로로 넣어도 기회 ID가 하나다(S02). 관계 미확인 고객은 참고 계산만 되고 분류는 "기다리는 중(확인 필요)"이다(S06).

### FR3. 고객 요구와 필수조건 필터 (P0) — [scope P0-3] [S07] [S08] [S09] [S11] [S13] [S14]

- **FR3.1** 고객 요구는 기회(또는 특정 공정 연결)에 속하며 요구 수준(필수 / 우대 / 비요구 / 미확인), 필요 단계(지금 / 나중 / 단계 미확인), 기한, 확인/추정, 근거, 확인 질문을 가져야 한다. 같은 산업이라는 이유로 수준을 짐작해 채우지 않는다. [S07]
- **FR3.2** 평가 때마다 요구별 판정(통과 / 미확인 / 제외)을 별도 행으로 남기고, 무엇(자격 ID, 공정 연결 ID)과 대조했는지와 사유·기준일을 저장해야 한다. "조건부 통과" 같은 중간 상태는 두지 않는다. [S08]
- **FR3.3** '통과'는 검수 완료된 거산 자격이 명칭·판본·보유 주체·사업장·공정/제품 범위·유효기간·현재 상태 모두 맞을 때만이며, 하나라도 모르면 '미확인', 없거나 범위가 안 맞는다고 확인되면 '제외'여야 한다. 한 인증의 통과가 다른 요구의 통과를 뜻하지 않는다. [S08] [S13]
- **FR3.4** 요구 자체가 미확인인 것("질문 필요")과 필수 요구의 거산 충족이 미확인인 것("확인 대기")은 다른 값으로 저장·표시해야 한다. 앞은 접촉 승인을 막지 않고 뒤는 막는다. **기회의 필터 상태 규칙(한 문장)**: 지금 단계 필수 요구 중 거산 충족 판정이 '미확인'이거나 필요 단계가 '단계 미확인'인 것이 하나라도 있으면 기회의 필터 상태는 "확인 대기"(분류 ②)이고, 요구 수준 자체가 '미확인'인 요구는 필터 상태에 영향을 주지 않고 확인 질문("질문 필요")으로만 남는다. 따라서 A정밀의 Nadcap(요구 수준 미확인)은 필터를 막지 않고, ISO 9001(필수·지금 단계·통과)만 필터에 걸려 "통과"가 된다. 이 규칙은 S07·S08과 FR4.13의 완료 기준에 연결된다. [mockup] [S07] [S08] [기획서 5.2.1·5.2.3 → scope P0-3]
- **FR3.5** 나중 단계(샘플·양산)에 필요하다고 확인된 요구는 지금 판정에서 빼고 "후속 단계 미완료"로 함께 표시해야 하며, 필수인데 단계가 불명확한 요구는 '확인 대기'여야 한다. [S08]
- **FR3.6** 두께·치수·시험·수량·납기 같은 기술 조건도 지금 단계 필수로 확인됐으면 같은 방식으로 대조해야 한다. 검수된 사양이 명백히 안 맞으면 해당 공정 연결 제외, 근거가 없으면 확인 대기, 수량·납기·생산 여력은 담당자가 확인한 상태만 기록하고 시스템이 계산하지 않는다. [S13] [CON-23]
- **FR3.7** 제외의 범위는 원인에 맞춰야 한다. 기업 전체 제한(폐업 등)은 기업과 모든 기회에, 프로젝트 제한은 해당 기회에, 소재·공정 불일치는 해당 공정 연결에만 적용하고, 같은 기회의 다른 공정 연결은 따로 판정해야 한다. [S09]
- **FR3.8** 자격의 정지·취소가 확인되면 만료일이 남아도 통과 근거로 쓰지 않고, 갱신 예정만으로 수행 시점 유효를 확정하지 않으며, 영향받는 기회를 재평가하되 이전 평가는 보존해야 한다. [S11]
- **FR3.9** 필수 자격이 없어 제외된 기회에 재검토 조건·근거·담당자·예정일을 기록할 수 있어야 하며, 새 근거가 확인되면 같은 기회 ID로 재평가해야 한다. 취득 의향만으로 점수를 올리지 않는다. [S14]

### FR4. 공통 평가 규칙 엔진 (P0) — [B-03] [scope P0-3] [Q1~Q4] [Q10]

규칙 수치와 순서는 기획서 5장·부록 F를 바꾸지 않는다. 부록 F 요약에 없는 세부는 v0.15 F.7~F.10을 기본값으로 채택했다(Q10). 모든 기준점(75·60·70·40)·확실도·감쇠·핵심 근거 조건·조사 요건은 규칙 설정 파일에 두고 "기업 승인 전 가설"로 표시한다.

- **FR4.1 프로필 선택**: 평가 전에 프로필을 기록해야 한다. 신규 기업의 새 기회, 기존 고객의 과거 거래와 무관한 새 품목은 신규 기회 프로필(8항목), 이 기회에 거래·견적·상담·제안 이력이 있고 재접촉 사유가 있으면 재접촉 프로필(7항목), 관계 미확인은 신규 기회 프로필로 참고 계산만 하고 분류는 "필터 확인 대기"여야 한다. 인증으로 발견된 기회도 둘 중 하나다. 점수에 유리한 프로필 선택은 금지하며 프로필 변경 시 사유와 이전 결과를 남긴다. [S03~S06]
- **FR4.2 항목 계산**: 항목 점수 = 배점 × 일치도 × 확실도 × 시점 감쇠. 항목 이름·배점·일치도 단계값은 부록 A의 규칙 설정 파일 명세(신규 기회 8항목 합 100 = 적합도 70 + 시점 30, 재접촉 7항목 합 100)를 따른다. 일치도는 부록 A의 항목별 고정 단계값만 허용하고 자유로운 소수를 받지 않는다. 확실도는 확인 1.0 / 강한 추정 0.65 / 약한 추정 0.25. 적합도 항목의 감쇠는 1. [Q10] [v0.15 F.1 F.2 F.7]
- **FR4.3 시점 감쇠**: 일반 외부 사건은 실제 발생일 기준 0~30일 1.0 / 31~90일 0.5 / 91일 이상 0. 공고는 마감 전 1.0, 마감·취소 후 0, 마감 여부 미상은 미확보. 재접촉의 재발주 시점·후속 일정은 부록 A의 날짜 경계(재발주 시점 절대 차이 0~60일 1.0 / 61~120일 0.5 / 121일 이상 0, 후속 일정 0~30일 이내 예정 또는 1~30일 경과 1.0 / 31~90일 이내 예정 0.5 / 그 외 0, 완료·취소는 0)를 따른다. 발생일 미상은 미확보이며 수집일·확인일로 대신하지 않는다. [v0.15 F.2 F.4]
- **FR4.4 항목 상태**: 확인 / 강한 추정 / 약한 추정 / 불일치 / 가점 없음 / 신호 없음 / 미확보 일곱 가지를 쓰며 앞 여섯은 판정 완료, 미확보만 점수 NULL이다. 미확보 항목도 행을 남겨 완료율 분모가 줄지 않아야 한다. [v0.15 F.6 F.7]
- **FR4.5 반올림과 기호**: 항목 점수는 소수 첫째 자리에서 반올림한 정수(0.5는 올림)로 저장하고, F(적합 합), T(시점 합), E=F+T, P(판정 완료 항목의 배점 합), S=E÷P×100(P=0이면 "산정 전"), C(완료 항목 수÷전체), W=P, R=E+미확보 배점 합+Σ(추정 항목을 확실도 1.0으로 재계산한 점수−현재 점수)를 계산해야 한다. 0≤E≤P≤100, E≤R≤100. S·C는 소수 첫째 자리까지 표시하되 분기에는 반올림한 S가 아니라 원래 E·P·R을 쓴다. [Q10] [v0.15 F.7]

### FR5. 근거 추출 (P0) — [B-04] [scope P0-4] [CON-07] [CON-09]

- **FR5.1** 홈페이지 URL 또는 본문 텍스트가 주어지면 외부 LLM으로 제품·소재·처리 목적에 관한 근거 문장 후보(각각 원문 인용, 출처, 발생일 후보)와 확인 질문 후보를 뽑아 근거 자료로 저장해야 한다. 가상 홈페이지 본문 1건에서 근거 3개 이상과 질문 1개 이상이 출처와 함께 생성되어야 한다. [B-04]
- **FR5.2** URL이 주어지면 robots.txt와 이용약관을 확인해 허용될 때만 본문을 가져오고, 허용되지 않으면 "이 사이트는 자동으로 읽을 수 없습니다. 내용을 직접 붙여 넣어 주세요"와 본문 붙여넣기 칸을 보여야 한다. 열리지 않는 주소는 "주소를 열 수 없습니다. 다시 확인해 주세요"로 알린다. [scope P0-4] [mockup 흐름 3]
- **FR5.3** 가져온 본문에서 이메일·전화번호 등 연락처 패턴은 저장 전에 제거해야 하며, 연락처가 저장되지 않았음을 테스트로 확인해야 한다. [CON-07] [B-04]
- **FR5.4** 외부 LLM으로 보내기 전에 보내는 내용이 '공개' 또는 '외부 AI 허용' 등급인지 검사하고, '내부 구조화만'·'처리 금지'·'미확인' 등급은 보내지 않아야 한다. 재접촉 입력값과 거산 내부 이력은 어떤 경우에도 보내지 않는다. 전송 기록은 0건임을 테스트로 확인한다. [CON-09] [FR8]
- **FR5.5** LLM 호출은 ① 근거 문장·날짜·상태 후보 추출 ② 확인 질문 생성 ③ 문안 초안의 세 곳으로 제한하고, 하나의 어댑터 뒤에서 외부 LLM / 호출 없음(템플릿)을 설정으로 고를 수 있어야 한다. 신규 기회의 기본은 외부 LLM, 재접촉의 기본은 호출 없음이다. 모드가 달라도 규칙 엔진 입력·출력 형식은 같아야 한다. 로컬 모델은 이번 범위 밖이다. [scope 3절 조건부 제외]
- **FR5.6** 근거 자료마다 출처 등급(A 공시·입찰·기업 내부자료 / B 기업 홈페이지·보도자료·채용 / C 출처 있는 DB·언론 / D 블로그·출처 불명)과 보안 등급(공개 / 외부 AI 허용 / 내부 구조화만 / 처리 금지), 외부 AI 허용·발표 허용 여부, 추출 방식(외부 LLM / 수동 입력)과 추출일을 저장해야 한다. D 단독 근거는 확인 대기다. [v0.15 F.6]
- **FR5.7 (팀 제안, 수용됨)** LLM이 제안한 확실도 등급(확인 / 강한 추정 / 약한 추정)과 출처 등급은 제안값으로 저장하고, 가상 사례 파일 또는 담당자 확인으로 확정값을 둘 수 있어야 한다. 확정 전에는 제안값으로 계산하되 "LLM 제안" 표시를 남긴다. 등급 판정 기준은 FR5.6과 v0.15 F.6을 따른다. [Q14 ①] [v0.15 F.6]
- **FR5.8 (팀 제안, 수용됨)** LLM이 공고·본문에서 인증·조건 요구 후보(예: "ISO 9001 보유 업체")를 찾으면 요구 후보로 저장하되, 수준은 원문에 명시된 경우에만 '필수'(강한 추정)로 제안하고 그 밖에는 '미확인'으로 두어 사람이 확정하게 해야 한다. 필수·비요구를 짐작하지 않는다는 기획서 5.2.1 원칙의 적용이다. [S07] [Q14 ②]
- **FR5.9** 홈페이지 자동 탐색(회사명+주소로 홈페이지 후보 찾기, 확신이 낮거나 못 찾으면 "확인 필요"로 담당자가 URL 입력·확정)은 P1이며, 검색 방식의 비용·약관 확인이 선행돼야 한다. [scope P1-5] [B-11]
