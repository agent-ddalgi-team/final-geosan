### Summary

범위 문서 P0~P3와 백로그 B-01~B-19, 러프 화면 S1~S5, 제약 CON-01~23을 요구사항(FR1~FR14, NFR1~NFR12)에 대조했고, Q1~Q10 답변과 v0.15 부록 F.1~F.10도 직접 확인했습니다. 대부분의 항목이 추적되고 측정 가능하며, FR4(규칙 엔진)는 Q10 채택 내용과 v0.15 F.7~F.10(핵심 근거, 시점 우선 세 요건, 조사 다섯 요건, 11분기, 정렬 키)에 맞습니다. A정밀 역산값(FR10.1)도 FR4.2·FR4.5로 직접 계산해 E 77 / P 95 / S 81.1(81.05의 반올림) / R 82가 나오는 것을 확인했습니다. 다만 "요구 미확인"이 필터 상태를 어떻게 바꾸는지, 실제 후보에 어떤 거산 값 묶음을 쓰는지 같은 규칙의 빈틈 2건(High)이 있고, 재접촉 상세 화면 누락과 추적 태그 오류 등 보완이 필요한 Medium이 있습니다. 모두 설계 단계 전에 문장 몇 줄로 닫을 수 있어 승인을 막을 정도는 아니라고 봅니다.

### Suggestions

- A정밀 8항목 중 증설(10점, 0~30일, 확인)은 기획서에 없는 신호를 역산으로 만든 값입니다. 증설 없이 계산하면 E 67이 됩니다. FR10.1의 "역산한 가정값" 표시는 적절하지만, PM이 확인할 때 이 신호가 가상으로 추가된 값이라는 점을 사례 파일에 같이 적어 두면 좋습니다.
- FR6.2 안의 "시점 우선 ③"과 화면 영역 ③(공정 연결)이 같은 번호라 읽을 때 헷갈립니다. 요건은 "시점 우선 요건 3"처럼 다른 표기를 쓰세요.
- 러프 화면의 "갱신 시각" 표시, [+ 재접촉 정보 입력] 버튼, 무응답은 실주가 아니라는 안내 문구, 건너뛰기 링크·저장 결과 낭독 같은 세부는 FR6에 한 줄씩 옮기면 설계 단계 누락을 줄일 수 있습니다.
- P0 부담 완화: 홈페이지 URL 자동 수집(robots.txt·약관 확인 포함, FR5.2)과 외부 LLM 근거 추출, 규칙 엔진, 화면 3개가 모두 10/30 뼈대 주변에 몰립니다. 뼈대 1차는 "본문 붙여넣기 입력 + LLM 호출 없는 템플릿 모드"로 먼저 통과시키고, URL 자동 수집은 11/6로 미루는 순서를 설계 단계에서 검토해 보세요(필수 판정 생략이 아니라 입력 경로의 순서입니다).
