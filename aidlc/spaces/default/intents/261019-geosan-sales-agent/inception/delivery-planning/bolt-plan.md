# Bolt 계획 (Bolt Plan) — 거산케미칼 AI 영업지원 에이전트 2차

"Bolt"는 한 번의 구현 묶음입니다. 작업 단위(`../units-generation/unit-of-work.md`) 하나를 골라 설계·코드 생성·테스트를 한 바퀴 돌려 **돌아가는 결과**를 내고, 사람이 확인(체크포인트)한 뒤 다음 Bolt로 갑니다. 확인된 답변(`delivery-planning-questions.md` Q1~Q4)대로 Bolt 하나 = 작업 단위 하나이고, 순서는 걷는 뼈대(가장 작은 끝단 조각을 먼저 끝까지 돌려 구조가 이어지는지 확인하는 방식) → 이정표 조건 → 가치·위험 혼합입니다. 의존 그래프(`../units-generation/unit-of-work-dependency.md`)를 어기는 순서는 없습니다. 팀 실천 방식: 트렁크 기반, Bolt 하나가 `main`에 스쿼시 커밋 하나, 테스트는 시나리오 먼저.

**계획의 전제(아직 확인 안 됨)**: 평일 하루 8시간·주말 4시간을 팀원 3명과 아직 합의하지 않았다(Q4 E). 합의가 바뀌면 이 계획의 날짜를 다시 계산한다. PM(최지예)은 거산 소통·팀 조율·AI-DLC 진행·PR 확인을 맡아 개발 여력 50%로 잡았다.

## 2. Bolt별 정의

### B1 — U1 뼈대 (걷는 뼈대, 10/22~10/28)

- **포함 단위**: U1 `u1-skeleton` (부품 10개 최소형 + Evidence 최소형, S1·S2·S3 P0, 한 덩어리 실행).
- **걷는 뼈대 표시**: 예. 증명하는 구조: 파일 투입 → 규칙 엔진 → 평가 기록(⓪ 흐름) → 웹 API → React 화면 → 의견 저장, 그리고 FastAPI가 React 빌드를 함께 내보내는 한 덩어리 실행.
- **완료 기준(Definition of Done)**: ① 시나리오 테스트 S01·S02·S04·S06·S07·S08·읽기 예시 2가 통과 ② `geosan verify-case examples/case-apjeong.json`이 E 77 / P 95 / S 81.1 / R 82, 필터 통과, 핵심 근거 충족, 분류 CONTACT_URGENT를 확인 ③ 브라우저에서 목록 → 상세 → [검토할 만함] 저장 → 목록에 "의견: 검토할 만함"이 보임 ④ 줄 커버리지 80% 이상, Ruff·Prettier·ESLint 통과 ⑤ 가상 데이터·내부용 띠가 보임 ⑥ 구현 검증 명령(사람이 승인한 것)이 통과.
- **확인 가설**: "비전공 4명이 AI 도구로 FastAPI + React + SQLite 한 덩어리를 일주일 안에 끝까지 돌릴 수 있고, 규칙 엔진이 기획서 수치를 그대로 재현한다." 이것이 깨지면 뒤 전체 일정을 다시 잡는다.
- **기대 시연**: 10/30 팀 시연. A정밀 카드 1위 → 상세(요구 판정 표·점수 세부) → 의견 저장. 메일로 화면 캡처 전달.
- **중간 확인 지점(늦어짐을 일찍 알기 위해, Q4 요청)**:

### B2 — U2 근거 추출·전송 보호 (10/29~11/4, 짝 1)

- **완료 기준**: 홈페이지 주소 확정/붙여넣기 → 근거 3개 이상·질문 1개 이상 생성(가짜 LLM 응답으로 테스트) → 재평가됨 표시; 전송 보호 거부 로그·"전송 0건" 테스트 통과; robots 차단 사이트에서 붙여넣기 안내; S03·S11 시나리오 통과. 외부 LLM 실제 호출은 설정으로 켜고 1건 시험.
- **확인 가설**: "외부 LLM 비용·약관 안에서 근거 추출이 1건 60초 안에 되고, 내부 자료가 밖으로 나가는 경로가 구조적으로 없다."
- **기대 시연**: A정밀에 가상 홈페이지 본문 붙여넣기 → 근거 목록 갱신 → 순위 변화.
- **겹치지 않는 작은 일**: 가짜 LLM 응답 파일(픽스처), 전송 0건 테스트, robots 테스트 케이스, LLM 계정·비용 상한 설정(PM), 근거 자료 화면 영역 부품.

### B3 — U8 접속 보호·배포 준비·최소 백업 (10/29~10/30, 짝 2)

- **완료 기준**: 비밀번호 없이·틀린 비밀번호로 모든 화면·API 거부, 5회 실패 30초 대기, 환경 변수 전달, 한 덩어리 빌드 스크립트, `backup`/`restore` 최소형(VACUUM INTO, 서버 멈춘 뒤 복원), 되돌리기 절차 한 쪽. 11/6 전에 시연 환경에 한 번 올림(호스팅은 인프라 설계에서 확정).
- **확인 가설**: "GitHub 연결만으로 올라가는 배포가 되고, 데이터 파일이 지워지지 않는 곳이다."
- **겹치지 않는 작은 일**: 환경 변수 목록 문서, 배포 설정 파일, HTTPS 확인, 백업 절차 문서.

### B4 — U3 후보 수집·병합 (10/31~11/5, 짝 2)

- **완료 기준**: 소스 계약표 기록 뒤 산단공 CSV를 설정 범위(충남+대전·세종, 키워드, 30~50건)로 수집, 인코딩·헤더·건너뛴 행 집계, 정규화·병합·"확인 필요" 목록과 확정 명령, S02 통과, 11/6 시연 환경에서 후보가 A정밀 아래에 보임.
- **확인 가설**: "실제 CSV가 설계대로 정규화되고 중복 집계가 없다."
- **겹치지 않는 작은 일**: CSV 샘플·인코딩 테스트 파일, 소스 계약표 작성(PM, 허용 범위 확인), 수집 설정 YAML, 병합 확인 목록 화면 없음(명령 출력 형식만).

### B5 — U4 거산 확인 창구 (11/5~11/10, 짝 1)

- **완료 기준**: 질문 상태 대기→요청→회신→반영(파생), 거산 확인 요청·직접 추가·회신 기록 인라인, 복사·텍스트 내보내기(출력 검사), 검수 전환 명령 → 묶음 재평가, 거산 값 묶음 전환과 "거산 확인 전" 띠·승인 비활성, S6 화면, S11·S13·S14 통과. 추가조사 기록(P2)은 제외.
- **확인 가설**: "거산 확인 병목을 화면·명령으로 돌릴 수 있고, 거산 값은 화면에서 바뀌지 않는다."
- **겹치지 않는 작은 일**: 질문 문장 템플릿, S6 화면 부품, 거산 확인 메일 양식(PM), 질문 목록 텍스트 형식 테스트.
