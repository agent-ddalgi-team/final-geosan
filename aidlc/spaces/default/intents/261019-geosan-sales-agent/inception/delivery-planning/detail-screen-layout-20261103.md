# 상세 화면(자세히 보기) 다섯 영역 구성 제안 — PM 메모 5장 (2026-11-03)

> 상태: **PM 결정 완료 2026-11-03 밤(9장).** 상세 화면 (1)(2)(3)(5)는 1차, (4) 영업 전략은 2차. 약속 파일 4장 1차분은 PM "반영" 확인 뒤 계약 요약에 적는다. 원본은 PM이 적은 "5. 상세 화면(자세히 보기) 구성"(기획 변경 메모 `docs/input/20261102_기획변경메모_방문후.md`에 들어갈 글). 이 제안서는 그 다섯 영역을 지금 설계(상세 화면 목업 S2, 계약 요약 v2, 이슈 #209·#210·#211·#218·#219·#27)와 대 보고 **이미 있음 / 새로 더함 / 범위 변경**으로 나누고, 시간·1차/2차·약속 파일 추가분·담당자 시간을 계산한 것이다. 약속 파일은 PM 확인 뒤에 고친다(팀 규칙: 약속 파일 → PR 체크리스트 → 코드). 규칙 숫자(부록 F)·A정밀 기대값·시나리오는 바꾸지 않는다.

## 0. 한 줄 결론

다섯 영역 중 (1) 회사 소개·(2) 추천 이유·(5) 담당자 기록은 **대부분 이미 설계와 이슈에 있다.** 새로 더하는 것은 ① 대표번호 조건 4가지, ② 기록 종류 "자료 조사"·접촉 횟수·한 칸 입력·타임라인 화면, ③ 검토사항 체크, ④ 영업 전략 초안이다. (추천안은 ①②만 1차였으나) **PM 결정(9장): 상세 화면 전부를 1차로 하고, 대신 대시보드 공정·산업군 막대·집계·산업군 AI 제안·칩과 엑셀을 2차(11/17 주)로 옮긴다.** 남는 초과분은 줄이지 않고 1차 전달 날짜를 늦춘다(결정 1: 마감 없이 완성되는 대로 전달). 사람별 1차 완료일은 5장.

## 6. 거산에 물을 질문 — 영업 메모를 OpenAI에 보내도 되는지 (#208 댓글에 남김, PM이 산업군 질문과 묶어 직접 보냄)

> **질문: 영업 메모를 OpenAI에 보내 "영업 전략 제안"을 받아도 됩니까?**
>
> 지금 프로그램의 영업 메모(통화·방문 뒤 담당자가 적는 글)는 거산 안에만 두고 밖으로 보내지 않습니다. 메모를 AI에 함께 보내면 "지난 통화에서 납기를 걱정했으니 납기 사례를 먼저 보여 주자"처럼 더 맞춤 제안이 나옵니다. 대신 상대 담당자 이름·전화, 통화 내용, 거산의 견적·샘플 진행 상황 같은 내부 정보가 외부 회사(OpenAI) 서버를 거칩니다. OpenAI는 API로 보낸 내용을 학습에 쓰지 않고 최대 30일 보관 뒤 지운다고 합니다.
>
> - **A** 보내지 않는다 (지금대로, 공개 자료로만 전략 제안)
> - **B** 보내되 사람 이름·전화번호·이메일은 지우고 보낸다
> - **C** 담당자가 "이 메모는 AI에 보내도 됨"이라고 고른 메모만 보낸다
>
> 추천: **A로 시작**하고, 1차 전달 뒤 전략 제안을 써 본 다음 B·C를 다시 정합니다.

B·C는 C4 EXTERNAL_AI의 "NOTE 전체 거부"를 바꾸는 깨는 변경이라 계약 버전을 올린다. B를 고르면 `scrub_contacts`만으로는 이름을 못 지우므로 사람 이름 제거 규칙이 더 필요하다.
