# 순서의 근거와 위험 (Risk and Sequencing Rationale) — 거산케미칼 AI 영업지원 에이전트 2차

이 문서는 Bolt(한 번의 구현 묶음: 작업 단위 하나를 설계·코드·테스트까지 돌려 돌아가는 결과를 내는 것) 순서를 왜 그렇게 잡았는지 적습니다. 순서는 `bolt-plan.md`, 사람 배정은 `team-allocation.md`, 바깥에서 막힐 수 있는 것은 `external-dependency-map.md`에 있습니다.

## 1. 쓴 방법

세 가지를 섞었습니다(확인된 답변 Q1).

1. **걷는 뼈대 먼저**(Cockburn, Crystal Clear): 가장 작은 끝단 조각(A정밀 1건이 파일 투입 → 평가 → 화면 → 의견 저장)을 먼저 끝까지 돌려 구조가 이어지는지 확인한다. 팀 실천 방식의 확정 사항이고 10/30 초기 동작 정의와 같다.
2. **이정표 조건**: 11/6(시연 환경 + CSV 후보)과 11/15(거산 전달) 날짜가 고정이라 U8·U3·U2를 11/6 전에, 나머지 P1을 11/13까지 둔다. 날짜가 점수보다 우선한다.
3. **WSJF 참고 표**(Reinertsen 지연 비용 ÷ 기간, SAFe): 뼈대 뒤 단위에 가치·긴급·위험 감소 점수(각 1~5)를 더해 크기로 나눈 값을 참고로 붙였다. 점수가 순서를 뒤집지는 않고, 같은 조건 안에서 무엇을 먼저 고를지의 근거다.

## 3. 의존 그래프와의 대조

Bolt 순서는 의존 그래프(`../units-generation/unit-of-work-dependency.md`)의 위상 순서를 모두 지킨다: U1 → {U2, U8, U3} → U4(U2 뒤) → U5 → U7(U2·U4·U5 뒤) · U6(U2·U5 뒤) → U10(U2·U3·U4·U8 뒤) → U9(U2·U3 뒤) → U11(U6·U7·U8 뒤). 어긋나는 곳은 없다. B9(U10)를 11/11에 두려면 U4(B5)가 11/10에 끝나야 하므로 B5를 11/5에 시작한다(U2가 11/4에 끝나는 조건).
