# 잘못 저장한 기록 "취소 표시" 제안 — A안, 2차 (PM 결정 2026-11-04)

**상태**: PM 결정(A안, 2차 보강 11/17 이후). 약속 파일에는 2차 시작 때 PM이 더한다(아래 3장). 이슈 #253(서버 이강욱)·#254(화면 고선주). 근거: PM 질문 "잘못 저장한 이력을 지울 수 있어야 하지 않나"(2026-11-04), 11/3 기록 규칙 Q5(고치기·지우기 없음, 이전 값은 이력).

## 0. 한 줄 결론

기록(메모·접촉 시도·영업 단계·다음 일정·질문 답)은 지금처럼 **지우지 않는다.** 대신 담당자가 자기 기록을 **"잘못 입력"으로 표시(취소)**할 수 있고, 취소된 기록은 활동 이력에 줄이 그어져 남으며 현재 단계·접촉 횟수·대시보드 건수에서는 빠진다. 누가 언제 취소했는지도 기록이다.

## 1. 왜 A안인가

| 안 | 내용 | 판단 |
|---|---|---|
| **A 취소 표시** | 지우지 않고 "잘못 입력" 표시 행을 덧붙임 | **채택.** 신뢰 원칙(Q5) 유지, 취소한 사람·시각이 남고 되돌릴 수 있음 |
| B 짧은 되돌리기 | 저장 뒤 10분 안에는 본인이 지움, 그 뒤 A | 오타는 깔끔하지만 규칙이 둘로 늘고 10분 뒤 실수는 못 지움 |
| C 본인 숨기기 | 본인 기록은 언제든 화면에서 숨김 | 다른 담당자가 본 기록이 사라져 혼란, 신뢰 원칙과 충돌 |

## 2. 화면 모양 (고선주, #254)

- [상세 › 활동 이력 › 내 기록 줄] 오른쪽에 **[잘못 입력]**. 누르면 인라인 한 줄 확인("이 기록을 잘못 입력으로 표시합니다. 이유(선택)") → [표시]. 모달 없음.
- [취소된 줄] 줄 긋기 + "취소 · 박 이사 · 11/06". 취소된 메모는 본문 대신 "(취소된 메모)". 취소 행위 자체도 한 줄로 보인다.
- [상세 › 기록 영역] 영업 단계·다음 일정·거절 이유·접촉 횟수는 취소 뒤 이전 값으로 돌아간다. 추천 목록 카드 꼬리표·대시보드 건수도 같이.
- [누가] 기본은 본인 기록만. 다른 담당자 줄에는 단추 없음. 설정으로 PM(관리자 키)에게 전체 허용 가능.
- [안 하는 것] 내용 고치기(수정)는 없다. 잘못 적었으면 취소하고 새로 적는다. 검토사항 체크는 이미 켜고 끌 수 있어 대상이 아니다.

## 3. 약속 파일 변경 (모두 더하는 변경, 2차 시작 때 PM이 적음)

| 어디 | 무엇 |
|---|---|
| C1 요청 | `POST /opportunities/{oppId}/records/{recordId}/cancel` 본문 `{ reason?: string ≤200, evalId }`. 기록 종류는 recordId 접두사(note·outcome)로 구분. 403 본인 아님·보기 전용, 404 없는 기록, 409 이미 취소됨 |
| C1 ActivityItem | `recordId`, `recordKind`(NOTE·OUTCOME), `cancelled: boolean`, `cancelledBy`·`cancelledAt`(nullable). 취소 행위는 kind `RECORD_CANCELLED` 한 줄. 취소된 NOTE는 summary "(취소된 메모)" |
| C1 상세 `records.outcome`·`contactCount`, 카드 `records.outcome`·`contactCount`, `/dashboard` 건수 | "취소된 행 제외" 한 줄 명시 |
| C0 코드표 | `activityKind`에 `RECORD_CANCELLED` |
| C6 `rec_note`·`rec_outcome` | `cancelled_at`(UTC)·`cancelled_by`(staffKey)·`cancel_reason`(≤200) 열. 행 삭제 없음 |
| C4 | 취소된 메모 본문은 상세·활동 이력에도 안 보냄(DB에만). 엑셀·외부는 원래부터 메모 제외라 추가 규칙 없음 |
| C7 설정 | `records.cancelByAnyStaff`(기본 false). true면 모든 담당자가 남의 기록도 취소 가능(PM 결정 때만) |

깨는 변경 없음. 질문 답(q_question 회신 칸)의 취소는 "답 다시 적기"로 대신하고, 답 이력 행(rec_note REPLY)은 NOTE와 같이 취소 가능.
