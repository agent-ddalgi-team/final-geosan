# 검토사항 질문 줄 [답 적기] — 1차 범위 제안 (PM 결정 2026-11-04)

**상태**: PM 결정 반영(1차 11/15 전달분). 약속 파일(계약 요약) 3장 "더하는 변경" 적음(2026-11-04). 이슈 #248(서버 이강욱)·#249(화면 고선주). 근거: #228 합친 뒤 PM 브라우저 확인, #208 댓글(메모·기록 활용 조건).

## 0. 한 줄 결론

상세 화면 "검토사항"의 **질문 줄마다 [답 적기]** 인라인 입력을 둔다. 답은 **새 표를 만들지 않고** 약속 파일에 이미 있는 **질문 답 기록(질문 표의 회신 칸, `POST /questions/{questionId}/reply`)**에 저장한다. 그래서 나중에 질문 목록 화면(#223)이 같은 답을 본다. 답이 있으면 줄 아래 "답: …"으로 보인다.

**답은 영업 메모와 같은 취급이다: 내부 전용, 외부 AI 전송 금지, 엑셀·질문 목록 내보내기에서 제외.** 답에는 상대 회사 담당자 이름·전화·통화 내용이 들어갈 수 있기 때문이다(11/3 연락처 규칙 `contact-policy-change-20261103.md`).

**2차(#224 묶음)로 미루는 것**: 담당자가 검토사항에 줄을 직접 추가하기, 질문 글 고치기(고친 글을 따로 저장해 원래 글 대신 보이기).

## 1. 화면 모양 (고선주)

- [상세 › 검토사항 › 질문 줄(꼬리표 "AI 질문·상대 회사"/"AI 질문·거산")] 글 옆에 **[답 적기]**. 누르면 그 줄 아래 인라인 한 칸(모달 없음, 500자). 저장하면 줄 아래 **"답: 2024년에 KS 인증 받았다고 함 — 박 이사 · 11/06"**.
- 답이 이미 있으면 "답: …"이 보이고 [답 적기]는 **[답 고치기]**로 바뀐다. 저장하면 최신 답으로 덮어쓴다(아래 4장 ①).
- "자료 못 찾음"·"자료 부족" 줄에는 [답 적기]가 없다(질문이 아니라서). 체크만 된다.
- 담당자를 고르기 전에는 [답 적기]가 잠긴다(체크 상자와 같음). 보기 전용 담당자는 403.
- 답을 저장해도 체크는 자동으로 바뀌지 않는다. 확인했으면 담당자가 체크한다.
- 가짜 서버 모드의 상세 응답 파일에 `reviewItems` 질문 줄과 답 1건을 넣어 화면 테스트가 돌게 한다.

## 2. 기존 답 기록 구조로 충분한가 (서버 이강욱)

| 항목 | 지금 약속 파일 | 지금 코드 | 판단 |
|---|---|---|---|
| 답 저장 자리 | 질문 표 `q_question`의 회신 칸. 응답 `Question.replyText`·`repliedAt` | 질문 표에 회신 열이 **아직 없음**(U4 미착수, #223 미정) | **충분하다.** 열만 더하면 됨. 새 표 없음 |
| 저장 요청 | `POST /questions/{questionId}/reply` `{ replyText ≤500, repliedAt }` "요청 → 회신" | 경로 **아직 없음** | 그대로 쓴다. 단, 검토사항에서는 거산에 요청하기 전(대기 상태)에도 답을 적으므로 **"대기 → 회신"도 허용**해야 함 |
| 검토사항 줄과 질문의 연결 | `reviewItems[].itemId = "Q:<questionId>"` | 그대로 구현됨 | 충분. 번호가 같으므로 답을 질문 번호로 저장하면 됨 |
| 여러 회사에 걸친 질문 | 질문 하나가 여러 기회에 연결됨(`q_question_opportunity_link`) | 그대로 | 답은 질문당 하나이므로 **연결된 모든 회사의 검토사항에 같은 답이 보인다.** 의도된 동작(같은 거산 질문은 한 번만 답) |
| 답한 사람 | 없음(`requestedBy`만 있음) | 없음 | `repliedBy`(담당자 키) 더해야 "— 박 이사" 표시 가능 |
| 답 이력 | `replyText` 하나(최신) | — | 이전 답은 남지 않음. 4장 ① |

## 3. 약속 파일 변경 (모두 더하는 변경, PM이 계약 요약에 적음)

| 어디 | 무엇 |
|---|---|
| C1 `Question` | `repliedBy: string \| null` 추가 |
| C1 `reviewItems[]` | 질문 줄(kind QUESTION)에 `replyText`·`repliedAt`·`repliedBy`(모두 nullable) 추가. 질문 표의 회신 칸 그대로 |
| C1 `POST /questions/{questionId}/reply` | 허용 상태를 "요청 → 회신"에서 **"대기 또는 요청 → 회신"**으로 넓힘. `repliedBy`는 요청 머리 `X-Staff-Key`에서 서버가 채움(본문에 없음). 보기 전용 403. 이미 회신이 있으면 덮어쓰고 활동 이력에 한 줄 더 남김 |
| C4 전송 보호 | 질문 답(`replyText`)을 NOTE와 같은 종류로: EXTERNAL_AI·EXTERNAL_SEARCH 거부, OUTPUT_EXPORT(엑셀·질문 목록 내보내기) 제외. `/questions/export`는 지금도 대기·요청 질문의 글만 내보내므로 바뀌는 것 없음을 명시 |
| C6 `q_question` | 열 3개 `reply_text`(Text), `replied_at`(date), `replied_by`(String 32). 이 모델 파일은 "PM 세션만 고친다" 표시가 있으므로 **PM이 열을 더하거나, 이강욱 PR에서 더하고 PM이 확인** |
| C0 `noteKind` | `REPLY` 추가. 답을 저장할 때마다 연결된 기회마다 `rec_note` 새 행(kind REPLY, text "Q:<questionId> 답: <답 글>", staffKey 답한 담당자). 화면 메모 입력에서는 고를 수 없음 |
| 활동 이력 | `rec_note` REPLY 행을 종류 `REPLY`(코드표에 이미 있음) "답 기록 · 2024년에 KS 인증…"으로. 저장할 때마다 한 줄이라 **이전 답도 모두 남는다** |
| C7 설정 | 없음. 길이 상한 500은 약속 파일 값 그대로 |

깨는 변경 없음. 계약 버전 그대로(v2).

## 4. PM이 정한 것 / 남은 결정

① **답 이력(PM 결정 2026-11-04, 확인 결과)**: 활동 이력은 따로 저장하는 표가 아니라 **메모·단계·의견 표를 읽을 때 만드는 목록**이다. 그래서 "답 저장 때 활동 이력에 기록"을 하려면 어딘가 행이 남아야 하는데, 새 표 대신 **이미 있는 메모 표(`rec_note`, 덧붙이기만 되는 표)에 종류 `REPLY` 행**을 남기면 된다. 최신 답은 질문 표 회신 칸(덮어쓰기), 이전 답은 모두 메모 표 REPLY 행 → 활동 이력 "답 기록" 줄로 보인다. 기록 규칙 Q5(이전 값은 이력)를 새 표 없이 지킨다. #248·#249 범위에 넣음.

①-2 **활동 이력의 취급(확인 결과)**: 활동 이력에는 메모·답 글이 그대로 들어가므로 **영업 메모와 같은 내부 전용**이다. 접속 보호 뒤 상세 화면에서만 보이고, 외부 AI·엑셀·질문 목록·대시보드 요약 어디에도 나가지 않는다. 지금 코드도 그렇고(활동 이력을 읽는 곳은 상세 화면뿐), 약속 파일 C1 `/activity`·C4 OUTPUT_EXPORT에 2026-11-04 명시했다.

② **#223과의 관계**: 질문 목록 화면이 생기면 같은 회신 칸을 보고 "답 받음"으로 표시된다. 검토사항에서 적은 답과 거산 메일 회신이 같은 칸이므로, #223에서 회신을 적을 때도 덮어쓰기다.

③ **#208 질문(메모 기반 전략 활용 조건)과의 관계**: 답은 지금 "내부 전용"이다. 거산이 (나) 또는 (다)를 고르면 **C4 규칙만** 바뀌고(답을 어디까지 내보낼지) 저장 구조는 그대로다. 그래서 지금 만들어 두고 나중에 바꿔도 된다.
