# 대시보드 공정·산업군 집계 + 지도 — U7 화면 설계 추가 제안 (2026-11-03)

> 상태: **초안, PM 결정 대기.** PM 요청(2026-11-03 저녁): 대시보드 집계와 지도는 "영업 중이거나 영업 고려 중"인 회사만 보여 준다. (1) 9종 공정별·산업군별 집계, (2) 거산 기준 30/50/100km 원과 상태별 점을 찍은 지도(네이버클라우드 Maps 웹 지도), (3) 작업 시간·담당·약속 파일 추가분. 아래는 현재 데이터 확인 결과, 화면 배치, 전송 보호 검토, 어림, 약속 파일 추가안이다. 약속 파일은 PM 확인 뒤에 고친다(팀 규칙: 약속 파일 → PR 체크리스트 → 코드).

## 0. 한 줄 결론

- **산업군 칸은 지금 데이터에 없다.** 거산 쪽 납품 실적에만 산업(방위산업·반도체·반도체 장비·자동차 부품·항공우주)이 있고, 상대 회사에는 없다. PM 안대로 **AI가 근거 추출 때 "AI 제안"으로 붙이고 사람이 상세에서 확정**하는 방식을 더한다.
- **공정별 집계는 지금 데이터로 바로 된다.** 회사마다 거산 공정 연결(processLinks)이 있다.
- **지도는 좌표가 있어야 하므로 거리 작업(#222, 11/17 주)과 같이 간다.** 집계 2개는 가짜 숫자 화면(#215)에 먼저 넣고 집계 API(#216)에서 실제 숫자로 바꾼다.
- 전송 보호: 네이버 지도에는 **지도 조각 요청(화면 중심·확대 단계)과 클라이언트 ID만** 나간다. 회사 이름·영업 상태·좌표 목록은 브라우저 안에서만 그린다. 이 규칙을 약속 파일 C4에 "화면 지도 규칙"으로 적고 검사 하나를 둔다.
- 작업 시간 어림 **약 33시간**(집계 17h + 지도 16h). 1차에 넣을 수 있는 것은 가짜 숫자 막대 2개(6h)까지.

## 1. 공통 기준 "대시보드 대상"

| 묶음 | 영업 단계(outcomeStatus 최신 값) | 점 색·모양 |
|---|---|---|
| 관심(영업 고려) | `INTERESTED` — Q2 결정대로 영업 단계의 "관심". 담아 두기 표시는 없음 | 파랑 ● |
| 진행 중(접촉~협의) | `IN_PROGRESS`, `SAMPLE_OR_REGISTRATION_APPROVED` | 주황 ◆ |
| 올해 성공 | `WON`이고 그 결과의 날짜(outcomeAt)가 올해 | 초록 ★ |
| 제외 | `NOT_EXECUTED`(미접촉), `ON_HOLD`(보류), `LOST`(거절), 작년 이전 `WON` | 안 보임 |

- 대상이 0곳이면 집계·지도 자리에 **"관심 표시한 회사가 아직 없어요"** 안내와 **[추천 목록 가기]** 버튼.
- 가상 사례(A정밀 등)는 세지 않는다(가상 띠는 그대로).
- ❓ 기존 건수 5개(미접촉 / 관심 / 접촉 중 / 견적·샘플 / 이번 주 일정)는 "할 일 가는 단추"라 그대로 두는 것을 추천한다. 미접촉 건수를 빼야 하면 말씀.

## 3. 산업군 — 지금 데이터에 없다 → AI 제안 + 사람 확정

| 확인한 곳 | 결과 |
|---|---|
| 회사(opp_customer) 열 | 이름·사업자번호·주소·관계·보안 등급·(11/3 추가) 대표번호·한 줄 소개·특징뿐. 산업군 없음 |
| 사례 파일 18곳 | `customer`에 산업군 키 없음. 근거 항목 중 "유사 산업 납품실적" 대조에 쓰는 `industry`(예: 밸브·유체기기)는 **거산 실적 쪽 산업**이지 회사의 산업군이 아님 |
| 거산 역량 파일 | 납품 실적 산업 5개: 방위산업, 반도체, 반도체 장비, 자동차 부품, 항공우주 |

추가 방식:
1. **산업군 목록은 설정 파일에**(`industries`): 방위산업, 반도체, 반도체 장비, 자동차 부품, 항공우주, 밸브·유체기기, 조선·해양, 전기·전자, 기계·설비, 기타. PM이 늘리고 줄인다(규칙 ⑩: 목록을 코드에 적지 않음).
2. **AI 제안**: 근거 추출(#219)의 결과에 `industries ≤3`(목록 안 값만)을 더한다. 공개 홈페이지 본문에서 "주요 납품처·적용 분야"를 읽어 고른다. 출처 AI, 확정 전.
3. **사람 확정**: 상세 머리(기업 요약) 특징 줄 아래 산업군 칩 "방위산업 · 반도체 장비 (AI 제안)" + [확정] [고치기](칩 선택, 모달 없음). 확정하면 출처 STAFF.
4. **집계는 AI 제안을 포함해 세고** 막대 옆에 "AI 제안 포함"을 작게 적는다. 확정 전 회사만 따로 빼면 처음엔 전부 0이라 화면이 비기 때문. ❓ 확정된 것만 세길 원하면 설정 한 줄로 바꿀 수 있게 둔다(`dashboard.countProposedIndustries`).
5. 한 회사가 여러 산업군 → 각각 센다. %는 "대상 ○곳 중 ○곳"이라 합이 100%를 넘을 수 있다(PM 지시). 산업군이 하나도 없으면 "미확정"으로 센다.
6. 공정별도 같은 규칙: 회사의 공정 연결(processLinks)이 여럿이면 각각 센다. 9종 전부 표시(0곳도).

## 4. 지도 — 네이버클라우드 Maps 웹 지도(Dynamic Map)

| 항목 | 결정·확인 |
|---|---|
| 지도 | 네이버클라우드 Maps **Web Dynamic Map**(JS). 월 600만 건 무료(대표 계정). 계정은 PM이 만든 네이버클라우드 계정 하나 — 지오코딩은 약관 때문에 이 계정으로 하지 않으므로(거리 제안서 8장) 이 계정은 **지도 표시 전용** |
| 키 | 클라이언트 ID 하나. 브라우저에 보이는 값이라 비밀이 아니지만, 콘솔에서 **허용 서비스 URL**(Vercel 주소)을 등록해 남이 못 쓰게 한다. 환경 변수 `VITE_NCP_MAPS_CLIENT_ID`(화면 빌드 때 들어감) |
| 가운데·원 | 설정 `geosan.lat/lng`(제2공장 봉주로 303-1)에 거산 마커, 반지름 30/50/100km 원 3개(설정 `distanceFilterPresetsKm` 재사용) |
| 점 | 대상 회사만. 색·모양은 1장. 누르면 작은 말풍선: 회사 이름 · 단계 · "거산에서 12.3km" · [자세히 보기] |
| 좌표 없는 회사 | 지도에 못 찍는다. 지도 아래 "좌표 없는 회사 2곳(주소 확인 필요)" 한 줄 |
| 빈 상태 | 대상 0곳이면 지도 대신 안내 + [추천 목록 가기] |
| 약관 | Dynamic Map은 우리 데이터를 지도 위에 그리는 용도로 제공되는 기능이라 괜찮다. 제7조 ⑩ 로고 표시는 SDK가 자동으로 넣는다. 지도에서 얻는 결과 데이터(좌표 등)는 저장하지 않는다(우리는 아무것도 받지 않음) |

### 4-1. 전송 보호 검토 — 거산 내부 정보가 지도 서비스로 가는가

지도 SDK가 네이버 서버로 보내는 것과 보내지 않는 것을 나눴다.

| 네이버 서버로 **가는 것** | 네이버 서버로 **안 가는 것**(브라우저 안에서만 그림) |
|---|---|
| 지도 조각(타일) 요청: 화면 중심 좌표·확대 단계·화면 크기 | 회사 이름, 영업 단계(관심·진행·성공), 거리, 메모 |
| 클라이언트 ID, 우리 페이지 주소(referrer) | 점(마커) 좌표 목록 — 마커는 SDK가 브라우저에서 그리며 서버로 보내지 않는다 |
| | 거산 좌표(원의 중심) — 단, 지도 중심을 거산에 두므로 "중심 좌표"로는 간접적으로 나간다(공개 주소라 문제 없음) |

주의할 SDK 기능: **검색·지오코딩·길찾기 같은 "서비스" 기능(naver.maps.Service.*)은 호출하면 주소·좌표가 네이버 서버로 간다.** 우리는 쓰지 않는다.

약속 파일 C4에 더할 "화면 지도 규칙"(TransferGuard 용도가 아니라 화면 규칙):
- 지도 SDK에 넘기는 값은 **마커 위치 좌표와 원의 중심·반지름뿐**. 회사 이름·단계·거리·메모는 SDK 함수 인자로 넘기지 않고 우리 쪽 HTML 요소(말풍선)로 그린다.
- `naver.maps.Service`(검색·지오코딩·길찾기)는 호출하지 않는다. 검사: 화면 테스트에서 SDK 가짜 객체를 두고 `Service.*` 호출이 0건인지 확인(Vitest).
- 지도용 데이터 API(`GET /dashboard/map`)는 접속 보호(세션) 뒤에만 열리고, 응답에 메모·연락처·대표번호는 넣지 않는다.
