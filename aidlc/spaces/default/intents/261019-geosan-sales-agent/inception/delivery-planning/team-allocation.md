# 팀 배정 (Team Allocation) — 거산케미칼 AI 영업지원 에이전트 2차

"Bolt"는 한 번의 구현 묶음(작업 단위 하나를 설계·코드 생성·테스트까지 돌려 돌아가는 결과를 내는 것)입니다. 이 프로젝트는 범위 mvp라 팀 구성 단계(1.5)를 건너뛰었습니다. **(갱신 2026-10-21, PM 지시)** 코드는 두 갈래로 만듭니다: 각 Bolt의 **얇은 끝단 조각과 설계 산출물은 PM 세션의 개발자 에이전트(aidlc-developer-agent)가 만들고**, 그 위에서 **팀원이 각자 Claude Code/Codex로 자기 모듈을 넓히는 PR**을 올립니다. 사람 4명은 그 밖에 검토·승인·파일 작성·거산 소통을 맡습니다. "짝"은 사람 2명이 하나의 Bolt를 함께 보는 단위이고, 동시에 진행하는 Bolt는 최대 2개(11/9 주에 한해 파일이 겹치지 않는 Bolt 1개를 3개째로 허용)입니다. AI-DLC 진행·승인(`/aidlc`, `$aidlc`)은 뼈대 기간에는 PM 세션에서만 합니다(`AGENTS.md` 도구 사용 규칙).

## 3. 승인과 확인 방식

- **체크포인트 승인**: 각 Bolt가 끝나면 엔진이 검증 명령을 돌리고 PM이 승인한다(설정: 단위 하나씩·순차·체크포인트). 뼈대(B1) 승인은 사람이 직접 하며, 그 뒤 "자동으로 이어갈지, 매번 검토할지"를 한 번 묻는다(팀 실천 방식).
- **PR 확인**: 모든 PR은 PM 또는 짝의 다른 사람이 읽는다. 뼈대 기간에는 PM 시간 부족을 줄이기 위해 **모듈 PR은 다른 모듈 담당 한 명이 먼저 읽고**(규칙 → 저장소, 저장소 → 화면, 화면 → 규칙 순환), PM은 합치기 전 확인만 한다. 체크리스트: 테스트 통과, 시나리오 번호, "약속 파일을 바꿨나요?", 가상 데이터 표시, 연락처 없음.
- **시나리오 테스트 분담(갱신 2026-10-21)**: 각 모듈 담당이 자기 모듈의 시나리오 테스트(Given/When/Then)를 쓰고 통과시킨다. PM은 A정밀 끝단 시나리오와 최종 합격 확인(S01~S14 중 해당 Bolt 범위 전체 통과·커버리지 80%·검증 명령)만 맡는다.
- **동시 2개 규칙**: 같은 파일을 많이 고치는 쌍(U4·U5, U2·U5, U6·U7)은 같은 주에 두지 않았다. 11/9 주의 3개째(B9)는 안내서·예시·백업 명령만 만든다.
- **합치기**: 1~2일마다 `main`에 스쿼시 커밋. 마이그레이션은 접두사별 파일, 머리가 둘이면 `geosan db merge-heads`.

- 팀 밖 검증자 1명(사관학교 동료 또는 멘토): 11/13 전 안내서 시험과 사용성 과제(10분).
- 거산 담당자: 10월 말 부분 시연(방문 날짜 미정), 11/15 접속·의견 기록, 11월 말 방문 확인.
