# 거래 확인 전 카드 점수 표시 — "점수 흐리게 + '거래 확인 전' 꼬리표" C1 변경 제안 (PM 결정 2026-11-04, 1차 본안)

**상태**: PM 승인(2026-11-04), 약속 파일 C1·C3·C6 반영 완료. 이슈 — 점수 표시: #262(규칙 엔진 유동렬)·#263(카드 응답 이강욱)·#264(화면 고선주), 거래 관계 입력(1차): #265(서버 이강욱)·#266(화면 고선주). 근거: #212 ① 결정 변경 — 거래 관계는 전달 후 거산이 쓰면서 알려 주기로 합의(18곳 질문은 보내지 않음). ② 고정 문구 '부분 시연·거산 확인 전'(앱 설정 `brand.demoLabel`)은 유지.

## 0. 한 줄 결론

거래 관계가 아직 확인되지 않은 회사(18곳 전부)는 카드 점수를 `--`로 숨기지 않고 **계산 점수를 흐리게 보이고 "거래 확인 전" 꼬리표**를 붙인다. 카드 정렬은 지금처럼 **계산 점수(E) 기준**이고 바뀌지 않는다. 거래 관계가 확인되면(거산이 알려 줌) 점수가 진하게 바뀌고 꼬리표가 사라진다.

## 1. 지금 상태와 왜 바꾸나

| | 지금 | 바꾼 뒤 |
|---|---|---|
| 카드 점수(거래 미확인) | 소개서 묶음이면 "참고 50점 · 3/8", 확인 묶음이면 `--` | "50점 · 3/8"을 **흐리게** + 꼬리표 **거래 확인 전** |
| 카드 정렬 | 계산 점수 E 내림차순(설정 `otherGroupSort`, 소개서·기본 둘 다 E 우선) | **그대로** |
| 분류 | 필수조건 확인 필요(FILTER_PENDING) | 그대로. 분류 규칙·점수 규칙 숫자는 안 바꿈 |
| 막는 조건 줄 | "거래 관계 확인 전" | 그대로 |
| 상단 고정 문구 | '부분 시연·거산 확인 전' | 그대로(② 결정) |

이유: 거산 확인 완료 묶음으로 바꾼 뒤(#212) 18곳 카드가 전부 `--`가 되어 순위가 있어도 점수가 안 보인다. 거래 관계는 거산이 쓰면서 알려 주기로 했으니, 그때까지 점수를 참고값으로 보이되 "확인 전"임을 분명히 한다.

## 2. 화면 모양

- [추천 목록 › 카드 점수] 거래 미확인이면 점수 글자를 흐리게(보조 색) + 바로 옆 꼬리표 "거래 확인 전". 예: "50점 · 3/8 [거래 확인 전]". 소개서 묶음에서는 지금 "참고 " 접두 그대로(바꾸지 않음).
- [추천 목록 › 카드 꼬리표 줄] 공정·지역·산업 꼬리표 옆이 아니라 **점수 옆**에 둔다(점수에 대한 주석이라서).
- [상세 › 머리 점수 줄] 같은 규칙으로 흐리게 + 꼬리표.
- [거래 확인 뒤] 점수 진하게, 꼬리표 없음. 분류는 재평가로 바뀐다.
- 가상 사례(A정밀)는 거래 관계가 사례 파일에 확정되어 있어 영향 없음(기대값 11항목 그대로).

## 3. 약속 파일 변경 (C1, PM 확인 뒤 적음)

| 어디 | 무엇 | 성격 |

## 4. 거래 관계를 화면에서 직접 입력하는 길 — 지금은 없음

- 지금 거래 관계는 **사례 파일의 `relationStatus`로만** 들어온다(NEW_CONFIRMED 거래 없음 / EXISTING_CONFIRMED 거래 중 / UNCONFIRMED). 화면·API·명령 어디에도 바꾸는 길이 없다.
- 거산이 알려 주면 지금 방식으로는 **PM이 사례 파일을 고쳐 다시 투입(`import-case`) → `evaluate`**. 개발 0시간, 회사마다 PM 손이 간다.
- 화면 입력을 만들면(1차에 넣을지 PM 결정):

| 누가 | 무엇 | 시간 |
|---|---|---|
| PM | 약속 C1 요청 1개 `POST /opportunities/{oppId}/relation` `{ relationStatus: NEW_CONFIRMED \| EXISTING_CONFIRMED, evalId }`(403 보기 전용, 409 평가 낡음), C6 `opp_customer.relation_confirmed_by` 열 1개(`relationConfirmedAt`은 이미 있음), 활동 이력 종류 `RELATION_CONFIRMED` | 0.5h |
| 이강욱(서버) | 요청 1개, 고객 행 갱신(확인 시각·담당자), 그 기회 재평가(기존 평가 진입점 재사용), 활동 이력 한 줄, 테스트 | 3h |
| 고선주(화면) | 상세 머리에 "거래 관계: 확인 전 [거래 없음] [거래 중]"(인라인, 모달 없음) → 저장 뒤 상세 새로 불러오기·"재평가됨" 띠, 카드 꼬리표 사라짐, 테스트 | 2h |

- 거래 관계는 거산 내부 정보라 지금 규칙대로 외부 AI·검색에는 안 나간다(C4 CUSTOMER_RELATION 거부). 엑셀(내부용)에는 나간다.

## 5. 시기

- 표시 변경(1~3장): 1차 본안. 규칙 엔진 표시 함수 1곳(유동렬)·카드 응답 2칸(이강욱)·화면 흐리게+꼬리표(고선주), 각 1~2h.
- 화면 입력(4장): **1차에 넣음(PM 결정 2026-11-04).** 6·7장 조건 포함.

## 6. "거래 중"을 고르면 카드를 어떻게 하나 (PM 질문, 의견과 기본안)

지금 규칙에서 거래 중(EXISTING_CONFIRMED)인 회사는 **신규와 똑같이 평가·정렬**된다. 규칙 엔진은 거래 관계를 "확인 전이면 필수조건 확인 필요"로만 쓰고, 거래 중이라고 빼거나 뒤로 보내지 않는다(가상 사례 A정밀도 거래 중이면서 1순위). 재접촉(기존 거래처 재영업) 프로필은 따로 있지만 U6과 함께 보류다.

| 안 | 기존 규칙과 맞나 | 비용 | 의견 |
|---|---|---|---|
| 목록 제외 | 안 맞음. "평가는 하되 거산 판단"이라는 원칙과 어긋나고, 거래 중 회사에 다른 공정을 제안하는 길(교차 영업)이 사라짐 | 작음 | 권하지 않음 |
| "기존 거래처" 표시만 | **맞음.** 규칙·정렬 그대로, 꼬리표만 | 가장 작음(화면만) | 규칙 관점에서 가장 자연스러움 |
| 표시 + 맨 아래 (**PM 기본안**) | 정렬 규칙(C3 BR6.4~6.5)에 "거래 중은 뒤로" 한 단계를 더해야 함. 분류·점수는 그대로 | 규칙 엔진 정렬 1곳 + 설정 키 1개(+2h, 유동렬) | 거산이 "새 거래처 찾기" 용도로 쓸 때 목록 위쪽이 깨끗해지는 장점. 기존 거래처에 다른 공정을 제안할 때는 아래에서 찾으면 됨 |

**기본안(PM): 목록에 남기되 "기존 거래처" 꼬리표 + 맨 아래.** 설정 `existingCustomerPlacement: BOTTOM | INLINE`(기본 BOTTOM, `examples/rule-config.yaml`)으로 두어 INLINE으로 바꾸면 "표시만" 안이 된다. 약속 C3에 적음(2026-11-04).

## 7. 되돌리기와 활동 이력

- 거래 없음 ↔ 거래 중 ↔ 확인 전 **어느 방향이든 바꿀 수 있다.** 같은 값으로 다시 보내면 400.
- 바꿀 때마다 `opp_relation_history` 1행(이전 값·새 값·담당자·시각)을 남기고, 활동 이력에 "거래 관계: 확인 전 → 거래 중 · 박 이사 · 11/20"(종류 RELATION_CONFIRMED)으로 보인다. 현재 값은 `opp_customer`(확인 시각·담당자).
- 바꾸면 그 기회를 **재평가**한다(분류·꼬리표·정렬이 같이 바뀜). "확인 전"으로 되돌리면 다시 필수조건 확인 필요가 된다.
- 사례 파일을 다시 넣어도 화면에서 바꾼 값을 되돌리지 않는다(파일 값과 다르면 경고 줄, 재투입 규칙과 같음). 약속 C6 재투입 규칙에 PM이 한 줄 더한다.
