# 범위·우선순위 변경 제안 — 10/29 거산 방문 후 (2026-11-02 메모 기준, 초안 2026-11-03)

> 상태: **PM 결정 완료 2026-11-03** (답은 4-1장, 재배정 시간표는 6장 "갱신" 표). 승인 문서(범위·작업 단위·의존 그래프·Bolt 계획·팀 배정·요구사항 표시·계약 요약 v2)에 같은 날 반영. 원본은 `docs/input/20261102_기획변경메모_방문후.md`(PM 메모, 손대지 않음). 이 제안서는 10/21 `b1-change-proposal-20261021.md`와 같은 틀로, 메모의 "바뀌는 것"을 승인 문서(범위·작업 단위·팀 배정·약속 파일)에 어떻게 반영할지와, 메모의 ❓ 칸을 **쉬운 말 질문 / 추천안 / 이유 / 이걸 고르면 달라지는 것** 표로 정리한 것이다. PM이 4장 표에 답하면 5장 "갱신 필요" 표대로 승인 문서를 고치고 커밋한다. 규칙 숫자(부록 F)·A정밀 기대값(E 77 / P 95 / S 81.1 / R 82)·시나리오·화면 3개는 바꾸지 않는다(메모 3장).

## 0. 방문에서 확인한 방향 (메모 1장 요약)

- 거산은 기존 거래처 재접촉보다 **새 후보 기업 영업을 먼저** 하고 싶어 한다.
- 지금 들어 있는 **18곳으로 바로 영업을 시작**하고, 그 과정의 메모·접촉 기록이 도구에 쌓이기를 원한다.
- 따라서 11/15 전달의 중심이 "자동 수집·자동 근거 추출"에서 "**영업하며 기록하고, 첫 화면에서 오늘 할 일을 보는 것**"으로 옮겨 간다.

## 3. U5 최소형이 약속 파일(계약 요약)과 얼마나 맞는가

메모 4장의 네 기록을 지금 약속 파일에 대 보면 **대부분 이미 있고, 더하기만 하면 된다.**

| 메모 4장 기록 | 약속 파일에 이미 있는 것 | 더할 것(추가 변경) | 깨는 변경 |
|---|---|---|---|
| 영업 단계: 미접촉 → 접촉 → 견적·샘플 → 성사 / 보류 / 거절 | C0 `outcomeStatus` 6값(NOT_EXECUTED / IN_PROGRESS / SAMPLE_OR_REGISTRATION_APPROVED / WON / ON_HOLD / LOST)이 **그대로 1:1로 맞음**. C1 `/outcomes`에 저장 | 쉬운 말 대응표(`web/src/labels/ko.ts`)에 "미접촉·접촉·견적·샘플·성사·보류·거절" 추가. 목록 카드 꼬리표 1줄 | 없음 |
| 접촉 시도: 날짜·방법(전화·메일·방문)·결과(연결됨·부재·거절) | C1 `/outcomes`의 접촉 건(`actionId`), `ActivityItem.kind = CONTACT_ATTEMPT`, FR7.5 "접촉 시도는 접촉 건마다 새 행" | C0에 `contactMethod: [CALL, EMAIL, VISIT]`, `contactResult: [REACHED, ABSENT, DECLINED]` 추가. `/outcomes` 본문에 `method`·`result`·`attemptedAt` 선택 칸 추가 | 없음 |
| 영업 메모: 자유 글 200자, 담당자·시각 자동 | FR7.6(담당자명·시각 자동), 연락처 검사 `find_contact`(`geosan/config/validators.py`) 재사용 | **여섯 번째 기록 종류** `rec_note` 테이블 + `POST /opportunities/{id}/notes` + `ActivityItem.kind`에 NOTE. 200자 상한은 설정값 | 없음(FR7.1 "기록마다 다른 테이블" 원칙대로 새 테이블) |
