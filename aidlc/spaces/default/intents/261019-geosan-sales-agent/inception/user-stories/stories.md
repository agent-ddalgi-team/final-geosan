# 사용자 스토리 (User Stories) — 거산케미칼 AI 영업지원 에이전트 2차

요구사항(`../requirements-analysis/requirements.md`, FR1~FR14·NFR1~NFR12)을 세 페르소나(`personas.md`: 영업 담당자 "박 이사", 검수자 "김 품질", 운영자 "최 운영")의 이야기로 다시 썼습니다. 묶음은 `user-stories-questions.md`의 확인된 답변(Q2)대로 가치 흐름 순서이고, 이야기 하나는 사용자 목표 하나(Q3), 수용 기준은 "주어진 상황 / 할 때 / 결과"(Given/When/Then) 형식으로 기획서 시나리오 번호 `[S nn]`을 붙여 시나리오 테스트에 그대로 옮길 수 있게 썼습니다(Q4). 운영자의 일도 결과가 보이는 이야기로 썼습니다(Q5).

**우선순위(MoSCoW)**는 백로그(`../../ideation/scope-definition/intent-backlog.md`)의 P0 = Must(10/30·11/6), P1 = Should(11/15), P2·P3 = Could, 판단 보류 = Won't를 그대로 씁니다. 전달 계획에서 MVP 경계를 확정합니다.

**ID 규칙**: 이야기는 `US{묶음}.{순번}`, 수용 기준은 `AC{묶음}.{순번}.{기준}`. 출처 태그는 요구사항 ID(`FR n.m`, `NFR n`), 백로그(`B-nn`), 시나리오(`[S nn]`), 질문 답변(`[Qn]`, 이 단계; `[Qn req]`, 요구사항 단계)입니다.

**INVEST 메모**: 각 이야기는 독립적으로 테스트할 수 있게 썼고(I·T), 세부는 설계에서 바꿀 수 있으며(N), 사용자에게 보이는 결과를 "so that"에 적었습니다(V). 크기는 비전공 4인 팀 기준 1~4일(S), 추정은 작업 단위 나누기에서 합니다(E). 의존은 각 묶음 끝에 적었습니다.

**참고 문서 반영**: 팀 페르소나 v2.0(`docs/input/05_사용자페르소나_v2_참고.md`, 참고용)에서 사용자가 지정한 것만 가져왔습니다(Q6~Q12): 측정 가능한 사용성 목표(이력 찾기 60초, 기록 선택 3회+메모 1줄, 대표 이해 5분), 사실/추정/미확인·내부용/외부용/가상 표시, 검수자 업무 흐름(확인 요청 → 자료 보완 → 판정 → 회신), 대표용 '거산이 줄 자료 목록', "ERP 복제가 아닌 판단 지원 도구" 원칙. 재접촉 우선 홈·견적/품질 이슈 시나리오·신입사원 페르소나·모바일 390px 필수·'조건부' 판정은 따르지 않습니다. 이 도구는 기록을 대신 관리하는 ERP가 아니라 "근거와 다음 행동을 제안하는 판단 지원 도구"이며, 모든 이야기는 그 원칙 안에서 씁니다.

## 묶음 1. 거산 역량 준비·검수 — [FR1] [FR11] [B-01] [S01]

### US1.1 공정 9종과 거산 값을 파일로 등록한다 — Must (P0)

**As a** 운영자, **I want** 공정 9종·역량 항목·인증과 적용 범위·검수 상태를 파일(CSV/JSON) 하나로 넣어 등록하기를, **so that** 관리 화면 없이도 추천의 근거가 되는 거산 데이터가 준비된다. [FR1.1~FR1.4] [B-01] [Q5]

- **AC1.1.1** Given 공정 9종(아연도금, 아노다이징, 흑착색(알카리흑착), 크로메이트, 전해연마, 크롬도금, 무전해니켈, 인산염피막, 부동태)이 적힌 파일, When 운영자가 등록 명령을 실행하면, Then 9종이 각각 하나의 공정으로 등록되고 공정마다 등록 상태(소개서 표기 / 공식 명칭 확정)가 보인다. [S01]
- **AC1.1.2** Given 등록된 공정, When 역량 항목(사양·시험·설비)을 넣으면, Then 종류 구분과 함께 저장되고 숫자 사양(예: 아연도금 두께 5/13/25㎛)은 최소·최대·단위로 나뉘어 저장된다. 설비 항목은 "설명용"으로 표시되어 생산능력 판정에 쓰이지 않는다. [FR1.2]
- **AC1.1.3** Given 거산 값 하나, When 조회하면, Then 검수 상태 넷(미확보 / 검수 대기 / 검수 완료 / 재확인) 중 하나와 검수자·검수일·근거가 함께 보이고, '검수 완료'가 아닌 값은 가점·필수조건 통과 근거로 쓰이지 않는다. [FR1.3] [S01]
- **AC1.1.4** Given ISO 9001·AS9100D 인증, When 적용 범위를 등록하면, Then 아노다이징·크로메이트·전기아연도금·부동태 4개 공정에만 연결되고, 다른 공정(예: 무전해니켈) 연결의 필수 인증 판정에는 쓰이지 않는다. 공정 ID가 비어 있는 범위는 "모든 공정"으로 해석되지 않는다. [FR1.4] [FR1.6]
- **AC1.1.5** Given 운영 안내서만 있는 비개발자 운영자, When 안내서대로 하면, Then 명령 3개 이내로 공정·인증 파일 등록이 끝난다. [Q5]

### US1.2 회사소개서 값을 '검수 대기'로 투입한다 — Must (P0)

**As a** 운영자, **I want** 회사소개서(2026-09-21판)의 공정·소재·두께·인증 범위·유효기간·주요 거래처를 '검수 대기'로 넣기를, **so that** 거산 확인 전에도 실제에 가까운 값으로 흐름을 돌려 보되 확인 안 된 값이 추천 근거로 쓰이지 않는다. [FR1.5~FR1.7] [FR2.6] [Q9 req]

- **AC1.2.1** Given 소개서 값 파일, When 투입하면, Then 모든 값이 '검수 대기'로 등록되고 출처가 "회사소개서 2026-09-21"로 남는다. [FR1.5]
- **AC1.2.2** Given 한화시스템 특수공정 승인서, When 투입하면, Then 상태가 '미확인'으로 등록되어 통과 근거로 쓰이지 않는다. [FR1.7] [S11]
- **AC1.2.3** Given 주요 거래처 13곳, When 투입하면, Then 고객 관계가 '기존 관계 확인'(이력 종류: 거래, 근거: 회사소개서, 검수 대기)으로 등록되고 보안 등급은 '내부 구조화만'이라 외부 LLM 전송 대상에서 제외된다. [FR2.6] [FR2.7]
- **AC1.2.4** Given 흑착색과 알카리흑착, When 등록하면, Then 하나의 공정으로 등록되되 "같은 공정 여부 거산 확인 전(가정 A11)" 표시가 남는다. [FR1.1] [Q12 req]

### US1.3 확인 질문에 답하면 값이 '검수 완료'가 된다 — Must (P0 질문 생성) / Should (P1 전환 흐름)

**As a** 검수자, **I want** 거산 값·요구 중 확인이 안 된 것에 대한 질문을 예/아니요로 답할 수 있는 형태로 받기를, **so that** 긴 문서를 읽지 않고도 바뀐 것만 알려 주면 추천 근거가 최신으로 바뀐다. [FR11.1] [FR11.3] [FR1.3] [Q4 req] [Q9 req]

- **AC1.3.1** Given '검수 대기'·'미확보'·'재확인'인 거산 값 또는 '미확인'·'단계 미확인'인 요구, When 평가를 실행하면, Then 해당 값·요구에 연결된 확인 질문(예: "ISO 9001 인증 범위에 아노다이징 라인이 포함됩니까?")이 예/아니요 형태로 생성·저장된다. [FR11.1] [S07]
- **AC1.3.2** Given 검수자의 답(예/아니요, 바뀐 것만), When 운영자가 해당 값의 검수 상태를 '검수 완료' 또는 '재확인'으로 바꾸면, Then 영향받는 기회가 재평가되고 이전 평가는 보존된다. [FR11.3] [FR5.10]
- **AC1.3.3** Given 운영 안내서만 있는 비개발자 운영자, When 안내서대로 하면, Then 명령 3개 이내로 값 하나의 검수 상태를 바꾸고 재평가까지 끝난다. [Q5]
- **AC1.3.4** Given '검수 완료'로 바뀐 값, When 조회하면, Then 검수자·검수일·근거(메일 답변 일자)가 함께 남고 그 값이 가점·통과 근거로 쓰이기 시작한다. [FR1.3]
- **AC1.3.5** Given 검수자 업무 흐름(확인 요청 → 자료 보완 → 판정 → 회신), When 질문 목록(US9.1)의 질문 하나를 따라가면, Then 요청(상태 '요청') → 검수자가 자료를 보완해 답함(상태 '회신') → 운영자가 통과/미확인/제외 판정에 쓰일 값으로 반영(상태 '반영')의 세 상태가 기록되고, '조건부' 같은 중간 판정은 없다. [Q8] [FR3.2]

**의존**: 없음(첫 묶음). US1.3의 전환 흐름은 US5.1(평가 실행)에 의존.

## 묶음 2. 후보 찾기 — [FR9] [B-07] [B-12] [B-14] [B-17]

### US2.1 산단공 CSV에서 범위를 정해 후보를 불러온다 — Must (P0, 11/6)

**As a** 운영자, **I want** 한국산업단지공단 전국등록공장현황 CSV를 지역·생산품 키워드 설정으로 걸러 후보 기업·기회로 등록하기를, **so that** 11/6 첫 흐름에서 실제 후보 30~50건이 추천 목록 2위 이하에 나타난다. [FR9.1] [FR9.2] [FR9.6] [Q6 req] [B-07]

- **AC2.1.1** Given 수집 설정(지역 기본값 충남+대전·세종, 생산품 키워드 목록), When 수집 명령을 실행하면, Then 설정 범위에 맞는 후보만 기업·기회로 등록되고 전국 전체가 들어오지 않는다. [FR9.1]
- **AC2.1.2** Given 수집 완료, When 집계를 보면, Then 원천 레코드 수, 중복 제거 후 기업 수·기회 수, 필터 결과·사유, 소스·기준일, 건너뛴 행 번호·이유가 보이고 부분 결과가 완전한 것처럼 보이지 않는다. [FR9.2]
- **AC2.1.3** Given CP949로 저장된 CSV 또는 헤더 이름이 다른 CSV, When 수집하면, Then 인코딩을 확인해 읽고 필수 열이 없으면 어떤 열이 없는지 알리고 멈춘다. [FR9.2]
- **AC2.1.4** Given 11/6 시연 설정, When 수집하면, Then 등록 후보 수가 30~50건으로 제한되고 중복 집계가 없다. [B-07]
- **AC2.1.5** Given 운영 안내서만 있는 비개발자 운영자, When 안내서대로 하면, Then 명령 3개 이내로 수집이 끝난다. [Q5]

### US2.2 업종코드를 보강하고 자체 도금라인 보유 업체를 표시한다 — Should (P1)

**As a** 운영자, **I want** 공장등록생산정보 API로 업종코드를 보강하고 특정수질유해물질 업체 CSV와 겹치는 후보를 표시하기를, **so that** 영업 담당자가 자체 도금라인이 있을 법한 후보를 제외 사유와 함께 보고 직접 제외를 정한다. [FR9.3] [B-12] [CON-06]

- **AC2.2.1** Given 후보 1,200건과 개발 계정 일 1,000건 제한, When API 보강을 실행하면, Then 하루 1,000건을 넘지 않게 나눠 실행되고 남은 건은 다음 실행으로 넘어간다. [FR9.3]
- **AC2.2.2** Given 수질유해물질 CSV와 겹치는 후보, When 목록을 보면, Then "자체 도금라인 보유 추정" 사유가 표시되되 자동 제외되지 않고 담당자가 '대상 아님'으로 제외를 확정한다. [FR9.3] [S09]
- **AC2.2.3** Given 이용·저장 허용 범위가 소스 계약표에 기록되지 않은 소스, When 수집을 시도하면, Then 실행되지 않고 이유가 보인다. [FR9.6]

### US2.3 나라장터 공고의 마감일을 시점 신호로 붙인다 — Could (P2)

**As a** 운영자, **I want** 조달청 나라장터 입찰공고 API로 공고·마감일을 기회의 시점 신호로 붙이기를, **so that** 공고 마감 전인 기회가 시점 점수를 받고 담당자가 기한을 본다. [FR9.4] [B-14]

- **AC2.3.1** Given 마감 전 공고, When 신호를 붙이면, Then 공고 항목(SIG_BID) 감쇠 1.0으로 시점 점수에 반영되고 카드에 마감일이 보인다. [FR4.3]
- **AC2.3.2** Given 마감·취소된 공고, When 재평가하면, Then 그 신호의 점수는 0이 되고 "마감"이 표시된다. [FR4.3] [S11]
- **AC2.3.3** Given G0 합의 전 실제 후보, When 공고 마감이 가까워도, Then 시점 우선 분류는 받지 않고 계획형 등 다음 분류로 표시된다. 시점 우선 반영은 가상 합의값이 있는 사례에서만 검증한다. [FR9.4] [FR4.7]

### US2.4 수동 명단으로 경쟁사 제외와 방산 씨앗을 표시한다 — Could (P3)

**As a** 운영자, **I want** 뿌리기술 전문기업 명단과 방산업체 지정현황을 한 번 내려받아 적용하기를, **so that** 경쟁사가 후보에서 빠지고 방산 공급망 후보가 표시된다. [FR9.5] [B-17] [CON-12]

- **AC2.4.1** Given 뿌리기술 전문기업 명단(표면처리 업종), When 적용하면, Then 겹치는 후보에 "경쟁사(수동 명단)" 제외 사유가 표시된다. [B-17]
- **AC2.4.2** Given 방산 자료 취급 제한을 거산이 확인하지 않은 상태, When 방산업체 명단 적용을 시도하면, Then 실행되지 않고 "거산 확인 필요"가 보인다. [CON-12]

**의존**: US2.x는 US3.1(병합)에 의존. US2.2~2.4는 US2.1 뒤.

## 묶음 3. 기회 정리 — [FR2] [B-02] [S02] [S04] [S06]

### US3.1 같은 기업·기회가 하나로 합쳐지고 애매하면 사람이 확정한다 — Must (P0)

**As a** 운영자, **I want** 여러 경로에서 들어온 같은 기업·기회가 자동으로 하나가 되고 애매한 것은 "확인 필요"로 남기를, **so that** 추천 목록에 같은 기회가 두 번 나오지 않고 잘못 합쳐지지도 않는다. [FR2.1~FR2.5] [CON-05] [B-02]

- **AC3.1.1** Given 공고 경로와 홈페이지 경로로 각각 발견한 A정밀 밸브 바디 건, When 등록하면, Then 기회 ID는 하나이고 발견 경로는 2건으로 남는다. [S02]

- **AC9.4.2** Given 배포 전, When 안내서의 백업 절차를 따르면, Then SQLite 파일 백업이 만들어지고 복원 절차로 직전 상태가 돌아온다. [NFR7]
- **AC9.4.3** Given 설정 파일(수집 범위, 담당자 목록, 거산 값 묶음, 규칙 설정, 로고·강조색), When 값을 바꾸면, Then 코드 수정 없이 반영되고 규칙 설정 변경은 버전·해시가 기록된다. [NFR11]

### US9.5 추가조사 질문·경로·담당·시간을 기록한다 — Could (P2)

**As a** 영업 담당자, **I want** "더 알아봐야 함"으로 분류된 기회에 질문 묶음·허용 경로·담당자·예상 시간·상한·재확인일을 상세에서 기록하기를, **so that** 조사가 흐지부지되지 않고 재확인일에 다시 본다. [FR12.1] [B-16] [S12]

- **AC9.5.1** Given 추가조사 기회, When 기록하면, Then 기록 1건이 생기고 조사 목록이 재확인일 오름차순(미기재 마지막) → 기회 ID 순으로 보인다. [S12]
- **AC9.5.2** Given P0 시점, When 가상 사례 파일에 조사 요건 값을 넣으면, Then 화면 입력 없이도 ⑧/⑨ 분류가 판정된다. [FR4.9]

### US9.6 화면을 다듬는다 — Could (P3)

**As a** 영업 담당자, **I want** 여유가 있을 때 간격·글꼴·색과 진행 단계 그림이 다듬어지기를, **so that** 보기 편해진다. 기능 완료 기준에는 들어가지 않는다. [FR6.9] [B-18] [Q12]

- **AC9.6.1** Given P3 작업, When 다듬기를 적용하면, Then 기능·수용 기준은 바뀌지 않고 화면 모양만 바뀐다. [FR6.9]
- **AC9.6.2** Given 지연, When 줄이는 순서를 적용하면, Then 이 이야기가 가장 먼저 빠진다. [scope 6절]

**의존**: US9.1은 US1.3·US5.2 뒤. US9.3은 US7.x 뒤. US9.4는 전체 뒤(인계). US9.6은 맨 마지막.

## 묶음 10. 공통 — [FR1.8] [FR14] [FR4.14] [FR6.6~FR6.8] [NFR4] [NFR8] [NFR10]

### US10.1 가상 데이터는 항상 가상이라고 보인다 — Must (P0)

**As a** 영업 담당자, **I want** 가상 사례·가상 검수 데이터가 섞인 화면과 출력물에 "가상·거산 실제 사양 아님" 띠가 항상 보이기를, **so that** 가상 수치를 실제 거산 역량으로 오해하지 않는다. [FR1.8] [CON-10] [scope P1-4]

- **AC10.1.1** Given 가상 행과 실제 행이 섞인 데이터, When 목록·상세·엑셀을 보면, Then 띠와 행 단위 표시가 모두 보인다. [FR1.8]
- **AC10.1.2** Given 실제 데이터만 있는 화면, When 보면, Then 가상 띠는 보이지 않지만 "내부용·고객 제출용 아님" 표시는 모든 화면·출력물에 항상 보인다. [FR1.8] [Q10]
- **AC10.1.3** Given 근거 문장과 거산 값, When 보면, Then 각각 사실(확인) / 추정(강한·약한) / 미확인(미확보·검수 대기)이 글자로 구분되어 추정이 확정처럼 보이지 않는다. [FR4.4] [FR1.3] [참고: 페르소나 v2]

### US10.2 담당자명을 고르고 거산 환경에서는 비밀번호로 보호된다 — Must (P0 담당자명) / Should (P1 접속 보호)

**As a** 영업 담당자, **I want** 계정 없이 상단에서 내 이름을 고르고, 거산 접속 환경에서는 공용 비밀번호와 HTTPS로 보호되기를, **so that** 쉽게 쓰면서도 밖에서 아무나 보지 못한다. [FR14.1~FR14.3] [NFR4] [Q7 req]

- **AC10.2.1** Given 담당자 목록 설정, When 상단에서 이름을 고르면, Then 이후 의견·담기·승인·결과에 그 이름과 시각이 저장된다. [FR14.1]
- **AC10.2.2** Given 거산 접속 환경, When 비밀번호 없이 또는 틀린 비밀번호로 접속하면, Then 모든 화면과 API가 거부되고, 맞으면 세션이 유지된다. 비밀번호는 환경 변수에서만 읽힌다. [FR14.2]
- **AC10.2.3** Given 호스팅 환경, When 접속하면, Then HTTPS로만 열린다. [NFR4]
- **AC10.2.4** Given 실제 거래처 정보 입력 전, When 담당자별 계정으로 전환하면, Then 담아 둔 기회·대시보드가 사람별로 나뉠 수 있다(방식은 G0 이후). [FR14.3]

### US10.3 거산 확인 전에는 참고 추천과 질문 목록만 보인다 — Should (P1)

**As a** 영업 담당자, **I want** 거산 확인이 안 된 값으로 평가된 기회에 "거산 확인 전" 띠·참고 점수·확인 대기 질문 목록이 보이고 승인은 막히기를, **so that** 11/15에 거산 답이 늦어도 흐름을 보되 확인 안 된 값으로 연락이 나가지 않는다. [FR4.14] [Q11 req]

- **AC10.3.1** Given 거산 값 묶음 '소개서', When 목록·상세를 보면, Then "거산 확인 전" 띠, 참고 점수, 질문 목록이 보이고 [승인]은 비활성이다. [FR4.14]
- **AC10.3.2** Given 거산 답으로 값이 '검수 완료'로 바뀜, When 묶음을 '거산 확인 완료'로 바꿔 재평가하면, Then 띠가 사라지고 정식 분류·승인이 열린다. [FR11.3]
- **AC10.3.3** Given 소개서 묶음 기회, When 대시보드를 보면, Then "질문 답변 기다림" 건수에 들어간다. [FR6.4]

### US10.4 쉬운 말·키보드·오류 안내가 모든 화면에서 한결같다 — Must (P0)

**As a** 영업 담당자, **I want** 모든 화면이 쉬운 말, 큰 글자, 색+글자 상태 표시, 키보드 조작, 다섯 상태(비어 있음·불러오는 중·정상·오류·일부)를 갖추기를, **so that** 누구나 안내 없이 쓴다. [FR6.6~FR6.8] [NFR8] [NFR10] [Q6 Q8 rough-mockups]

- **AC10.4.1** Given 거산 담당자 1명(11/15 당일) 또는 팀 밖 검증자 1명(11/13 전), When 안내 없이 "목록 확인 → 상세 보기 → 의견 저장"을 하면, Then 10분 안에 끝난다. [FR6 완료 기준] [Q13 req]
- **AC10.4.2** Given 임의 화면, When 검사하면, Then 본문 글자 16px 이상, 글자 대비 4.5:1 이상, h1 하나, "본문으로 건너뛰기" 링크, 저장 결과 낭독, 상태는 색+글자다. [FR6.7] [NFR8]
- **AC10.4.3** Given 외부 호출·DB·파일 오류, When 발생하면, Then 오류 코드 없이 쉬운 말 안내가 보이고 로그에 남으며 조용히 실패하지 않는다. 일부 소스 실패 시 불러온 것과 실패한 것이 구분된다. [NFR10]
- **AC10.4.4** Given 로고·강조색 설정 변경, When 반영하면, Then 모든 화면의 로고·강조색이 한 번에 바뀐다. [FR6.8]
- **AC10.4.5** Given P0, When 입력 화면을 찾으면, Then 관리 화면은 없고 가상 사례·후보·거산 값은 파일로만 들어온다. [FR6.6]

### US10.5 거산 내부 자료와 연락처는 밖으로 나가지 않는다 — Must (P0)

**As a** 거산 대표·상무(영업 담당자 변형), **I want** 재접촉 입력값·거산 내부 이력·주요 거래처 관계가 외부 AI로 가지 않고 개인 연락처가 저장되지 않기를, **so that** 도면·노하우·거래처 정보가 새지 않는다. [NFR4] [FR5.4] [FR8.2] [CON-09] [CON-11]

- **AC10.5.1** Given 외부 LLM 호출 직전, When 보낼 내용의 보안 등급을 검사하면, Then '공개'·'외부 AI 허용'만 보내지고 '내부 구조화만'·'처리 금지'·'미확인'은 보내지지 않으며 거부가 로그에 남는다. [FR5.4]
- **AC10.5.2** Given 재접촉 흐름 전체, When 테스트하면, Then 외부 전송 기록이 0건이다. [FR8.2] [S05]
- **AC10.5.3** Given LLM 호출 로그, When 보면, Then 시각·모드·모델·보낸 자료 등급·토큰 수만 있고 본문은 없다. [NFR5]
- **AC10.5.4** Given API 키·비밀번호, When 코드를 검사하면, Then 하드코딩이 없고 환경 변수로만 읽힌다. [NFR4]

**의존**: 공통 묶음은 각 화면 이야기와 함께 구현된다.
