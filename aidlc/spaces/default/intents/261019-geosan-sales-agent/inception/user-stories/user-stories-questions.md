# 사용자 스토리 계획 질문 (User Stories)

요구사항(`../requirements-analysis/requirements.md`, FR1~FR14·NFR1~NFR12)을 "누가 왜 무엇을 하는가"의 이야기(사용자 스토리)로 바꾸기 전에, 사람과 이야기의 단위를 정합니다. 우선순위(P0~P3 → Must/Should/Could/Won't)는 백로그에서 이미 정해졌으므로 다시 묻지 않습니다. 수용 기준은 인셉션 규칙에 따라 "주어진 상황 / 할 때 / 결과"(Given/When/Then) 형식으로 쓰고, 팀 실천 방식에 따라 시나리오 테스트의 재료가 되게 씁니다. `[Answer]:` 칸에 보기 글자를 적거나 `X`를 고른 뒤 직접 적어 주세요.

## Q1. 이야기의 주인공(페르소나)을 몇 명으로 둡니까?

이해관계자 지도에는 영업 담당자(1차 사용자), 기술·품질 담당자(검수자), 대표·상무(의사결정자), 팀 4인이 있습니다. 관리 화면이 없으므로 파일 투입·수집·평가 실행은 팀이 합니다.

C. 2명: 거산 영업 담당자와 팀 운영자만. 검수자 역할은 메일 질문 목록 스토리 안에서 다룸
