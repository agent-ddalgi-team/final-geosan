# 사용자 스토리 필요성 평가 (User Stories Assessment) — 거산케미칼 AI 영업지원 에이전트 2차

## 결정

**Execute** — 사용자 스토리를 작성한다.

## 근거

- 사용자가 직접 쓰는 웹 화면이 5개(추천 목록, 근거 상세, 의견·담기·승인·결과 영역, 대시보드, 재접촉 입력)이고, 1차 사용자(거산 영업 담당자) 외에 검수자(기술·품질 담당자), 팀 운영자(파일 투입·수집·평가 실행), 읽기 전용 관람자(대표·상무)가 있다. 사용자별 목표가 다르다. [requirements.md 1절, FR6] [stakeholder-map]
- 판단 규칙(필터 → 점수 → 11개 분류 → 정렬)이 복잡하고, 담당자 입력(의견·담기·승인·결과, 시점 우선 체크)이 규칙과 얽힌다. "누가 왜 무엇을 하는가"를 스토리로 적어야 설계·테스트가 사용자 가치에 묶인다. [FR4, FR7]
- 팀 실천 방식이 기획서 시나리오 S01~S14를 Given/When/Then 시나리오 테스트로 먼저 쓰는 방식(custom)이므로, 수용 기준(AC)이 곧 시나리오 테스트의 재료가 된다. [team-practices Testing Posture]
- 4인 비전공 팀이 AI 도구로 구현하므로, 요구사항(FR n.m)을 "담당자가 이렇게 쓴다"는 이야기로 다시 쓰면 작업 단위 나누기·전달 계획에서 가치 순서를 잡기 쉽다. [CON-16]

## 고려한 요소

| 요소 | 판단 |
|---|---|
| 프로젝트 유형 | 그린필드 웹 도구, 범위 mvp. 리팩터링·버그 수정·인프라 전용이 아님 |
| 사용자 대면 범위 | 화면 5개, 담당자 기록 5종, 메일 질문 목록 내보내기 |
| 복잡도 신호 | 규칙 엔진 11분기, 두 대응 흐름(신규·재접촉), 가상/실제 데이터 구분, 거산 값 묶음 3종 |
| 다중 페르소나 | 영업 담당자, 기술·품질 검수자, 팀 운영자, 대표·상무(읽기) |
| 교차 협업 | 팀 4인(PM·BE·FE·AI)과 거산(검수·확인 메일) |

## 원칙

이 도구는 ERP를 복제하지 않는다. 근거와 다음 행동을 제안하는 판단 지원 도구이며, 담당자의 입력을 줄이고 판단을 빠르게 하는 이야기가 우선한다. [Q1] [참고: 팀 페르소나 v2.0]

## 스토리가 가장 가치를 더하는 영역

1. 추천 목록 → 근거 상세 → 의견 저장의 핵심 흐름(10/30 뼈대)과 11/15 실사용 과제.
2. 접촉 승인 조건(막는 조건·질문 필요·소개서 묶음 승인 불가)과 결과 기록처럼 "담당자가 실수하면 안 되는" 지점.
3. 거산 확인 대기 상태와 메일 질문 목록(거산 확인 병목을 푸는 흐름).
4. 팀 운영자의 가상 사례 파일 투입·수집·평가 실행·거산 값 검수 상태 전환(관리 화면이 없으므로 절차가 곧 사용자 경험).
5. 재접촉 입력(외부 전송 없음)과 신규 흐름의 분리.
