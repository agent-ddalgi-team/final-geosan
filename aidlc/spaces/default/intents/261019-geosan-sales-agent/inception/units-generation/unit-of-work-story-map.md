## 3. 단위 안 구현 순서(권장)

단위 안에서의 순서는 팀 실천 방식(시나리오 테스트 먼저 → 규칙 계산 → API → 화면 → 단위 테스트)을 따릅니다. 단위 사이 순서는 전달 계획이 정합니다.

| 단위 | 안에서의 순서 |
|---|---|
| U1 | S01·S02·S04·S06·S07·S08·읽기 예시 2 시나리오 테스트 → 설정·거산 역량·기회·근거 자료·조사 요건 투입 → RuleEngine → EvaluationLedger ⓪ 흐름(근거 연결 포함) → 검증 명령 → WebApi 목록·상세·의견 → WebUI S1·S2(근거 목록·확인 질문 읽기 전용)·S3 → 한 덩어리 실행 → 화면 시나리오(목록 → 상세 → 의견) |

## 4. 대응 확인

- 이야기 40개가 모두 단위 하나에 대응됐다(US1.1~US10.5, 빠짐·중복 없음).
- 단위 11개 모두 이야기가 1개 이상 있다: U1(11), U2(3), U3(2), U4(4), U5(6), U6(2), U7(4), U8(1), U9(4), U10(2), U11(1) = 40.
- 수용 기준이 여러 단위에 걸치는 이야기는 2장에 적었고, 대표 단위가 수용 기준 전체의 완료 책임을 진다.
