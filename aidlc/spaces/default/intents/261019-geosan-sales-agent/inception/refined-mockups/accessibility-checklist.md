# 접근성 점검표 (Accessibility Checklist) — 거산케미칼 AI 영업지원 에이전트 2차

목표 수준은 WCAG 2.1 AA입니다(러프 화면 Q6, 요구사항 NFR8·FR6.7). 거산의 "누구나 쉽게"를 반영해 큰 글자·쉬운 말·키보드 조작을 기본으로 합니다. 각 항목은 구현·테스트에서 통과/실패를 가를 수 있게 적었습니다.

## 1. 공통 (모든 화면)

## 2. S1 추천 목록

| # | 항목 | 기준 |
|---|---|---|
| S1-1 | 탭 | `Tabs`는 화살표 키로 전환, `role="tablist"`, 선택 탭 `aria-selected` |
| S1-2 | 검색 칸 | `role="search"`, 라벨 "고객명·기회명 검색", 결과 건수 aria-live |
| S1-3 | 카드 | 카드 제목 h2(기업·기회 이름), 분류 태그 `aria-label`, 점수 "점수 81"로 읽힘, 카드 안 Tab 순서: 의견 3개 → 담기 → 자세히 보기 |
| S1-4 | 의견 버튼 | `role="group" aria-label="내 의견"`, 선택 상태 `aria-pressed`, 저장됨 aria-live |
| S1-5 | '대상 아님' 사유 | 펼쳐지면 포커스가 사유 칸으로, Esc로 닫힘, 필수 오류는 글자 |
| S1-6 | 쪽 넘김 | 현재 쪽 `aria-current="page"`, "1~20 / 134건" 글자 |
| S1-7 | 빈·오류 상태 | 설명 글자와 1차 행동 버튼이 포커스 가능 |

## 3. S2 근거 상세

| # | 항목 | 기준 |
|---|---|---|
| S2-1 | 제목 | h1 = 기업·기회 이름, 영역 1~5는 h2 |
| S2-2 | 진행 단계 | `Steps`에 `aria-current="step"`, 각 칸 글자 라벨, 축약 이름은 `title`에 전체 이름, 배지는 글자 |
| S2-3 | 요구 표 | `<table>`에 머리글 행(`th scope="col"`), 판정 태그 글자 포함, 스크롤 영역은 키보드로 이동 가능 |
| S2-4 | 기한 내 대응 체크 | `Checkbox` 라벨 전체 글자, 변경 시 "재평가됨" aria-live, 초기화 안내는 `role="alert"` |
| S2-5 | 확인 질문 펼치기 | `aria-expanded` 반영, 펼침/접힘 글자("나머지 1개 펼치기 / 접기") |
| S2-6 | 거산 확인 요청 인라인 | 펼치면 포커스가 기한 칸으로, Esc로 닫힘, 보내면 "요청됨" aria-live |
| S2-7 | 홈페이지 주소 입력 | 라벨 "홈페이지 주소", 오류는 칸 아래 글자 + `aria-describedby`, 진행 중은 `aria-busy` |
| S2-8 | 점수 자세히 보기 | `Collapse` 머리글이 버튼, `aria-expanded`, 펼침/접힘 글자 |
| S2-9 | 승인·결과 인라인 | 비활성 버튼·비활성 목적 항목의 이유는 옆에 글자로(툴팁만 금지), Radio 그룹 화살표 이동, 확정 후 "승인됨" aria-live, 승인 상태(미정/승인/거절/취소) 글자 표시 |
| S2-12 | 근거 등급·LLM 제안 | "[LLM 제안]" 태그는 글자 포함, 확정되면 사라지고 활동 이력에 남음 |
| S2-10 | 활동 이력 | `<ol>` 또는 Timeline에 각 항목 시각·작성자·내용 글자, "더 보기" 버튼 |
| S2-11 | 띠 | 가상·내부용·거산 확인 전·재평가됨 띠는 `role="status"`, 색만으로 구분하지 않음 |

## 7. 테스트 방법 (팀이 직접 할 수 있는 순서)

1. 자동 검사: 브라우저 확장 axe DevTools 또는 Lighthouse 접근성 점수 90 이상(대비·라벨·랜드마크·제목).
2. 키보드만으로 10/30 시연 5단계(mockups.md 9장)와 흐름 1~6(interaction-spec.md 3장) 수행.
3. 화면 낭독기(macOS VoiceOver 또는 NVDA)로 S1 카드 1개와 S2 요구 표·승인 영역 읽기.
4. 확대 200%, 창 폭 1100px·1000px에서 기능 손실 없는지 확인.
5. 흑백(회색조) 보기에서 상태 구분이 글자로 되는지 확인.
6. 통과 기준: 1~5 모두 통과 + 팀 밖 검증자 1명이 안내 없이 10분 안에 목록→상세→의견 저장(FR6 완료 기준).
