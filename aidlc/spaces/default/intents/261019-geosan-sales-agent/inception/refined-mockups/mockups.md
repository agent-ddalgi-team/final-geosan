# 상세 화면 (Refined Mockups) — 거산케미칼 AI 영업지원 에이전트 2차

러프 화면(`../../ideation/rough-mockups/wireframes.md`, `user-flow.md`)을 사용자 스토리(`../user-stories/stories.md`)와 요구사항(`../requirements-analysis/requirements.md`)에 맞춰 구현 수준으로 다듬은 문서입니다. 부품은 Ant Design 5, 글꼴은 Pretendard, 짧은 입력은 인라인, 재접촉 입력은 별도 페이지, 좁은 화면은 접기·가로 스크롤, 진행 단계는 Steps 가로 바입니다(`refined-mockups-questions.md` Q1~Q6). 색·간격·부품 이름은 `design-system-mapping.md`, 동작 세부는 `interaction-spec.md`, 접근성은 `accessibility-checklist.md`에 있습니다.

그림 속 값은 모두 가상이며 A정밀 사례는 기획서 수치(E 77 / P 95 / S 81.1 / R 82)를, 나머지는 "(예시)" 자리채움을 씁니다. 화면 문구는 쉬운 말 대응표(러프 화면 8장)를 따릅니다.

## 1. 화면 목록과 우선순위

| 번호 | 화면 | 경로(안) | 우선순위 | 이야기 |
|---|---|---|---|---|
| S1 | 추천 목록 (신규 기회 탭 / 재접촉 탭, 검색 칸) | `/opportunities` | P0 (재접촉 탭·검색 P1) | US6.1, US6.5, US7.1, US7.2 |
| S2 | 근거 상세 (신규용 / 재접촉용) | `/opportunities/:id` | P0 (재접촉용·진행 단계·활동 이력·승인·결과 P1) | US6.2, US6.3, US6.6, US6.7, US7.3, US7.4, US4.1 |
| S3 | 의견·담기·승인·결과 영역 (S1·S2 안) | 별도 경로 없음 | 의견 P0, 나머지 P1 | US7.1~US7.4 |
| S4 | 대시보드 (활동 요약 P2 포함) | `/` (11/15부터 첫 화면, 그 전엔 `/opportunities`가 첫 화면) | P1 | US6.4, US9.3 |
| S5 | 재접촉 정보 입력 | `/opportunities/:id/recontact` (새 기회면 `/recontact/new`) | P1 | US7.5 |
| S6 | 질문 목록 (거산 확인 요청·내보내기) | `/questions` | P1 | US9.1, US1.3 |

공통 틀, 좁은 화면 규칙, 다섯 상태(비어 있음·불러오는 중·정상·오류·일부)는 모든 화면에 적용됩니다(공통 규칙은 `interaction-spec.md` 1.1, 화면별 표는 이 문서의 각 장). 메뉴는 대시보드·추천 목록·질문 목록 세 개뿐이며 관리 화면은 없습니다. 거산 접속 환경(P1)에서는 모든 화면 앞에 접속 보호 화면 S0이 한 번 보입니다.

### S0 접속 보호 (P1, 거산 접속 환경에서만)

```
+------------------------------------------+
|  거산 영업지원                            |
|  비밀번호 [            ]  [들어가기]       |
|  (틀리면) 비밀번호가 맞지 않습니다. 다시 입력해 주세요 |
+------------------------------------------+
```

- 공용 비밀번호 1개(FR14.2). 맞으면 세션이 유지되어 다시 묻지 않고, 틀리면 위 문구(글자)와 함께 입력값이 지워진다. 비밀번호 없이 어떤 화면·API도 열리지 않는다. 팀 노트북 환경에서는 설정으로 끈다. 상태: 정상 / 오류(틀림) / 불러오는 중(확인 중 버튼 로딩). [US10.2]

## 2. 공통 틀

```
+----------------------------------------------------------------------------------+
| [로고]  거산 영업지원       대시보드   추천 목록   질문 목록         담당자: [박 이사 v] |
+----------------------------------------------------------------------------------+
| ⓘ 가상 데이터 표시 중 · 내부용 · 고객 제출용 아님          (조건부: 거산 확인 전)       |
+----------------------------------------------------------------------------------+
|  [본문으로 건너뛰기]                                                              |
|  (화면별 본문, 최대 폭 1200px, 좌우 여백 24px)                                     |
+----------------------------------------------------------------------------------+
```

- 위쪽 띠(Layout.Header): 로고 자리(설정에서 교체), 메뉴 3개(대시보드는 11/15 전까지 숨김), 담당자명 선택(Select, 계정 없음; FR14.1). 담당자명을 고르지 않으면 의견·담기·승인·결과 버튼이 비활성이고 "먼저 담당자를 고르세요"가 보인다. 고른 담당자명은 브라우저에 기억되어 새로고침 뒤에도 유지된다.
- 담당자명 목록에는 "보기 전용"이 있다. 출처는 페르소나의 대표·상무 '읽기만 하는 날' 변형(`../user-stories/personas.md` 2장)이며, 계정이 없으므로 보안 기능이 아니라 **실수 방지용**이다: 기록 버튼이 모두 비활성이고 모든 화면(대시보드·추천 목록·질문 목록)을 읽을 수만 있다.
- 알림 띠(Alert, 닫기 없음): "내부용·고객 제출용 아님"은 항상 보이고, 가상 데이터가 섞이면 "가상 데이터 표시 중"이, 평가 묶음이 소개서(검수 대기)이면 "거산 확인 전: 참고 추천이며 접촉 승인은 열리지 않습니다"가 같이 보인다. [FR1.8] [FR4.14] [Q10 stories] **(갱신 제안 2026-10-21, 기능 설계 Q7 답 확정 후 적용)** 앱 설정 `brand.demoLabel`(예: "부분 시연·거산 확인 전")이 있으면 같은 띠에 함께 보인다.
- 본문 최대 폭 1200px, 흰 바탕, 글자 16px, 줄 간격 1.6. 강조색은 버튼·선택 상태·현재 단계에만 쓴다.
- 좁은 화면(Q5): 1024~1279px에서는 카드 요약 줄을 두 줄로 접고 표는 가로 스크롤, 기능은 모두 동작. 1024px 미만에서는 띠 아래에 "넓은 화면에서 써 주세요(1024px 이상)" 안내 띠가 더 보이고 동작은 막지 않는다.
- 다섯 상태는 화면마다 아래에 적었고, 공통 규칙은 `interaction-spec.md` 1.1.

## 3. S1 추천 목록

### 3-1. 신규 기회 탭 (P0, 10/30 첫 화면)

```
+----------------------------------------------------------------------------------+
| 추천 목록                                  [신규 기회 (12) | 재접촉 (3)]            |
| [🔍 고객명·기회명 검색                     ]  갱신: 10/30 09:00  정렬: 추천 순서     |
+----------------------------------------------------------------------------------+
| 1  A정밀 · 밸브 바디 아노다이징                [지금 바로 연락 검토]  81  ●○○○○○    |
|    추천 이유  알루미늄 주물 아노다이징 외주 모집 공고, 마감 3주 뒤 (11/20)            |
|    막는 조건  없음 — 지금 단계 꼭 필요한 요구(ISO 9001) 통과                         |
|    다음 할 일 응모 전 피막 두께 요구 확인                                           |
|    [검토할 만함] [추가 확인] [대상 아님]      [☆ 담기]            [자세히 보기 →]   |
+----------------------------------------------------------------------------------+
| 2  (예시) B정공 · 브라켓 아연도금                [확인 후 연락 검토]  74  ●○○○○○    |
|    추천 이유  홈페이지에 철계 부품 아연도금 외주 언급                                 |
|    막는 조건  인증 요구 미확인 — 질문 필요 (승인은 막지 않음)                        |
|    다음 할 일 고객에게 인증 요구 여부 묻기                                           |
|    의견: 추가 확인 (수정)                     [★ 담김 (빼기)]      [자세히 보기 →]   |
+----------------------------------------------------------------------------------+
| 3  (예시) C산업 · 하우징 크로메이트             [기다리는 중 (확인 필요)]  --         |
|    막는 조건  거래 관계 확인 전 (승인 막힘)                                          |
|    ...                                                                            |
+----------------------------------------------------------------------------------+
|                                     ‹ 1  2  3 ›   20건씩                           |
+----------------------------------------------------------------------------------+
```

- 카드(Card): 1행 순위 번호·기업/기회 이름(크게, 20px 굵게)·분류 태그(쉬운 말, 색+글자)·점수(작게, 회색)·진행 점(P2, 6칸 중 도달 칸만 채움). 2~4행 추천 이유·막는 조건·다음 할 일(각 1줄, 넘치면 "…"과 상세에서 전체). 5행 의견 버튼 3개 + 담기(P1) + 자세히 보기. [FR6.1] [US6.1]
- 막는 조건 줄에는 "(승인 막힘)" 또는 "(승인은 막지 않음)"이 글자로 붙는다. 분류가 "기다리는 중"·"준비 중"이면 점수 자리에 "--"만 보이고 참고 점수는 상세의 "점수 자세히 보기"에서 본다. **(갱신 제안 2026-10-21, 기능 설계 Q5 답 확정 후 적용)** 소개서 묶음(거산 확인 전)으로 평가한 카드는 "--" 대신 "참고 81"처럼 참고 점수를 회색으로 보여 부분 시연에서 순위를 설명할 수 있게 한다.
- 의견 버튼을 누르면 그 자리에서 저장되고 "저장됨 10:12"가 3초 보였다가 "의견: 검토할 만함 (수정)"으로 바뀐다. [대상 아님]은 버튼 아래 사유 칸이 펼쳐진다(인라인, Q3). [US7.1]
- 검색 칸(P1): 고객명·기회명 부분 일치, 입력 후 300ms 지연 검색, 결과 없으면 "검색 결과가 없습니다". 지우면 원래 순위로. [US6.5]
- 정렬은 규칙 엔진 순서 고정(FR4.11). 사용자가 정렬을 바꾸는 조작은 두지 않는다(순서 변경 화면 없음).
- 탭 숫자는 각 탭의 건수. 재접촉 탭(P1)은 3-2.
- **담아 둔 목록(P1)**: 대시보드의 "담아 둔 목록 보기"는 S1을 "담은 것만" 토글(검색 칸 옆 Switch)이 켜진 상태로 연다. 같은 카드 틀이며 [빼기]로 빠진다. 상태: 비어 있음 "담아 둔 기회가 없습니다" / 불러오는 중 / 정상 / 오류(목록과 같음) / 일부(20건씩). 별도 경로는 `/opportunities?bookmarked=1`.

- 요구 표(Table): 판정 열은 태그(색+글자). "질문 필요(승인은 막지 않음)"과 "확인 대기(승인 막힘)"은 다른 색·다른 글자. 통과는 "통과(응모 가능)"처럼 단계를 붙인다. [FR3.4]
- 승인 가능 여부 줄 옆의 체크(시점 우선 요건 3, P0 데이터·P1 화면): 체크하면 평가 입력으로 저장되고 새 평가가 만들어진다(FR4.7). 마감일·필수 요구 판정이 바뀌면 체크가 풀리고 "다시 확인해 주세요" 표시.
- 홈페이지 주소 입력란은 "확인 필요"일 때만 보인다. [확정] 뒤 진행 표시와 "재평가됨" 띠, "이전 평가 보기" 링크. [US4.1]
- 접촉 승인·결과 기록은 P1이며 10/30에는 보이지 않는다. 승인 상태는 미정 / 승인 / 거절 / 취소(FR7.4)이고 버튼은 [승인] [거절]이다. 승인 가능 조건이 안 되면 [승인]이 비활성이고 옆에 "ISO 9001 확인이 끝나야 승인할 수 있습니다"처럼 이유가 글자로 보인다. 평가가 소개서 묶음이면 [승인] 비활성 + "거산 확인 전" 띠. 가상 검수·거산 확인 완료 묶음에서는 조건만 맞으면 승인할 수 있다(A정밀 승인 가능). 목적 네 가지 중 "기존 제안 후속 확인"은 이 기회에 연결된 이력 종류가 견적·제안일 때만 활성이고 아니면 비활성 이유가 글자로 보인다. 재평가로 분류가 바뀌어도 승인은 남고 "이전 승인은 이전 평가 기준(#평가 ID)"이 표시된다. [FR7.4] [FR4.14] [AC7.3.5]
- 결과 상태에 "샘플·등록 승인 받음"이 있어 진행 단계 ⑤(승인 절차)를 채운다. 무응답은 미실행 또는 진행중이지 실주가 아니다. [AC6.6.1] [FR7.5]
- 근거 자료의 확실도·출처 등급이 아직 확정 전이면 "[LLM 제안]" 태그가 붙고, 가상 사례 파일 또는 담당자 확인으로 확정되면 태그가 사라진다. [AC4.1.5]
- 활동 이력(P1, Timeline): 다섯 기록과 접촉 시도·회신을 시각순으로, 작성자·시각·바뀌기 전 값. 의견·승인 항목에는 "(평가 #ID를 보고)"가 붙어 어느 평가를 보고 낸 것인지 보인다. [US6.7] [AC7.1.4]

- 시스템 생성 질문(P0 데이터)과 담당자가 "거산 확인 요청"(S2) 또는 [+ 질문 직접 추가](질문 한 줄·대상 기회·기한)로 추가한 질문이 같은 목록에 있다. 질문마다 대상·현재 값·예/아니요 답 칸·답변 시 바뀌는 것·요청자·상태·기한. [US9.1] [Q8 stories] [AC9.1.4]
- **상태 모델과 주체**: 대기(시스템이 만들었지만 아직 거산에 안 보냄) → 요청(담당자가 [요청으로 보내기]를 누르거나, 복사·내보내기 뒤 "내보낸 '대기' 질문 N건을 요청 상태로 표시할까요?"에 [표시]를 누르면; 요청자·기한(기본값 +7일) 기록) → 회신(거산 답이 메일로 오면 담당자가 [회신 기록]에 답 한 줄과 날짜를 적음) → 반영(운영자가 운영 안내서의 명령으로 값의 검수 상태를 바꾸고 재평가하면 자동 표시). S2의 [거산 확인 요청]은 이미 있는 '대기' 질문을 '요청'으로 바꾸고, 담당자가 [+ 질문 직접 추가]로 새로 쓴 질문은 처음부터 '요청'이다('대기' 없음). 복사·내보내기는 '대기'와 '요청' 질문을 모두 담고, 그 자체로는 상태를 바꾸지 않는다. [AC9.1.1] [AC9.1.4]
- **이 화면은 거산 값을 바꾸지 못한다(읽기 전용 + 상태 기록만)**. [반영] 버튼은 없다. '검수 완료' 반영은 운영 안내서의 명령으로만 하며(US1.3, 관리 화면 없음), 계정이 없는 첫 버전에서 누구나 누를 수 있는 버튼으로 확인 안 된 값이 추천·승인 근거가 되는 것을 막기 위해서다. [Q R-02 결정]

## 11. 후속 확장 후보와 지금 반영할 것 (사용자 수정 요청 2026-10-20)

**후속 확장 후보(이번 범위 밖, 기록만)**: 거산이 허가하면 팀이 거산 홈페이지를 만들고, 홈페이지에 '직원 전용' 입구를 두어 이 영업 도구로 들어가게 한다. 홈페이지는 공개, 영업 도구는 비밀번호로 보호된 별도 공간으로 분리한다(내부 점수·추정·거래처 정보 유출 방지). 연결 아이디어: 거산 확인 완료된 공정·인증 정보를 홈페이지 공정 소개에도 쓰고, 홈페이지 문의는 이 도구의 새 영업기회로 들어오게 할 수 있다(인바운드 문의라 연락 동의 문제가 적다). 이 후보는 범위에 넣지 않으며 우선순위도 매기지 않는다. 거산 허가와 G0 합의 뒤에 범위 변경으로 다룬다.

**지금 반영할 것(화면 설계는 바꾸지 않음)**:
- 영업 도구는 **독립된 웹 주소**로 동작한다. 홈페이지가 생겨도 영업 도구는 그 안에 끼워 넣지 않고 별도 주소·별도 접속 보호(S0)를 유지한다. 화면·경로(`/opportunities` 등)는 그대로다.
- 디자인 테마(강조색·글꼴·둥글기)는 `design-system-mapping.md` 1장의 토큰 한 곳(`src/theme/tokens.ts`, `src/config/brand.ts`)에서만 관리해, 나중에 홈페이지와 같은 테마를 공유할 수 있게 한다. 화면 코드에 색·글꼴 값을 직접 적지 않는다.
- **인프라 설계·G0로 넘기는 메모**: 배포 방식을 정할 때 홈페이지를 나중에 같은 곳에 올릴 수 있는지(같은 호스팅에서 공개 사이트와 비밀번호 보호 공간을 나눌 수 있는지)도 함께 검토한다. 이 단계에서는 서비스명을 정하지 않는다.
