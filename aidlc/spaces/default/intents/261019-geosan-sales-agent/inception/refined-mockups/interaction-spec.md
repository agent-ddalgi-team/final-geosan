# 상호작용 명세 (Interaction Spec) — 거산케미칼 AI 영업지원 에이전트 2차

`mockups.md`의 화면이 "어떻게 움직이는지"를 부품 단위로 적은 문서입니다. 형식은 부품 명세 템플릿(이름·상태·입력값·좁은 화면·접근성)을 따르고, 부품 이름은 Ant Design 5(`design-system-mapping.md`)를 씁니다. 모든 입력은 인라인이며 모달을 쓰지 않습니다(`refined-mockups-questions.md` Q3). 수용 기준은 사용자 스토리(`../user-stories/stories.md`)의 AC 번호로 연결했습니다.

## 1. 공통 규칙

| 규칙 | 내용 | 근거 |
|---|---|---|
| 저장 피드백 | 저장 성공 시 버튼 옆에 "저장됨 HH:MM"(aria-live="polite") 3초 → 영구 상태 문구("의견: 검토할 만함 (수정)")로 교체. 실패 시 "저장하지 못했습니다. 다시 시도" + 입력값 유지 | AC7.1.1, AC7.1.3 |
| 담당자명 미선택 | 상단 담당자명이 비어 있으면 모든 기록 버튼 비활성 + 버튼 옆에 글자 "먼저 담당자를 고르세요"(툴팁만 쓰지 않음). 보기 전용(대표·상무)도 같고 모든 화면을 읽을 수만 있음 | FR14.1, personas |
| 동시 수정 | 저장 요청에 "내가 본 값의 버전"을 보내고, 서버가 더 새 값을 가지면 저장은 되되 응답에 이전 값이 와서 "다른 담당자가 방금 바꿨습니다 (이전: …)" 알림(Alert, 닫기 가능) | FR7.6 |
| 오류 문구 | 오류 코드를 보이지 않고 쉬운 말 + 다음 행동. 모든 외부 호출은 타임아웃(목록 10초, 근거 추출 60초) | NFR10, NFR2 |
| 진행 표시 | 1초 넘는 작업은 Spin 또는 Skeleton, 5초 넘으면 "조금 오래 걸리고 있습니다", 60초 넘으면 실패 처리 | NFR2 |
| 확인(confirm) | 되돌릴 수 없는 동작은 '대상 아님'·'실주'의 사유 필수와 승인 '취소'뿐. 그 밖에는 확인창 없이 저장 후 수정 가능. **유일한 모달 예외**: 재접촉 입력(S5)에 입력한 내용이 있을 때 이탈하면 브라우저 기본 확인창을 쓴다. 보호 범위 두 가지: 탭 닫기·새로고침·주소 직접 이동은 `beforeunload`, 화면 안 이동(메뉴 클릭, [취소], "‹ 재접촉 목록으로")은 라우터에서 이동을 막고 `window.confirm("입력한 내용이 사라집니다. 나갈까요?")`를 띄운다. 둘 다 Ant Design Modal이 아닌 브라우저 대화상자이며 키보드로 머무르기/나가기를 고를 수 있다. 저장 뒤에는 뜨지 않는다 | ux-guide 오류 예방, Q3 예외 |
| 동시 수정 표현(통일) | 내 저장은 되고, 서버가 더 새 값을 갖고 있었으면 "다른 담당자가 방금 바꿨습니다 (이전: …)" 알림과 최신 값이 보이며 내 입력 칸의 글은 지워지지 않는다 | FR7.6 |
| 쉬운 말 | 화면 문구는 대응표(러프 화면 8장)만 쓴다. 전문 용어(E/P/S/R, 필터, 프로필)는 "점수 자세히 보기" 안에서만 | Q8 rough-mockups |
| 키보드 | 모든 부품 Tab 순서는 시각 순서, Enter/Space 활성, Esc는 펼친 인라인 입력 닫기 | accessibility-checklist |
| 좁은 화면 | 1024~1279px: 카드 요약 2줄, 표 가로 스크롤, Steps small. <1024px: 안내 띠만, 동작 유지. 브라우저 확대(zoom)로 폭이 줄어든 경우에는 안내 띠를 띄우지 않는다(기기 폭 기준) | Q5 |
| 담당자명 | 상단 Select 값은 브라우저 localStorage에 기억. "보기 전용"은 기록 버튼 비활성(실수 방지용, 보안 아님) | FR14.1, personas |

### 1.1 공통 다섯 상태 규칙 (모든 화면·영역)

| 상태 | 공통 규칙 |
|---|---|
| 비어 있음 | `Empty` + 왜 비었는지 한 줄 + 다음 행동 버튼(있으면). 빈 표·빈 목록을 설명 없이 보이지 않는다 |
| 불러오는 중 | 1초 넘으면 Skeleton(목록·표) 또는 Spin(동작). 5초 넘으면 "조금 오래 걸리고 있습니다". 버튼은 로딩 상태로 중복 클릭 방지 |
| 정상 | 그림대로 |
| 오류 | `Alert type=error` + 쉬운 말 원인 + [다시 시도]. 오류 코드 비노출, 로그에 기록. 입력값은 유지 |
| 일부 | 0건 / 1건 / 20건 초과(쪽 나눔) / 긴 글(자르기 + 전체 보기) / 일부 소스 실패(불러온 것과 실패한 것 구분) |

## 2. 부품 명세

### 2.1 추천 카드 (OpportunityCard)

| 항목 | 값 |
|---|---|
| 부품 | Card + Tag + Button 그룹 |
| 설명 | 추천 목록의 한 줄. 기업·기회, 분류, 점수, 추천 이유·막는 조건·다음 할 일, 의견·담기·자세히 보기 |
| 분류 | 표시 + 입력 |

상태: default / hover(테두리 강조) / focus-within(2px 윤곽) / 의견 저장 중(버튼 로딩) / 의견 저장됨 / 담김 / 기다리는 중·준비 중(점수 "--", 승인 막힘 표기) / 소개서 묶음("거산 확인 전" 작은 태그).

입력값: `opportunityId`, `rank`, `title`, `classificationCode`(11분기 코드 → 쉬운 말), `scoreS`(null 허용), `reason`, `blocker`(text + blocksApproval:boolean), `nextAction`, `opinion`(null | 검토할 만함 | 추가 확인 | 대상 아님), `bookmarked`, `stage`(1~6, P2), `isVirtual`, `datasetKind`(가상 검수 | 소개서 | 거산 확인 완료), `isRecontact`.

좁은 화면: 1024~1279에서 추천 이유·막는 조건·다음 할 일을 2줄로 접고 버튼은 줄바꿈. <1024 동일.

접근성: 카드 제목 h2, 분류 태그는 `aria-label="분류: 지금 바로 연락 검토"`, 점수는 "점수 81"로 읽힘, 버튼 그룹은 `role="group" aria-label="내 의견"`, 저장됨은 aria-live. [AC6.1.5]

### 2.2 의견 버튼 그룹 (OpinionButtons)

상태: 미선택 / 선택됨(해당 버튼 primary) / '대상 아님' 사유 펼침(TextArea 1줄 + [저장] [취소]) / 저장 중 / 저장됨 / 오류.

동작: 버튼 하나를 누르면 즉시 저장(검토할 만함·추가 확인). '대상 아님'은 사유 칸이 펼쳐지고 사유 없으면 [저장] 비활성 + "사유를 적어 주세요". 저장 후 "의견: 대상 아님 (수정)". (수정)을 누르면 세 버튼이 다시 보인다. 의견은 본 평가 ID와 함께 저장된다. [AC7.1.1~7.1.4]

접근성: 세 버튼은 토글 그룹(`aria-pressed`), 사유 TextArea에 `aria-required`, 오류는 `aria-describedby`.

### 2.3 담기 토글 (BookmarkToggle, P1)

상태: 담기 전(☆ 담기) / 담김(★ 담김 (빼기)) / 저장 중. 의견과 독립. 담기는 진행 단계에 영향 없음. [AC7.2.1~7.2.3, AC6.6.3]

### 2.4 검색 칸 (OpportunitySearch, P1)

Input.Search, placeholder "고객명·기회명 검색". 300ms 디바운스, 부분 일치, 두 탭 공통. 결과 없음: Empty "검색 결과가 없습니다". 지우기(✕)로 원래 순위. 결과 응답 1초 이내. [AC6.5.1~6.5.3]

접근성: `role="search"`, 라벨 "고객명·기회명 검색", 결과 건수 aria-live("3건 찾음").

### 2.5 진행 단계 (ProgressSteps, P1)

Steps(가로, `size` 기본, 1280 미만 `small`). 6칸 ① 추천·확인 중 → ② 연락 승인 → ③ 연락 시도 → ④ 상담 진행 → ⑤ 승인 절차 → ⑥ 거래 성사. 현재 칸 `process`(강조색), 지난 칸 `finish`, 남은 칸 `wait`. 보류·실주·대상 아님은 오른쪽 Tag(각각 회색·빨강·회색). 계산 규칙은 서버가 기존 기록에서 도출(새 상태 저장 없음): 접촉 승인 '승인'이면 ②, 접촉 시도 기록이 있으면 ③, 회신 '있음' 또는 결과 '진행중'이면 ④, 결과 상태 "샘플·등록 승인 받음"이면 ⑤, 결과 '수주'면 ⑥. 무응답은 ③ 유지. 배지: 결과 '보류' → "보류", 결과 '실주' → "실주", 의견 '대상 아님' → "대상 아님", 접촉 승인 '거절' → "거절". [AC6.6.1~6.6.4] [Q R-10 결정]

접근성: Steps는 `aria-current="step"`과 각 칸 글자 라벨, 축약 이름일 때 `title`에 전체 이름.

### 2.6 요구 판정 표 (RequirementTable)

Table(머리글 행 고정, 10행 넘으면 세로 스크롤 320px). 열: 요구 / 꼭 필요한가 / 언제 필요 / 거산 상태 / 판정. 판정 태그: 통과(응모 가능)=초록, 나중 단계=회색, 질문 필요(승인은 막지 않음)=파랑, 확인 대기(승인 막힘)=노랑, 제외=빨강 — 모두 글자 포함. 아래 "승인 가능 여부" 한 줄 + 시점 우선 요건 3 체크박스. [AC5.2.1~5.2.3, AC6.2.1]

체크박스(DeadlineReadyCheck, P0 데이터·P1 화면): 라벨 "기한(11/20) 안에 대응할 수 있음 (담당자 확인)". 체크/해제 시 즉시 저장 → 새 평가 생성 → 분류 태그·순위 갱신 + "재평가됨" 띠. 마감일·필수 요구 판정이 바뀌면 서버가 체크를 초기화하고 체크박스 옆에 "조건이 바뀌어 다시 확인해 주세요"(경고). [AC7.3.4, AC5.3.1]

### 2.7 확인 질문 목록 + 거산 확인 요청 (QuestionList, ConfirmRequestInline)

List 3개 표시 + "나머지 N개 펼치기"(Collapse). 각 줄 끝 [거산 확인 요청] 버튼(P1): 누르면 그 줄 아래 인라인 폼(기한 DatePicker 기본값 +7일, 메모 1줄) + [보내기] [취소]. 보내면 질문 목록(S6)의 그 질문이 상태 '대기' → '요청'으로 바뀌고 요청자·기한이 기록되며 버튼이 "요청됨 (11/09 기한)"으로 바뀐다. 목록 맨 아래 [+ 질문 직접 추가]를 누르면 질문 한 줄(Input, 1~200자)·기한(기본값 +7일) 입력 인라인 폼이 펼쳐지고 [보내기]로 상태 '요청'인 자유 질문이 이 기회에 연결되어 추가된다(S6의 [+ 질문 직접 추가]와 같은 동작: 직접 추가한 질문의 첫 상태는 언제나 '요청'). 이미 요청된 질문은 중복 요청 불가. [AC6.2.6, AC9.1.4]

### 2.8 홈페이지 주소 입력 (HomepageConfirm)

"확인 필요"일 때만 보임. Input(url) + [확정]. 확정 → Spin "근거를 찾는 중입니다 (최대 1분)" → 성공: 근거 자료 목록 갱신 + "재평가됨" 띠 + "이전 평가 보기" 링크. 실패: 인라인 오류 문구 2종(열 수 없음 / 자동 읽기 불가 + 본문 붙여넣기 TextArea 표시). URL 형식 오류는 blur 시 "주소 형식을 확인해 주세요". [AC4.1.1, AC4.1.2, AC4.1.6]

### 2.9 점수 자세히 보기 (ScoreDetails)

Collapse 한 패널, 기본 접힘. 머리글 "점수 자세히 보기". 펼치면 E/P/S/R 4개 Statistic + 항목별 표(항목, 배점, 일치도, 확실도, 감쇠, 점수, 상태) + 규칙 버전·거산 값 묶음·평가 시각. 미확보 항목은 점수 칸 "--"와 "미확보". `aria-expanded` 반영, 펼침/접힘 글자 표시. [AC6.2.2]

### 2.10 접촉 승인 인라인 (ApprovalInline, P1)

상태 표시 "접촉 승인 상태: 미정 / 승인 / 거절 / 취소"(FR7.4) + [승인] [거절] 버튼. 승인 가능 조건(지금 단계 필수 요구 모두 통과 + 관계·중복 확인 완료 + 평가 묶음이 '소개서'가 아님) 미충족이면 [승인] 비활성 + 옆에 이유 글자(툴팁만 쓰지 않음). 소개서 묶음이면 비활성 + "거산 확인 전". 가상 검수·거산 확인 완료 묶음은 조건만 맞으면 승인 가능(A정밀 승인 가능). [승인]을 누르면 아래에 Radio 그룹 네 가지(요구 확인 / 검수된 역량 소개 / 기존 제안 후속 확인 / 일정 응답; 기본값은 질문 필요가 남아 있으면 "요구 확인")와 [확정] [취소]. "기존 제안 후속 확인"은 이 기회에 연결된 이력 종류가 견적·제안일 때만 활성이고 아니면 비활성 + 옆에 "이 기회에 제안·견적 이력 없음" 글자. 확정 → "승인됨 · 박 이사 · 11/16 10:20" + [취소하기](사유 필수, 상태 '취소'). [거절]은 사유 선택(요구 확인 중 / 여력 없음 / 기타) 후 상태 '거절'. 재평가로 분류가 바뀌면 기존 승인 줄에 "이전 승인은 이전 평가 기준(#평가 ID)"이 붙는다. [AC7.3.1~7.3.5, AC3.2.3] [Q R-09·R-10 결정]

### 2.11 결과 기록 인라인 (OutcomeInline, P1)

Select 상태(미실행|진행중|샘플·등록 승인 받음|보류|수주|실주) → Radio 회신(있음|없음) → DatePicker 다음 일정 → Input 메모 1줄 → [저장]. "샘플·등록 승인 받음"은 진행 단계 ⑤를 만든다(요구사항 FR7.5 갱신 필요). 세 번 선택 + 메모 1줄이 기본 경로. '실주' 선택 시 사유 Input이 펼쳐지고 필수. 안내 문구 "무응답은 미실행 또는 진행중이며 실주가 아닙니다"는 항상 보임. 저장하면 접촉 건(ACTION)에 시도·회신 행이 추가되고 활동 이력에 반영. [AC7.4.1~7.4.5]

### 2.12 활동 이력 (ActivityTimeline, P1)

Timeline 세로, 최신이 위. 항목: 시각 · 작성자 · 종류(분류/의견/담기/승인/접촉 시도/회신/결과) · 내용 · (바뀌기 전 값). 분류 항목은 평가 ID·규칙 버전 포함. 의견·승인 항목은 "(평가 #ID를 보고)"를 붙여 어느 평가를 보고 낸 것인지 보인다(AC7.1.4). 20건 넘으면 "더 보기". 비어 있으면 "아직 기록이 없습니다". [AC6.7.1~6.7.3]

### 2.13 대시보드 건수 버튼 (CountTile, P1)

Card 안 Statistic + 화살표. `role="link"`, 읽힘 "확인할 기회 3건, 열기". 누르면 조건 필터가 적용된 S1 또는 S6. 0건이면 회색. [AC6.4.1, AC6.4.2]

### 2.14 일정 목록 (ScheduleList, P1)

List: 기한 지남(⚠, 빨강 글자+아이콘) → 오늘 → 이번 주. 항목 클릭 → S2 결과 기록 영역으로 스크롤·포커스. 처리 전까지 기한 지남 유지. [AC6.4.3]

### 2.15 재접촉 입력 폼 (RecontactForm, P1)

Form(라벨 위, 7개 Form.Item + 이력 종류 Radio + 각 확인/추정 Radio + 확인일 DatePicker, 7번 줄에도 확인일). 필수 검증은 blur와 제출 시, 오류는 칸 아래 글자. [저장하고 평가]는 항상 활성이며 누르면 검증하고, 오류가 있으면 저장하지 않고 첫 오류 칸으로 포커스 이동 + 상단 오류 요약(`role="alert"`). 통과 → Spin → 재접촉 탭으로 이동 + 새 카드 강조(2초). 입력 중 이탈 시 브라우저 기본 확인창(탭 닫기·새로고침은 `beforeunload`, 화면 안 이동은 라우터 차단 + `window.confirm`; 유일한 모달 예외, 1장 참고). 이력 없음 판단 시 Alert 안내 + 신규 탭 링크. 금액·단가·도면·연락처 칸 없음. [AC7.5.1~7.5.5]

### 2.16 알림 띠 (StatusBanner)

Alert(닫기 없음, `role="status"`). 종류: 내부용(항상, 회색), 가상 데이터(가상 행 포함 시, 노랑), 거산 확인 전(소개서 묶음, 파랑), 좁은 화면 안내(<1024px, 회색), 재평가됨(해당 상세에서 10초, 초록). 여러 개면 한 줄에 점으로 이어 표시. [AC10.1.1~10.1.3, AC10.3.1] (갱신 제안 2026-10-21, Q7 확정 후) 앱 설정 `brand.demoLabel` 문구(예: "부분 시연·거산 확인 전")가 있으면 같은 줄에 함께 표시. 카드 점수는 소개서 묶음에서 "참고 81"(Q5 확정 후).

### 2.17 질문 목록 (QuestionBoard, P1)

Table/List 필터(전체|대기|요청|회신|반영) + 기한 지남 우선 정렬. 행: 질문, 대상, 현재 값, 예/아니요 답 칸(읽기 전용 표시), 답하면 바뀌는 것, 요청자·기한·상태 Tag. 상태 전이와 주체: 대기(시스템이 만든 질문만; 담당자가 직접 쓴 질문은 처음부터 '요청') → 요청([요청으로 보내기] 또는 복사·내보내기 시 담당자, 요청자·기한 기록) → 회신(담당자가 [회신 기록] 인라인에 거산 답 한 줄과 날짜를 적음) → 반영(운영자가 운영 안내서의 명령으로 검수 상태를 바꾸면 서버가 자동 표시). **이 화면에는 검수 상태를 바꾸는 버튼이 없다(읽기 전용 + 상태 기록만)**; 거산 값 변경은 명령으로만 한다(US1.3). [+ 질문 직접 추가]는 질문 한 줄·대상 기회·기한(기본값 +7일) 인라인 폼이며 [보내기] 즉시 상태 '요청'(직접 추가한 질문에 '대기'는 없음). [질문 목록 복사] → 클립보드(번호·질문·예/아니요·대상 순 텍스트, 대기·요청 상태 모두 포함) + "복사됨" aria-live. [파일로 내보내기] → .txt 다운로드. 복사·내보내기 자체는 상태를 바꾸지 않는다. 대신 복사·내보내기 직후 버튼 아래에 "내보낸 '대기' 질문 N건을 요청 상태로 표시할까요? 기한 [+7일]" 한 줄과 [표시] [아니요]가 펼쳐지고, [표시]를 누르면 그 N건이 요청자·기한과 함께 '요청'으로 바뀐다. [AC9.1.1~9.1.5, AC1.3.2, AC1.3.5] [Q R-02·R-03 결정]

## 3. 흐름별 상태 전이

### 3.1 흐름 1: 추천 확인 → 의견 (P0)

```
S1 정상 → [검토할 만함] → 카드 저장 중(버튼 로딩) → 저장됨(3초) → "의견: 검토할 만함 (수정)"
                                             └ 실패 → "저장하지 못했습니다. 다시 시도"(입력 유지)
S1 → [자세히 보기] → S2 불러오는 중(Skeleton) → S2 정상 → [목록으로] → S1(스크롤 위치·의견 반영)
```

### 3.2 흐름 2: 승인·결과 (P1)

```
S2 → 승인 가능 여부 확인 → [승인](활성 조건: 필수 요구 모두 통과 + 관계·중복 확인 + 평가 묶음이 '소개서'가 아님)
   → 목적 펼침(4개, 해당 없는 것은 비활성+이유) → [확정] → "승인됨" + 진행 단계 ② → (연락 뒤) 결과 기록 3선택+메모 → 저장 → 진행 단계 ③/④/⑤(샘플·등록 승인 받음)/⑥(수주) → 일정이 대시보드에
   [거절] → 사유 선택 → 상태 '거절' + 배지
   비활성 사유: "ISO 9001 확인이 끝나야 승인할 수 있습니다" / "거산 확인 전" / "먼저 담당자를 고르세요"
```

### 3.3 흐름 3: 홈페이지 확정 → 재평가 (P0)

```
S2 근거 자료 "확인 필요" → 주소 입력 → [확정] → Spin(최대 60초) → 성공: 근거 추가 + "재평가됨" + 순위 갱신
                                                          → 자동 읽기 불가: 안내 + 본문 붙여넣기 칸 → [붙여넣고 찾기]
                                                          → 열 수 없음: "주소를 열 수 없습니다. 다시 확인해 주세요"
```

### 3.4 흐름 4: 재접촉 입력 (P1)

```
S1 재접촉 탭 → [+ 재접촉 정보 입력] → S5 → 7칸 입력(검증) → [저장하고 평가] → Spin → S1 재접촉 탭(새 카드 강조)
                                            └ 이력 없음 판단 → Alert "신규 기회로 평가됩니다" + 신규 탭 링크
```

### 3.5 흐름 5: 거산 확인 요청 → 반영 (P1)

```
S2 확인 질문 [거산 확인 요청](이미 있는 '대기' 질문 → '요청') 또는 S2·S6 [+ 질문 직접 추가](새로 쓴 질문은 처음부터 '요청') → 기한 입력 → [보내기] → S6 상태 '요청' → (메일 답) → 담당자 [회신 기록] → 상태 '회신' → 운영자가 안내서 명령으로 검수 상태 변경·재평가 → 상태 '반영'(자동), S2 "재평가됨"
```

### 3.6 흐름 6: 대시보드 (P1)

```
접속 → S4(건수 4, 일정, 담아 둔 목록 링크, 업무 흐름, 최근 내가 한 일, 활동 요약 P2)
     → 건수 클릭 → 필터된 S1 또는 S6   → 일정 클릭 → S2 결과 기록 영역   → 담아 둔 목록 보기 → 목록([열기][빼기])
```

## 4. 입력 검증 요약

| 입력 | 규칙 | 오류 문구 |
|---|---|---|
| '대상 아님' 사유 | 1~200자 필수 | 사유를 적어 주세요 |
| '실주' 사유 | 1~200자 필수 | 실주 사유를 적어 주세요 |

| 메모 | 0~200자 | 200자까지 적을 수 있습니다 |

### 2.18 접속 보호 (PasswordGate, P1, 거산 접속 환경에서만)

단일 비밀번호 Input.Password + [들어가기]. 틀리면 `role="alert"` "비밀번호가 맞지 않습니다. 다시 입력해 주세요"와 입력값 초기화, 5회 연속 실패 시 30초 대기 안내. 맞으면 세션 쿠키로 유지(브라우저 닫기 전까지). 팀 노트북 환경은 설정으로 끈다. [AC10.2.2]

### 2.19 근거 등급 표시 (EvidenceGradeTag)

근거 자료 줄의 확실도(사실/추정)·출처 등급(A~D) 태그 옆에, 가상 사례 파일이나 담당자 확인으로 확정되기 전이면 "[LLM 제안]" 태그(회색)가 붙는다. 확정되면 사라지고 활동 이력에 "근거 등급 확정" 항목이 남는다. [AC4.1.5]

## 5. 화면 밖 동작(참고)

- 평가 실행·수집·검수 상태 전환('검수 완료' 반영)은 운영자가 운영 안내서의 명령으로 한다(관리 화면 없음, US1.1·US1.3·US2.1·US5.1). 화면은 결과와 질문 상태만 보인다.
- 엑셀·PDF(P2)는 S1·S6 상단 버튼으로 두되 이번 명세에는 포함하지 않는다(US9.2).
