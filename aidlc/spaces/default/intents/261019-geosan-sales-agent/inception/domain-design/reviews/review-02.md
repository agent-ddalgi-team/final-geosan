### Summary
수정본의 부품 15개는 YAML 기준으로 depends_on과 dependents가 서로 맞고(대칭), 순환 호출이 없으며, 모든 엔티티의 주인 부품이 하나입니다. 첫 리뷰의 소견 12개 중 11개는 해결됐고, R-11만 ADR-003의 보안 영향 문장이 빠져 남았습니다(Low). 수정으로 새로 생긴 문제는 Medium 1건과 Low 6건입니다. Medium은 뼈대의 핵심 경로인 "평가 실행" 명령이 촉발 흐름 6개 표에 없다는 점이고, 표에 한 줄 보태는 정도로 고칠 수 있습니다. Critical은 없고 Major도 없어서 승인을 막지는 않습니다.

> R-01 Reviewer note: CapabilityCatalog는 바뀐 값의 ID와 새 검수 상태만 돌려주고, 영향 기회는 EvaluationLedger가 찾는다. CapabilityCatalog는 OpportunityRegistry·EvaluationLedger를 읽지 않아 순환이 없다. 다만 processId·capabilityId로 찾는 데이터 경로가 약하다(새 소견 2).

> R-02 Reviewer note: TransferGuard 입력 계약이 자료 종류 태그 7종 + 보안 등급, 금지 종류 하나라도 있으면 묶음 전체 거부, 태그·등급 없으면 기본 거부로 components.md와 ADR-004에 모두 쓰였다.

> R-03 Reviewer note: 철회 자료와 처리 금지 원문의 스냅샷 비노출 주인이 EvaluationLedger로 정해졌다. TransferGuard 쪽 문장도 맞춰졌다. 다른 읽기 경로는 새 소견 6에 적었다.

> R-04 Reviewer note: WorkflowRunner가 15번째 부품이 됐다. 촉발 경로 6개 표와 한 흐름 = 한 트랜잭션, 외부 호출은 트랜잭션 밖이라는 규칙이 있다. 5개 부품과의 의존이 양쪽에서 맞는다. 표에 빠진 경로는 새 소견 1에 적었다.

> R-05 Reviewer note: DashboardReporting이 CapabilityCatalog와 EvidenceExtraction 의존을 선언했고, 두 부품의 dependents에도 반영됐다.

> R-06 Reviewer note: QuestionOpportunityLink가 생겼다. 질문은 대상(targetKind + targetId)당 하나이고, 기회 영향은 연결 행으로 나눴다. 기한 지남 건수는 기회별로 연결 기준으로 센다. 부품 요약 표와 엔티티 표에도 반영됐다.

> R-07 Reviewer note: ADR-010이 생겼다. ReadinessCheck와 RankAdjustment를 EvaluationLedger가 소유하고, 순위 조정은 이력 행으로만 남긴다. 프로필 변경 사유와 이전 평가 ID, 프로필별 묶음 규칙도 있다.

> R-08 Reviewer note: ADR-011이 생겼다. 교차 부품 참조는 ID만 저장하고 외래 키를 걸지 않으며, 같은 부품 안은 외래 키를 건다. 서버 검사 항목으로 표시하고 테스트로 보장한다. 검사 담당 배정이 일부 빠진 점은 새 소견 5에 적었다.

> R-09 Reviewer note: ADR-007에 sourceEvalId와 최신 확정 평가 ID를 읽을 때 비교하는 완화책이 들어갔다. 비교하는 부품이 지정되지 않은 점은 새 소견 3에 적었다.

> R-10 Reviewer note: 뼈대 문단에 "ConfirmationDesk는 질문 후보 저장만 하는 최소형"이라고 적혔다.

> R-11 Reviewer note: ADR-009~011에는 보안 영향 문장이 있다. ADR-003(확인·조사 창구, 거산 값 읽기 전용)에는 "보안 영향" 줄이 아직 없다. ADR-003은 거산 값 변경 경로를 막는 결정이라 보안 영향을 명시해야 한다.

> R-12 Reviewer note: JudgmentEvidence의 식별자는 judgmentEvidenceId이고 (judgmentId, evidenceId) 쌍이 유일하다고 적혔다. NFR6 비용은 TransferGuard가 호출 수·토큰을 집계하고 OperatorCommands가 환산하는 것으로 정리됐다.

### Suggestions

- ADR-003에 "보안 영향: 거산 값 쓰기 함수가 CapabilityCatalog에만 있고 OperatorCommands에서만 호출되므로 화면에서 거산 값을 바꾸는 경로가 호출 그래프에 없다" 한 줄을 넣으면 R-11이 닫힙니다.
- Part B 흐름 표에 "외부 호출 단계"와 "트랜잭션 단계"를 열로 나누면 비전공 팀이 경계를 읽기 쉽습니다.
- 소견 5의 서버 검사 담당 표는 다음 단계(기능 설계)의 데이터 사전에 그대로 옮길 수 있게 두면 좋습니다.
