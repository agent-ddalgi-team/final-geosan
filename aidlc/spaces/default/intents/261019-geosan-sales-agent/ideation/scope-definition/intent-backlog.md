# 우선순위 백로그 (Intent Backlog) — 거산케미칼 AI 영업지원 에이전트 2차

범위 문서(`scope-document.md`)의 P0~P3을 "만들 수 있는 덩어리"(proto-Unit)로 나눈 목록입니다. 의도 문서(`../intent-capture/intent-statement.md`)의 성공 기준, 실현 가능성 평가서(`../feasibility/feasibility-assessment.md`)의 일정 판정, 제약 목록(`../feasibility/constraint-register.md`)의 제약을 반영했습니다. MoSCoW는 Must(반드시) / Should(가능한 한) / Could(여유 시) / Won't(이번엔 안 함)이며, 실제 작업 단위 분할은 뒤 단계(작업 단위 나누기)에서 다시 정합니다.

## 1. 가치 흐름 (Value Stream)

거산 영업 담당자가 얻는 가치는 "어떤 기회를 왜 검토하고, 연락 전에 무엇을 확인할지"입니다. 이 가치가 만들어지는 순서와 각 단계를 담당하는 백로그 항목입니다.

```
[후보 찾기] -> [기회 정리] -> [근거 확보] -> [평가·분류] -> [추천 확인] -> [의견·승인·결과 기록] -> [재평가]
   B-07         B-02          B-04          B-03           B-05          B-09, B-05           B-03
   B-14(P3)                   B-11(P1)                     B-10(시연)
```

"뼈대"(Q6)는 이 흐름을 가상 사례 1건으로 끝까지 한 번 통과시키는 것이며, B-06이 그 통합 항목입니다.

## 3. 우선순위 근거

- Must(P0)는 의도 문서의 성공 기준 "10/30 초기 동작"과 "신규 기회 흐름 끝까지"를 직접 만드는 항목입니다. 하나라도 빠지면 거산에 보여줄 것이 없습니다.
- Should(P1)는 "11/15 기능 완료·실사용 전달"에 필요한 항목입니다. 재접촉 흐름은 기획서 필수 범위이지만 실데이터가 없어 가상 사례로 기본 동작만 보증합니다.
- Could(P2·P3)는 11/27 통합 인수와 발표 완성도를 높이는 항목입니다. 지연 시 범위 문서 6장 순서로 줄입니다.
- 순서는 "뼈대 먼저"(Q6)이므로 B-06이 B-01~B-05의 얇은 버전을 먼저 묶고, 그 뒤 각 항목을 두껍게 합니다.
