# 실현 가능성 평가서 (Feasibility Assessment) — 거산케미칼 AI 영업지원 에이전트 2차

이 문서는 의도 문서(`../intent-capture/intent-statement.md`)가 정한 문제·성공 기준·제외 범위를 바탕으로, "11/15까지 기획서 2.2 필수 8항목 전부"라는 기준선이 지금의 팀·자료·예산 조건에서 실현 가능한지를 보수적으로 판단한 것입니다. 근거는 `feasibility-questions.md`의 확인된 답변(Q1~Q10)과 사용자가 제공한 데이터 소스 리서치 문서입니다. 확인되지 않은 추정은 "가설"로 표시했습니다.

## 1. 한 줄 판정

**조건부 실현 가능.** 기능 자체는 모두 만들 수 있지만, 4인 비전공 팀이 AI 도구에 의존해 약 4주 안에 필수 8항목 전부를 끝내는 것은 위험이 높습니다. 신규 기회 흐름을 끝까지 돌리고 재접촉 흐름은 가상 사례로 기본 동작만 확인하는 수준이라면 11/15 안에 가능성이 높다고 봅니다(가설). 어디까지를 "완성"으로 볼지는 다음 단계(범위 정의)에서 P0~P3 우선순위로 확정해야 합니다.

## 2. 의도 문서와의 연결

| 의도 문서 항목 | 이 평가에서 다루는 질문 |
|---|---|
| 문제 정의: 역량·인증 근거 구조화 + 영업 판단 지원 | 근거가 될 실제 거산 자료가 있는가 (3장 "자료") |
| 성공 기준: 10/30 초기 동작 → 기업 접촉 → 11/15 기능 완료·실사용 전달 → 12월 초 후기 | 일정과 작업량이 맞는가 (4장), 기업이 접속할 방법이 있는가 (5장) |
| 11/15 기준선: 기획서 2.2 필수 8항목 전부 | 항목별 난이도와 위험 (3장) |
| 제외 범위: 단가·견적, 납기 확정, 자동 발송, 가격·경쟁사 비교 | 제약 목록에 반영 (`constraint-register.md`) |
| 가정: 미정 항목은 범위 밖, 숫자 목표 없음, G0 확인자 미정 | RAID 기록의 가정으로 승계 (`raid-log.md`) |

## 3. 영역별 기술적 실현 가능성

| 영역 | 판정 | 근거와 주의점 |
|---|---|---|
| 후보 수집 (외부 소스 3개) | 가능, 주의 필요 | 산단공 공장현황 CSV·API, 특정수질유해물질 업체 CSV, 나라장터 입찰공고 API는 모두 연락처가 없는 공개 데이터라 법적 위험이 낮음 (Q10, 리서치 문서). 단, 공장현황 CSV에는 사업자등록번호가 없어 상호명·주소로 기업을 맞춰야 하고, API 개발 계정은 하루 1,000건 제한이 있음. 각 소스의 이용·저장 허용 범위는 아직 "확인 필요" |
| 기업·기회 중복 정리 | 가능, 난이도 중 | 사업자번호 없는 소스가 섞이므로 상호명 정규화가 필요. 불확실한 병합은 사람이 확인하는 방식이 안전 (리서치 문서 3장 제안) |
| 공통 평가 (필터 → 점수 → 분류) | 가능 | 규칙 엔진은 결정적 계산이라 팀 숙련도로도 구현 가능. 단, "평가 규칙서"가 없어 기획서 부록 F가 기준이며, 분류 분기 문구·핵심 근거 기준·시점 우선 세 요건은 요구사항 단계에서 질문으로 확정해야 함 |
| 외부 LLM 활용 (근거 추출·질문 생성·문안 초안) | 가능, 저비용 | 공개 자료만 보내므로 전송 제한 없음 (Q3). 건당 비용은 소액이며 800만 원 지원비 안에서 개발 중 사용 가능 (Q6). 월 사용량 상한은 정하지 않음 → 가설: 개발 기간 LLM 비용은 수만 원 단위에 그칠 것으로 보이나 측정 전 |
| 신규 기회 흐름 (끝까지) | 가능 | 공개 자료 + 가상 사례만으로 실행·검증 가능. 첫 대응 흐름으로 결정됨 |
| 재접촉 흐름 | 기능은 가능, 실데이터 검증은 불가(현재) | 거산 실제 이력은 G0 전까지 없음 (Q3, Q8). 가상 사례로 구현·검증하고 "실제 이력 검증 미실시"로 보고하는 것이 현실적 |
| 3개 화면 (추천 목록·근거 상세·의견/결과) | 가능 | 기본안 스택으로 구현 가능. 화면 꾸밈은 지연 시 가장 먼저 줄일 부분 |
| 운영 기록·엑셀·PDF 출력 | 가능, 후순위 | 단순 인쇄형 PDF면 부담이 작음. 11/15 이전 완료는 우선순위에 따라 달라짐 |
| 배포 (거산 접속) | 미정 | 5장 참조. 팀에 AWS 계정이 없고 복잡한 인프라를 피해야 함 (Q5, Q9) |

## 4. 작업량과 일정의 현실성

| 조건 | 내용 | 출처 |
|---|---|---|
| 투입 | 4인 전일(주 30시간 이상) | Q7 |
| 숙련도 | 전원 비전공자, 사관학교 교육·1차 MVP 경험, AI 코딩 도구 의존 | Q5 |
| 기간 | 10/19 시작 → 10/30 초기 동작 → 11/15 기능 완료 (약 4주) | 의도 문서 |
| 병행 부담 | 기존 레포 방식과 AI-DLC 방식을 함께 진행해 인력이 나뉨 | Q8 |

보수적 판단(가설): 숙련 팀 기준으로도 "24개 테이블, 시나리오 14개, 두 흐름, 3개 화면, 출력"을 4주에 끝내는 것은 빠듯합니다. 비전공 팀이 AI 도구로 작업하면 설계·검토·수정 왕복에 시간이 더 듭니다. 따라서 다음과 같은 우선순위 초안을 범위 정의 단계에 넘깁니다. 이것은 제안이며, 확정은 팀 합의(PM 주관)로 합니다.

| 우선순위 | 내용 | 목표 시점 (가설) |
|---|---|---|
| P0 | 9종 공정 구조와 가상 검수 데이터, 기회 병합, 필터·점수·분류 계산, 추천 목록·근거 상세·의견 화면, 신규 기회 흐름 끝까지 | 10/30 초기 동작, 11/8 안정화 |
| P1 | 재접촉 흐름(가상 사례로 기본 동작), 승인·접촉·결과 최소 기록, 외부 소스 3개 중 1~2개 실제 연결 | 11/15 |
| P2 | 엑셀·단순 PDF 출력, 나머지 소스 연결, 추가조사 기록 | 11/15 이후 보완 |
| P3 | 수동 명단(뿌리기술 전문기업·방산업체) 활용, 화면 다듬기 | 여유 시 |

## 5. 배포 방식의 선택지 (결정은 G0와 인프라 설계 단계에서)

사용자가 "설정이 쉽고 비용이 적은 방식"을 요청했으므로 (Q9), 문제 수준에서 선택지만 비교합니다. 구체 기술 선택은 뒤 단계에서 합니다.

| 선택지 | 장점 | 단점·조건 | 적합한 경우 |
|---|---|---|---|
| A. 팀 노트북에서 실행, 미팅 때 화면 공유로 시연 | 비용 0, 설정 없음 | 거산이 스스로 써 볼 수 없음 → 11월 중순 실사용 목표와 맞지 않음 | 10/30 초기 동작 시연까지 |
| B. 저비용 호스팅 서비스에 서버 하나 올리고 거산이 웹으로 접속 | 설정이 비교적 쉽고 월 비용이 작음(가설: 월 수만 원 이내, 측정 전). 공개 자료·가상 데이터만 다루면 보안 부담이 작음 | 접속 권한(로그인) 필요. 12/11 이후 비용 부담자를 거산과 협의해야 함 | 신규 기회 흐름 실사용 (11월 중순~) |
| C. 거산 PC 또는 거산 서버에 설치 | 재접촉 실제 이력을 거산 지정 환경에 두는 원칙에 맞음 | 설치·갱신 지원 부담, 거산 측 IT 환경 확인 필요 | 재접촉 실데이터 단계 (G0 이후) |

권장 방향(가설): 11월 중순 실사용은 B로, 재접촉 실제 이력이 들어오는 시점에는 C 또는 로컬 처리로 나누는 두 단계 접근이 비용·보안·숙련도 조건을 함께 만족합니다. G0에서 거산의 접속 방식·비용 부담을 확인한 뒤 확정합니다.

## 6. 자료·조직 조건

- 거산 실제 자료(공정 사양·인증 범위)는 검수 전이고, 일부 받은 자료도 질이 충분하지 않음 (Q8). 따라서 추천의 "근거"는 당분간 가상 검수 데이터로 채우며, 발표에서 실제/가상을 구분해야 함.
- 거산의 우선순위(회사소개서·공정 정리·불량 대응)와 2차 기획(잠재고객 추천)이 다르므로, 기업이 추천 결과 검증과 실사용에 소극적일 위험이 있음 (Q8). 의도 문서의 연결고리(역량 데이터가 소개서 근거로 이어짐)를 G0에서 설명하는 것이 참여를 끌어낼 방법임.
- 소통은 메일과 2주 간격 미팅이라 질문 답변이 늦을 수 있음 (Q8). 11/15 이전 기업 피드백 경로는 아직 비어 있어 범위 정의에서 정해야 함.

## 7. 결론과 다음 단계로 넘기는 결정

- 기능 실현 가능성: 전 항목 "가능". 막는 기술 장벽은 없음.
- 일정 실현 가능성: "11/15까지 8항목 전부"는 높은 위험. P0~P3 우선순위 확정이 필요.
- 범위 정의 단계에서 정할 것: P0~P3 확정, 11/15 이전 기업 피드백 경로, 수동 명단 활용 여부, 홈페이지·채용 소스 추가 여부.
- G0에서 거산과 확인할 것: 접속 방식과 12/11 이후 비용 부담, 실제 자료 사용·전송 범위, 방산 자료 취급 제한, 재접촉 이력 입력 경로.
