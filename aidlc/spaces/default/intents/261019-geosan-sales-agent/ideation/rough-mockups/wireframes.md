# 러프 화면 초안 (Wireframes) — 거산케미칼 AI 영업지원 에이전트 2차

이 문서는 영업 담당자가 쓰는 화면의 "대략적인 모습"입니다. 색·글꼴·정확한 배치는 뒤 단계(상세 화면 설계)에서 정하고, 여기서는 무엇이 어디에 놓이고 어떤 순서로 읽히는지만 잡습니다. 의도 문서(`../intent-capture/intent-statement.md`)의 1차 사용자(영업 담당자), 범위 문서(`../scope-definition/scope-document.md`)의 P0 화면 3개와 P1 추가 화면, 백로그(`../scope-definition/intent-backlog.md`)의 B-05(화면 3개)·B-08(재접촉)·B-09(기록)·B-13(접속 환경)을 바탕으로, `rough-mockups-questions.md`의 확인된 답변(Q1~Q9)과 첫 검토 뒤 사용자가 요청한 수정(담기 버튼, 재접촉 화면, 승인 조건 통일)을 반영해 그렸습니다.

그림 속 값은 모두 가상입니다. A정밀 밸브 바디 건은 기획서의 가상 사례 수치(E 77 / P 95 / S 81.1 / R 82, 시점 우선 접촉 후보)를 그대로 썼고, 그 밖의 기업·숫자·날짜는 "예시"라고 표시한 자리채움 값입니다.

## 0. 이 문서에서 쓰는 말

| 말 | 뜻 |
|---|---|
| 점수 계산기 | 기획서 5장·부록 F의 정해진 규칙대로 필터 → 점수 → 분류를 계산하는 부분. 사람이 바꾸지 않는 한 같은 입력이면 같은 결과가 나옵니다 |
| 막는 조건 | 지금 단계에서 꼭 필요한 요구 중 "통과"가 아닌 것(확인 대기·제외), 또는 거래 관계·중복 확인이 안 된 상태. 하나라도 있으면 접촉 승인이 막힙니다 |
| 바깥 AI 서비스 | 공개 자료에서 근거 문장과 질문을 뽑는 데 쓰는 외부 인공지능. 거산 내부 이력은 보내지 않습니다 |
| 자동 읽기 허용 규칙 | 홈페이지가 "프로그램이 읽어가도 된다"고 밝혀 둔 규칙. 이를 어기면서 읽지 않습니다 |
| 담기 | 담당자가 나중에 다시 보려고 기회를 따로 저장하는 동작. 의견(검토할 만함 등)과는 별개입니다 |

## 1. 화면 목록과 우선순위

| 번호 | 화면 | 우선순위 | 첫 화면 여부 | 근거 |
|---|---|---|---|---|
| S1 | 추천 목록 (신규 기회 탭 / 재접촉 탭) | P0 (재접촉 탭은 P1) | 10/30 첫 화면 | 범위 문서 P0-5·P1-1, Q1·Q9 |
| S2 | 근거 상세 (신규 기회용 / 재접촉용) | P0 (재접촉용은 P1) | | 범위 문서 P0-5·P1-1 |
| S3 | 의견/담기/승인/결과 영역 (S1·S2에 붙음) | 의견은 P0. 담기·승인·결과 기록은 P1 (담기는 대시보드와 같이 11/15, 사용자 확정) | | 범위 문서 P0-5·P1-2, Q2 |
| S4 | 대시보드 | P1 | 11/15부터 첫 화면 | Q1·Q9 |
| S5 | 재접촉 최소 필드 입력 | P1 | | Q7, 백로그 B-08 |

Q2에 따라 "의견 남기기"와 "담기"는 목록(S1)과 상세(S2) 양쪽에서 바로 할 수 있고, "접촉 승인·결과 기록"은 상세(S2)에서만 합니다. 그래서 S3은 별도 페이지가 아니라 S1·S2에 붙는 작은 영역으로 그렸습니다.

## 2. 공통 틀 (모든 화면)

```
+------------------------------------------------------------------+
| [로고]  거산 영업지원          대시보드  추천 목록      [담당자명] |
+------------------------------------------------------------------+
|                                                                  |
|   (화면별 내용)                                                  |
|                                                                  |
+------------------------------------------------------------------+
```

- 위쪽 띠: 로고 자리(지금은 글자), 메뉴 2개(대시보드는 P1 전까지 숨김), 담당자 이름.
- 흰 바탕, 회색 계열, 강조색 1개(버튼·선택 상태에만). 로고·강조색은 나중에 한 곳에서 바꿀 수 있게 둡니다 (Q4).
- 글자는 기본보다 한 단계 크게, 줄 간격 넉넉하게 (Q6).
- 상태 표시는 항상 "색 + 글자" 함께. 예: [통과] 초록 배경에 "통과" 글자 (Q6).
- 데스크톱 기준(가로 1280 이상). 휴대폰은 시간이 나면 (Q5).

접근성 공통: 페이지마다 제목(h1) 하나. 위쪽 띠는 머리글 영역, 메뉴는 탐색 영역, 본문은 주 영역. Tab 키는 "본문으로 건너뛰기" → 메뉴 → 본문 순서. 모든 버튼은 Enter 또는 Space로 누를 수 있습니다.

<!-- Text fallback: 제목 "추천 목록"과 오른쪽 "신규 기회 / 재접촉" 탭. 아래로 카드가 순위순으로 나열되며, 각 카드는 순위 번호·기업과 기회 이름(크게)·분류를 쉬운 말로(오른쪽)·점수(작게) 한 줄, 추천 이유 한 줄, 막는 조건 한 줄, 다음 할 일 한 줄, 의견 버튼 3개와 담기 버튼, 자세히 보기 버튼으로 구성. 맨 아래 쪽 넘김 -->

- 정렬: 점수 계산기의 분류 → 점수 순서. 신규 기회와 재접촉은 탭으로 나뉘고 서로 섞어 정렬하지 않음 (Q3, 기획서 5.1).
- 카드에서 크게 보이는 것: 기업·기회 이름, 추천 이유, 막는 조건, 다음 할 일. 작게: 순위, 분류, 점수 (Q3).
- 분류는 쉬운 말로 표시 (8장 대응표). 예: "시점 우선 접촉" → "지금 바로 연락 검토".
- [검토할 만함] [추가 확인] [대상 아님]을 누르면 그 자리에서 저장되고 버튼이 "의견: 검토할 만함 (수정)"으로 바뀜. [대상 아님]은 짧은 사유 입력 칸이 펼쳐지고 사유 없이는 저장되지 않음 (Q2).
- [담기]를 누르면 "담김 (빼기)"로 바뀌고, 대시보드의 "담아 둔 기회"에 들어감. 의견과 별개로 동작함 (사용자 수정 요청). 담기 버튼은 P1(11/15)이며 10/30 화면에는 보이지 않음. 백로그에는 담기 항목 추가가 필요함 (요구사항 분석에서 반영).
- "막는 조건" 줄은 승인에 영향을 주는지 글자로 밝힘: "(승인 막힘)" 또는 "(승인은 막지 않음)".
- "접촉 승인" 버튼은 여기 없음. 상세에서만 (Q2).
- "가상 데이터 표시 중" 띠는 가상 사례가 섞여 있을 때 항상 보임 (기획서 8장).

신규 기회 카드와 다른 점:

| 항목 | 신규 기회 카드 | 재접촉 카드 |
|---|---|---|
| 둘째 줄 | 추천 이유 (공개 자료 근거) | 지난 거래: 과거 공정·품목, 수주 여부, 마지막 납품일 |

| 다섯째 줄 | (없음) | 다음 할 일: 다음 약속·샘플 일정 |

다섯 가지 상태 (두 탭 공통):

| 상태 | 보이는 것 |
|---|---|
| 비어 있음 | 신규: "아직 추천할 기회가 없습니다. 팀이 후보를 넣으면 여기에 나타납니다." 재접촉: "입력된 재접촉 정보가 없습니다. [재접촉 정보 입력]으로 시작하세요." |
| 불러오는 중 | 카드 모양의 회색 자리표시 3개 |
| 정상 | 위 그림 |
| 오류 | 카드 자리에 "목록을 불러오지 못했습니다. 다시 시도" 버튼. 오류 코드는 보이지 않음 |
| 일부 | 후보가 1건이면 쪽 넘김 숨김. 100건 이상이면 20건씩 쪽 넘김. 추천 이유가 길면 2줄에서 자르고 상세에서 전체 |

## 5. S3 의견 / 담기 / 승인 / 결과 (S1·S2에 포함)

별도 페이지가 아닙니다. 위치와 우선순위는 다음과 같습니다.

| 어디 | P0 (10/30) | P1 (11/15) |
|---|---|---|
| S1 카드 | 의견 3가지 중 하나('대상 아님'은 사유) | 담기/빼기 |
| S2 맨 아래 | 의견 | 담기/빼기, 접촉 승인(목적 선택), 결과 상태·사유·다음 일정 |

- 기록 다섯 가지(시스템 분류 / 내 의견 / 담기 / 접촉 승인 / 영업 결과)는 화면에서도 따로 보이고, 하나를 바꿔도 다른 것이 바뀌지 않습니다. 기획서 5.4의 네 가지 기록(시스템 분류·담당자 의견·접촉 승인·영업 결과)에 "담기"가 추가 기록으로 더해진 것입니다. "담기"는 의견과 상관없이 켜고 끌 수 있습니다.
- 의견을 저장하면 "저장됨 10:12"가 버튼 옆에 잠깐 보였다가 "의견: 검토할 만함 (수정)"으로 남습니다. 담기는 "담김 (빼기)"로 남습니다.
- 실수 방지: '대상 아님'과 '실주'는 사유가 비어 있으면 저장 버튼이 눌리지 않고 이유가 글자로 보입니다.

접근성: 이 영역은 카드·상세 안에서 마지막 Tab 순서. 버튼 묶음은 "내 의견" 이름표가 붙은 그룹이며, 저장 결과("저장됨")는 화면 낭독기에 바로 읽힙니다.

## 10. 가정과 뒤 단계로 넘기는 것

| 구분 | 내용 | 어디서 |
|---|---|---|
| 가정 | 대시보드는 담당자·대표가 같은 화면을 보며, 사람별 구분은 첫 버전에 없음 | 요구사항 분석에서 확인 |
