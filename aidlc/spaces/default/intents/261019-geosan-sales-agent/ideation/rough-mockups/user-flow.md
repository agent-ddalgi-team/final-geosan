# 사용 흐름 (User Flow) — 거산케미칼 AI 영업지원 에이전트 2차

영업 담당자가 화면에서 실제로 밟는 길을 적었습니다. 화면 이름은 `wireframes.md`의 S1~S5를 따르고, 흐름은 의도 문서(`../intent-capture/intent-statement.md`)의 1차 사용자·성공 기준, 범위 문서(`../scope-definition/scope-document.md`)의 10/30·11/15 이정표, 백로그(`../scope-definition/intent-backlog.md`)의 B-06(신규 기회 뼈대)·B-08(재접촉)·B-09(기록)와 `rough-mockups-questions.md`의 답변(Q2·Q7·Q9), 첫 검토 뒤 사용자 수정 요청(담기 버튼, 재접촉 화면, 승인 조건 통일)에 맞췄습니다. 그림 속 기업·날짜 중 "(예시)"는 자리채움 값입니다.

## 0. 접촉 승인 가능 조건 (모든 흐름에 공통)

**지금 단계에 꼭 필요한 요구가 모두 "통과"이고, 거래 관계·중복 확인이 끝났으면 승인할 수 있다.** "나중 단계" 요구(예: 양산 전 샘플 승인)와 "질문 필요"(고객이 요구하는지 아직 모르는 것)는 승인을 막지 않는다. 질문 필요가 남아 있으면 승인 목적은 "요구 확인"으로 둔다 (기획서 5.2.1·5.2.2). 꼭 필요한 요구인데 거산이 충족하는지 모르는 것("확인 대기")과 거래 관계 미확인은 승인을 막는다. A정밀 가상 사례는 승인 가능하다.

## 1. 흐름 1: 추천 확인, 의견 남기기, 담기 (가장 흔한 길, P0)

- 사용자: 거산 영업 담당자
- 시작: 추천 목록을 연다 (10/30에는 첫 화면, 11/15부터는 대시보드에서 "추천 목록으로" 버튼)
- 단계:
  1. S1 추천 목록 → 신규 기회 탭이 열려 있음 → 순위순 카드가 보임
  2. S1 카드 → 추천 이유·막는 조건·다음 할 일을 읽음 → 판단이 서면 [검토할 만함] 또는 [추가 확인]을 누름 → 그 자리에 "의견: … (수정)"으로 저장됨
  3. (P1, 11/15부터) (나중에 다시 보려면) S1 카드 → [담기] → "담김 (빼기)"로 바뀌고 대시보드의 담아 둔 기회에 들어감. 의견 없이 담기만 해도 됨
  4. (판단이 안 서면) S1 카드 → [자세히 보기] → S2 근거 상세가 열림
  5. S2 → 요구별 판정 표·근거 자료·확인 질문을 읽음 → 맨 아래 의견 버튼 또는 [담기]를 누름 → 저장됨
  6. S2 → [목록으로] → S1로 돌아오며 방금 남긴 의견·담기 상태가 카드에 보임
- 끝: 카드에 내 의견과 담김 표시가 보이고, 대시보드(P1)의 "담아 둔 기회" 건수가 늘어남
- 오류·예외:
  - [대상 아님]을 누르면 사유 칸이 펼쳐짐 → 사유 없이 저장을 누르면 "사유를 적어 주세요"가 칸 아래 글자로 보임 → 사유를 적으면 저장
  - 저장 실패 → 버튼 옆 "저장하지 못했습니다. 다시 시도" → 다시 누르면 재시도, 입력한 사유는 남아 있음
  - 분류가 "기다리는 중(확인 필요)"인 카드도 의견·담기는 할 수 있음. 다만 접촉 승인은 막힘 (0장)

클릭 수: 가장 짧은 길은 2번(목록 열기 → 의견 또는 담기 버튼). 상세를 거치면 4번.

## 2. 흐름 2: 접촉 승인과 결과 기록 (P1)

- 사용자: 거산 영업 담당자
- 시작: 의견을 남기거나 담아 둔 기회에 실제로 연락하기로 함
- 단계:
  1. S1 (또는 S4 담아 둔 기회 목록) → 해당 카드 [자세히 보기] 또는 [열기] → S2 근거 상세
  2. S2 → 2번 표 아래 "승인 가능 여부" 줄을 확인 (0장 조건) → 맨 아래 접촉 승인 [승인] → 목적 선택(요구 확인 / 역량 소개 / 일정 응답, 재접촉은 기존 제안 후속 확인 / 일정 응답) → 승인자·시각이 기록됨
  3. (연락한 뒤) S2 → 결과 기록 상태(진행중 등)와 다음 일정을 입력 → 저장
  4. 다음 일정이 대시보드의 이번 주 일정에 나타남
- 끝: 같은 기회에 기록 다섯 가지(시스템 분류, 내 의견, 담기, 접촉 승인, 영업 결과)가 각각 따로 기록됨. 담기는 기획서 5.4의 네 기록에 더해진 추가 기록
- 오류·예외:
  - 막는 조건(확인 대기·제외·거래 관계 미확인)이 있으면 [승인] 버튼이 눌리지 않고 옆에 "ISO 9001 확인이 끝나야 승인할 수 있습니다"처럼 이유가 보임. "나중 단계"·"질문 필요"만 있으면 눌림
  - 결과를 "실주"로 바꾸면 사유 칸이 필수
  - 재평가로 분류가 바뀌어도 이미 한 승인은 그대로 남고, 새 평가에는 "이전 승인은 이전 평가 기준" 표시

## 3. 흐름 3: 근거 보강 — 홈페이지 주소 확정 (P0 입력란, P1 자동 탐색)

- 사용자: 거산 영업 담당자 또는 팀
- 시작: S2 근거 자료 영역에 "홈페이지 확인 필요" 표시가 보임
- 단계:
  1. S2 → 홈페이지 주소 입력란에 주소를 넣고 [확정]
  2. 시스템이 본문(연락처 제외)을 가져와 근거를 뽑음 → 근거 자료 목록이 늘어나고 "재평가됨" 표시
  3. 분류·점수가 바뀌면 S1 카드 순위도 바뀜
- 끝: 근거 자료에 홈페이지 항목이 추가되고 확인 질문이 줄어듦
- 오류·예외:
  - 주소가 열리지 않으면 "주소를 열 수 없습니다. 다시 확인해 주세요"
  - 사이트가 자동 읽기를 허용하지 않으면 "이 사이트는 자동으로 읽을 수 없습니다. 내용을 직접 붙여 넣어 주세요" + 본문 붙여넣기 칸
  - 이전 평가는 지워지지 않고 "이전 평가 보기"로 남음

## 4. 흐름 4: 재접촉 정보 입력과 평가 (P1)

- 사용자: 거산 영업 담당자 (팀은 원본을 받지 않음)
- 시작: S1 재접촉 탭 → [+ 재접촉 정보 입력]
- 단계:
  1. S5 입력 화면 → 7개 칸을 채우고 각각 확인/추정을 고름 → [저장하고 평가]
  2. 외부로 보내지 않고 재접촉 프로필로 계산됨 → S1 재접촉 탭에 카드가 나타남 (지난 거래·다시 연락할 이유·다음 할 일)
  3. 카드 [자세히 보기] → S2 재접촉용 상세(지난 거래 이력, 다시 연락할 이유, 후속 일정)
  4. 이후는 흐름 1·2와 같음
- 끝: 재접촉 목록에 카드가 생기고, 신규 기회 목록과 섞이지 않음
- 오류·예외:
  - 필수 칸이 비면 그 칸 아래 이유가 보이고 저장되지 않음
  - 이 기회에 과거 이력이 없다고 판단되면 "이 기회는 재접촉이 아니라 신규 기회로 평가됩니다" 안내 후 신규 탭으로
  - 추정으로 표시한 항목이 많으면 카드에 "이력 일부 추정 (확인 필요)"가 보이고 승인 전 확인을 권함

## 5. 흐름 5: 하루 시작 — 대시보드 (P1, 11/15부터)

- 사용자: 거산 영업 담당자, 대표
- 시작: 접속하면 S4 대시보드가 첫 화면
- 단계:
  1. S4 → 건수 4개와 이번 주 일정, 담아 둔 기회 목록을 봄
  2. "확인할 기회 3건"을 누름 → S1이 그 조건으로 걸러져 열림 → 흐름 1
  3. 담아 둔 기회의 [열기] → 해당 기회의 S2 → 흐름 2. [빼기] → 목록에서 사라지고 건수가 줄어듦
  4. 일정 항목을 누름 → 해당 기회의 S2 → 흐름 2의 결과 기록
- 끝: 처리한 건수가 줄고 "최근 내가 한 일"에 기록이 쌓임
- 오류·예외: 기록이 하나도 없으면 "아직 기록이 없습니다. 추천 목록에서 시작하세요"와 버튼만 보임

## 6. 전체 흐름 그림

```
         [접속]
           |
   (10/30) |         (11/15부터)
           v              v
      S1 추천 목록 <--- S4 대시보드 (담아 둔 기회 목록 [열기]/[빼기])
        |     |
        |     +--[탭: 재접촉]--> S5 입력 (P1) --> S1 재접촉 카드 --> S2 재접촉용 상세
        |
        +--[카드 의견 버튼 / 담기(P1)]--> 저장 (흐름 1, 2클릭)
        |
        +--[자세히 보기]--> S2 근거 상세
                              |-- 의견 저장 (P0) / 담기 (P1)
                              |-- 홈페이지 주소 확정 --> 재평가 (흐름 3)
                              |-- 접촉 승인 (P1, 0장 조건을 만족할 때만)
                              +-- 결과·다음 일정 기록 (P1) --> S4 일정
```

## 7. 10/30 시연 순서 (뼈대 확인용)

범위 문서의 10/30 최소 범위(가상 사례 1건이 필터 → 점수 → 분류 → 목록·상세 → 의견 저장까지)를 화면 흐름으로 옮기면 다음 7단계입니다. 승인·결과 기록은 P1이라 이 시연에 없습니다.

1. 추천 목록을 연다 → A정밀 카드가 1위, "지금 바로 연락 검토", 점수 81 (S 81.1의 반올림)
2. 카드의 막는 조건이 "없음"인지 확인
3. [자세히 보기] → 요구별 판정 표에서 ISO 9001 "통과(응모 가능)", 샘플 승인 "나중 단계", Nadcap "질문 필요" → "승인 가능 여부: 가능" 줄 확인
4. 점수 자세히 보기를 펼쳐 E 77 / P 95 / S 81.1 / R 82 확인
5. 맨 아래 [검토할 만함] → 저장됨 (담기 버튼은 P1이라 이 시연에 없음)
6. [목록으로] → 카드에 "의견: 검토할 만함" 표시
7. (가능하면) 산단공 공장현황 자료에서 불러온 실제 후보가 2위 이하에 보임

## 8. 가정

- 로그인·담당자 구분 방식은 접속 환경(G0)에서 정해지므로 여기서는 "담당자명"만 상단에 표시한다고 가정.
- 대시보드 건수의 정확한 정의(확인할 기회 = 분류가 연락 검토 종류이고 아직 내 의견이 없는 것 등)는 요구사항 분석에서 확정.
- "담아 둔 기회"는 사람별로 따로 저장되는지(담당자마다 다른 목록) 요구사항 분석에서 확인.
