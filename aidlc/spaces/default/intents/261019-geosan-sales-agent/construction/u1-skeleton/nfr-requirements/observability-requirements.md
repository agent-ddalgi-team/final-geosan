# 관측 요구 (Observability Requirements) — U1 뼈대 (u1-skeleton)

요구사항 NFR5(추적성·감사)·NFR10(오류 처리)을 "무엇을 어떻게 남기고 보는가"로 세분한 것입니다. 뼈대는 팀 노트북 실행이라 모니터링 대시보드·알림은 없고, **서버 로그 한 파일과 데이터베이스의 기록 테이블**이 관측 수단입니다. 호스팅 환경의 헬스 체크·알림은 U8·관측 설계(운영 단계는 이번 범위에서 건너뜀)에서 다시 봅니다.

## 1. 로그 (NFR10, NFR5)

| ID | 요구 |
|---|---|
| NFR10.1 | 서버·명령은 한 줄 JSON 로그(시각(시간대 포함), 레벨, 이벤트 이름, ref, 요청 경로·메서드·상태·소요 ms, 묶음/평가/기회 ID 등 식별자)를 표준 출력과 로그 파일에 남긴다. 레벨: DEBUG(개발 때만), INFO, WARNING, ERROR |
| NFR10.2 | 모든 오류는 짧은 식별자 `ref`와 함께 로그에 남고, 화면·명령 출력에는 쉬운 말 + nextAction + ref만 보인다. 스택·오류 코드는 로그에만 |
| NFR10.3 | 로그에 넣지 않는 것: 근거 원문·본문, 의견 메모 본문, 비밀번호·API 키·환경 변수 값, 처리 금지 자료 원문. 식별자와 길이·건수만 남긴다 |
| NFR10.4 | 공정 연결 현재 결과와 최신 평가가 어긋나 재계산한 경우(BR2.5), 검수 상태 사본과 FieldEvidence가 어긋난 경우(entities 원본 규칙) WARNING 로그를 남긴다 |
| NFR10.5 | 명령(import·evaluate·verify-case)은 시작·끝·건수·건너뛴 항목·소요 시간을 INFO로 남기고 출력 마지막 줄에 한국어 요약 한 줄 |
| NFR10.6 | 로그 파일 위치는 설정(기본 `logs/geosan.log`), 하루 1파일 회전, 14일 보관(뼈대 기간엔 로컬) |

## 2. 기록 테이블이 곧 감사 기록 (NFR5)

| 무엇을 알고 싶은가 | 어디서 보는가 |
|---|---|
| 이 순위가 어떤 입력·규칙으로 나왔나 | EvaluationBatch(규칙 버전·해시·기준일·묶음) + EvaluationRun.inputSnapshot·snapshotHash |
| 항목별 점수·근거 | ItemJudgment + JudgmentEvidence |
| 요구가 왜 통과/미확인/제외인가 | RequirementCheck(비교값·사유·자격 ID) |
| 누가 언제 어떤 의견을 냈고 어느 평가를 봤나 | ReviewOpinion(staffName·recordedAt·evalId·version·previousOpinionId) |
| 거산 값이 언제 누구 근거로 검수됐나 | FieldEvidence(reviewer·reviewedAt·basis·dataVersion) |
| 파일을 언제 누가 넣었나 | 모든 행의 created_at·created_by, Opportunity.caseId, supersededAt |

NFR5.5: 위 표의 어느 질문에도 로그를 뒤지지 않고 테이블 조회만으로 답할 수 있어야 한다(코드 생성에서 조회 예시를 안내서에 둔다).

## 3. 지표 (뼈대에서는 로그로만 계산)

| ID | 지표 | 어떻게 |
|---|---|---|
| NFR10.7 | 요청별 소요 시간(목록·상세·의견) | 로그의 소요 ms, 성능 요구 측정에 사용 |
| NFR10.8 | 평가 1건·전체 소요 시간 | 명령 로그 |
| NFR10.9 | 오류 건수(레벨 ERROR) | 로그 집계(수동) |
| NFR10.10 | 외부 전송 건수 | 전송 로그 테이블 행 수 = 0(U1) |

알림 임계값·대시보드는 뼈대에 없다. 11/6 시연 환경부터 "서버 살아 있음" 헬스 경로(`/api/v1/health`, U8)를 둔다.

## 4. 화면에서 보이는 상태 정보

- NFR10.11: 모든 화면 위쪽 띠에 데이터 갱신 시각(최신 확정 묶음 생성 시각)과 가상 데이터 포함 여부, 거산 값 묶음을 보인다(BR10.4).
- NFR10.12: 상세의 "점수 자세히 보기"에 규칙 버전·거산 값 묶음·평가 시각을 보인다(BR10.5).
- NFR10.13: 오류 상태는 쉬운 말 원인·다음 행동·[다시 시도]·작은 ref를 보인다(BR10.7).

## 상류 문서와의 연결

- 요구사항 NFR5(스냅샷·버전·작성자·시각·본문 없는 로그), NFR10(쉬운 말·로그·부분 실패 구분).
- 기능 명세 W3·W5~W7, 규칙 BR2.5·BR7.1~7.3·BR9.2~9.4·BR10.4·BR10.5·BR10.7.
- 계약 3장(ref·로그 규칙·본문 금지), C1 meta(updatedAt·hasVirtualData·datasetKind).
