# 성능 요구 (Performance Requirements) — U1 뼈대 (u1-skeleton)

요구사항 NFR2(응답 시간)와 NFR8(사용성)의 수치를 뼈대 단위에 맞게 세분한 것입니다. 기준 문서: `../../../inception/requirements-analysis/requirements.md` 3장, 계약 3장 응답 시간 행(`../../../inception/contract-design/contract-summary.md`), 기능 명세 W1~W9(`../functional-design/functional-spec.md`). 측정 환경은 팀 노트북(SQLite 한 파일, 단일 프로세스)이며, 호스팅 환경 측정은 U8 뒤에 다시 한다. "목표"는 넘지 않으려는 값, "중단 한도"는 화면이 기다리기를 멈추는 값이다(둘은 다른 것).

## 1. 응답 시간 목표 (NFR2)

| ID | 대상 | 목표 | 중단 한도 | 측정 방법 |
|---|---|---|---|---|
| NFR2.1 | 추천 목록 `GET /opportunities` (100건 이하, 20건 쪽) | 서버 응답 1초 이내, 화면 표시 3초 이내 | 10초 | 가상 후보 50건 + A정밀 1건으로 10회 측정, p95 |
| NFR2.2 | 근거 상세 `GET /opportunities/{oppId}` | 서버 응답 1초 이내, 화면 표시 3초 이내 | 10초 | 같은 데이터로 10회, p95 |
| NFR2.3 | 평가 1건(규칙 엔진 계산 + 저장) | 1초 이내 | 없음(명령) | `evaluate --opp` 1건 10회, 최대값 |
| NFR2.4 | 전체 평가(`evaluate`, FULL 묶음) 50건 | 30초 이내 | 없음 | 부분 시연 데이터(실제 기업 20 + 가상 30)로 측정 |
| NFR2.5 | 전체 평가 2,000건(규모 상한, NFR3) | 10분 이내 | 없음 | 11월 U3 수집 뒤 측정(뼈대에서는 목표만) |
| NFR2.6 | 의견 저장 `POST /opinions` | 500ms 이내 | 10초 | 10회, p95 |
| NFR2.7 | `import-case` 파일 1개 | 2초 이내 | 없음 | 실제 기업 파일 20개 연속 투입 ≤ 1분 |
| NFR2.8 | `verify-case` | 3초 이내(평가 1건 + 비교) | 없음 | A정밀 파일 10회 |
| NFR2.9 | 서버 시작(`serve`) | 5초 이내 | 없음 | 설정 읽기·마이그레이션 확인 포함 |
| NFR2.10 | 화면 첫 로드(React 번들) | 2초 이내(로컬) | — | 빌드 산출물 크기 1MB 이하(gzip 전) |

외부 LLM 추출(60초)과 홈페이지 읽기는 U2이므로 여기 없다.

## 2. 화면 반응 규칙 (NFR2·상호작용 명세)

- NFR2.11: 1초를 넘는 작업은 진행 표시(자리표시 또는 스피너)를 보이고, 5초를 넘으면 "조금 오래 걸리고 있습니다"를 보인다.
- NFR2.12: 중단 한도(10초)를 넘으면 오류 상태(쉬운 말 + [다시 시도])로 바꾸고 입력값을 유지한다.
- NFR2.13: 의견 저장 피드백 "저장됨 HH:MM"은 응답 직후 표시하고 3초 뒤 영구 문구로 바꾼다.

## 3. 사용성 목표 (NFR8)

| ID | 목표 | 확인 방법 |
|---|---|---|
| NFR8.1 | 가장 흔한 길(목록 열기 → 의견)은 클릭 2번, 상세를 거치면 4번 | 10/30 시연 흐름 5단계로 세기 |
| NFR8.2 | 본문 글자 16px 이상, 글자 대비 4.5:1 이상, 상태는 색과 글자를 함께 | 접근성 점검표(`../../../inception/refined-mockups/accessibility-checklist.md`) |
| NFR8.3 | 모든 기능 키보드 조작, 페이지마다 h1 하나, "본문으로 건너뛰기", 저장 결과 낭독 | 키보드만으로 시연 흐름 5단계 수행 |
| NFR8.4 | 카드·목록에는 쉬운 말만, 전문 용어(E/P/R)는 점수 세부 안에서만 | 대응표 파일 대조 |
| NFR8.5 | 거산 담당자 1명이 안내 없이 "목록 확인 → 상세 보기 → 의견 저장"을 10분 안에 | 11/13 전 팀 밖 검증자 1명 사전 검증, 11/15 거산 담당자 |

## 4. 자원 제약

- NFR2.14: 단일 프로세스, 메모리 512MB 이하(팀 노트북·저비용 호스팅 전제), 전체 평가 중에도 목록 조회가 멈추지 않도록 평가는 명령으로만 돌리고 화면 요청과 같은 프로세스에서 긴 잠금을 잡지 않는다(쓰기 잠금 대기 5초, NFR7.2).
- NFR2.15: SQLite WAL 모드로 읽기(화면)와 쓰기(평가·의견)가 서로 막지 않게 한다.

## 5. 측정 시점

- 뼈대 체크포인트(10/28): NFR2.1~2.4, 2.6~2.10, 8.1~8.4를 팀 노트북에서 측정해 결과를 `tests/perf-notes.md`(코드 생성에서 위치 확정)에 적는다. 목표를 넘으면 원인과 조정안을 적고, 목표 자체는 측정 뒤 조정할 수 있다(요구사항 A6).
- NFR2.5·NFR8.5는 뼈대 밖(11월).

## 상류 문서와의 연결

- 요구사항 NFR2(3초·1초·60초), NFR8(클릭 2·4번, 16px, 4.5:1, 쉬운 말), 가정 A6.
- 계약 3장 응답 시간(목표 vs 중단 한도 구분), C1 쪽당 20건·최대 50건.
- 기능 명세 W3(⓪ 평가), W5·W6·W7, 규칙 BR10.7·BR10.8.
