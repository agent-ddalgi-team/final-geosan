# 보안 요구 (Security Requirements) — U1 뼈대 (u1-skeleton)

요구사항 NFR4(데이터 보호)·NFR5(추적성)와 팀 금지 규칙(연락처 미저장, 내부 자료 외부 전송 금지, 비밀 값 코드 금지)을 뼈대 단위에 맞게 세분한 것입니다. 뼈대는 **외부 호출이 없고**(LLM·홈페이지 읽기는 U2), **접속 보호가 없는 로컬·팀 노트북 실행**(공용 비밀번호·HTTPS는 U8)이므로, 이 단계의 보안 요구는 "데이터에 무엇이 들어오고 무엇이 나가는가"에 집중합니다.

## 1. 배포 모양 (적용 범위를 정하는 전제)

- 뼈대 기간(10/21~10/28)과 10월 말 부분 시연: 팀 노트북에서 `serve`로 띄워 같은 컴퓨터의 브라우저로 본다. 외부 공개 주소 없음, 계정 없음, 사용자는 팀 4명과 시연 자리의 거산 담당자.
- 데이터: 가상 사례(A정밀), 거산 회사소개서 값(소개서 묶음, 내부 구조화만), 실제 기업 10~20곳의 **공개** 자료(홈페이지·공고 인용). 개인 연락처 없음.
- 따라서 인증·세션·전송 암호화 요구는 U8에서, 거래처·내부 이력 전송 차단은 U2 전송 보호에서 다루며 여기서는 "구조적으로 불가능하게 만드는" 요구만 둔다.

## 2. 데이터 보호 요구 (NFR4)

| ID | 요구 | 확인 방법 |
|---|---|---|
| NFR4.1 | 고객·기회·근거·이력·의견 어디에도 담당자 이름·이메일·전화 열이 없다. 자유 문장(파일의 quote·basis·notes·content·allowedSummary·factJudged·distinctionBasis·identityBasis·question, 화면의 의견 메모·사유)에 이메일·전화 패턴이 있으면 저장하지 않고 거부한다(규칙 BR2.1, BR9.1) | 연락처가 섞인 파일·요청으로 테스트, DB 전체 검색 0건 |
| NFR4.2 | 보안 등급 '처리 금지'(FORBIDDEN) 근거의 원문은 평가 스냅샷·상세 응답·로그 어디에도 넣지 않는다(ID·차단 사유만)(BR7.3) | FORBIDDEN 근거 1건으로 평가 뒤 스냅샷·응답·로그 검색 |
| NFR4.3 | 뼈대에는 외부로 나가는 호출이 없다. 외부 LLM·HTTP 클라이언트 코드가 U1 모듈에 없고, 테스트에서 네트워크 호출이 0건임을 확인한다 | 네트워크 차단 상태에서 전체 테스트 통과, 전송 로그 테이블 0행 |
| NFR4.4 | 비밀번호·API 키는 코드·설정 파일·로그·저장소에 없고 환경 변수로만 읽는다. 뼈대가 읽는 환경 변수는 데이터베이스 경로(GEOSAN_DB_PATH)뿐이다 | 저장소 비밀 패턴 검사(CI, 3.7), check-config가 설정 파일의 비밀 키를 오류로 |
| NFR4.5 | 실제 기업 자료는 공개 자료(홈페이지·공고)만 넣고 보안 등급 PUBLIC으로 표시한다. 회사소개서 값은 INTERNAL_ONLY(내부 구조화만)로 표시해 11월 U2 전송 보호가 외부로 보내지 않게 한다 | 파일 검사기가 securityGrade 필수, 기본값 없음 |
| NFR4.6 | 거산 값 묶음(가상 검수 / 소개서)은 묶음별로 따로 저장되고 평가는 활성 묶음만 읽어, 검수 전 값이 다른 묶음의 검수 완료 값과 섞여 통과 근거가 되는 일이 없다(BR1.3, BR1.7) | 두 묶음 투입 뒤 활성 묶음 전환 테스트 |
| NFR4.7 | 데이터베이스 파일은 저장소에 커밋하지 않는다(`.gitignore`), 백업 파일도 같다 | CI에서 `*.db` 커밋 여부 검사(3.7) |

## 3. 접근·권한 요구 (NFR4, FR14.1)

| ID | 요구 | 확인 방법 |
|---|---|---|
| NFR4.8 | 기록 요청(의견 저장)은 담당자 키 헤더가 앱 설정 목록에 있어야 받고, 없거나 예약 키 viewer면 403으로 거부한다. 조회 요청은 키 없이 허용한다(뼈대 기간 로컬) | 키 없음·목록 밖·viewer 세 경우 테스트 |
| NFR4.9 | 담당자 키는 인증이 아니라 실수 방지용이다. 이 한계를 안내서와 화면 띠("내부용")에 밝히고, 실제 거래처 정보 입력 전 담당자별 계정(FR14.3, G0 이후)으로 닫는다 | 문서 확인 |
| NFR4.10 | 뼈대 기간에는 접속 보호를 끈 상태로 두되, 외부에서 접근 가능한 주소(공개 터널·호스팅)에 올리지 않는다. 11/6 시연 환경 배포는 U8(접속 보호·HTTPS) 뒤에만 한다 | 팀 규칙, 외부 의존 지도 E-4 |

## 4. 입력 검증 요구 (경계마다)

| ID | 요구 |
|---|---|
| NFR4.11 | 파일 경계: 모르는 키 거부, 허용 값(C0 코드·단계 이름) 밖 거부, 숫자 범위(일치도 단계값, 점수 0~100), 날짜 형식, 연락처 패턴, 파일 안 참조 범위(evidenceRefs·signalRefs), 한 항목 오류면 저장 없음(BR2.2) |
| NFR4.12 | API 경계: 본문 형식·필수 값·길이(메모 200자)·열거값 검증, 실패는 400 fields[]; 경로 ID 형식 검증, 없는 ID는 404; 요청 본문 크기 상한 64KB(의견), 응답에 내부 오류 문장·스택 비노출 |
| NFR4.13 | 설정 경계: 규칙 설정·앱 설정 형식 검사, 잘못된 키 지목, 기본값 대체 금지(BR7.6) |
| NFR4.14 | 화면 출력: 사용자가 적은 문장(의견 메모·사유)과 파일에서 온 문장(근거 인용)은 HTML로 해석하지 않고 글자로만 표시한다(React 기본 이스케이프 유지, dangerouslySetInnerHTML 금지) |
| NFR4.15 | 파일 경로: 투입 명령은 인자로 받은 경로만 읽고, 데이터베이스 경로는 환경 변수 또는 설정의 절대 경로만. 심볼릭 링크·상위 경로(`..`) 탈출은 코드 생성에서 검사 |

## 5. 추적·감사 요구 (NFR5)

| ID | 요구 |
|---|---|
| NFR5.1 | 모든 평가는 입력 스냅샷·해시·규칙 버전·해시·코드 버전·거산 값 묶음을 보존한다(BR7.1, BR7.2) |
| NFR5.2 | 의견은 작성자(담당자 키)·시각(시간대 포함)·본 평가 ID를 보존하고, 수정은 새 행이며 덮어쓰지 않는다(BR9.2, BR9.4) |
| NFR5.3 | 투입 명령은 어느 파일을 언제 누가(`created_by`) 넣었는지 행마다 남긴다 |
| NFR5.4 | 전송 로그는 U2부터 쓰이며 뼈대에서는 비어 있다(0건이 곧 "외부 전송 없음"의 증거) |

## 6. 위협 고려 (간단 STRIDE, 뼈대 범위)

| 위협 | 뼈대에서의 노출 | 대응 |
|---|---|---|
| 위장(다른 담당자 키로 기록) | 있음 — 키는 검증되지 않음 | 알려진 잔여 위험(NFR4.9). 실수 방지용으로 명시, 계정은 G0 이후 |
| 변조(파일로 거산 값·평가 조작) | 팀 내부만 접근 | 파일 투입은 명령으로만, 검수 상태 되돌림 금지(BR1.7), 평가 이력 보존 |
| 부인(누가 의견을 냈는지) | 낮음 | 담당자 키·시각·버전 이력(NFR5.2) |
| 정보 노출(연락처·내부 자료) | 가장 중요 | NFR4.1~4.6, 외부 호출 0건 |
| 서비스 거부 | 낮음(로컬) | 요청 크기 상한, 중단 한도, 쓰기 잠금 5초 |
| 권한 상승 | 없음(권한 단계 없음) | — |

## 7. 의존성·공급망

- NFR4.16: 파이썬·노드 의존성은 잠금 파일(lock)로 고정하고, 취약점 검사(파이썬 `pip-audit`, 노드 `npm audit`)는 CI 파이프라인(3.7)에서 돌린다. 뼈대 기간에는 설치 시 1회 수동 실행.
- NFR4.17: 새 의존성 추가는 PR에 이유를 적는다(약속 파일 규칙과 같은 "먼저 적고 만든다").

## 상류 문서와의 연결

- 요구사항 NFR4·NFR5, FR14.1~14.3, 가정 A10, 팀 금지 규칙(project.md Forbidden: CON-07·09·11·23, 비밀 값).
- 기능 명세 W2·W7, 규칙 BR2.1·BR2.2·BR7.3·BR7.6·BR9.3·BR9.4·BR11.3.
- 계약 C1 보안 경계(세션은 U8), C4 전송 보호(U2), 3장 로그 규칙.
- 구현 단계 지침(`phases/construction.md` Security): 비밀 하드코딩 금지, 경계 입력 검증, 인증 우회 표시.
