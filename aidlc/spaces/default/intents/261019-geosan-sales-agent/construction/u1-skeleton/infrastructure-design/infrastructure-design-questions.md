# 인프라 설계 질문 — U1 뼈대 (u1-skeleton)

뼈대 기간(10/21~10/28)과 10월 말 부분 시연은 팀 노트북에서 돌리며, 시연 환경 호스팅(11/6 전)·접속 보호·백업 명령은 U8과 그때의 인프라 설계에서 정합니다(전달 계획 B3, 외부 의존 E-4, 팀 실천 방식 Deployment: 구체 서비스는 G0·인프라 설계에서). 그래서 이 단계는 "로컬 실행 + CI(자동 검사)"만 설계하고, 확인된 답변은 PM 지시(2026-10-21, "3.4는 로컬 + CI만, 호스팅은 11월")에 따라 추천안으로 기록합니다. 요약 확인은 이 작업에서 꺼져 있습니다.

## Q1. 뼈대 기간 실행 환경은 무엇으로 할까요?

A. 팀 노트북 로컬 실행만: `geosan serve`로 띄우고 같은 컴퓨터 브라우저로 본다. 외부 주소 없음, 접속 보호 꺼짐, 컨테이너 없음. 부분 시연도 PM 노트북으로. (추천: PM 지시와 같고, 11/6 전 호스팅 결정을 막지 않음)
B. 지금 Docker 이미지도 함께 만들어 둔다(호스팅 후보가 컨테이너형일 때 대비).
C. 지금 호스팅 서비스를 골라 바로 올린다.
X. Other (please specify)

[Answer]: A

## Q2. CI(자동 검사)는 언제 만들까요?

팀 실천 방식은 `main`에 합치기 전 CI에서 포매터·린터·테스트를 돌리는 것이고, CI 파이프라인을 만드는 단계(3.7)는 뼈대의 코드 생성·빌드와 테스트 뒤입니다. 팀원 PR이 10/23부터 들어오므로 그 전에 검사가 있으면 좋습니다.

A. 설계는 여기서 적고, 워크플로 파일은 3.5 코드 생성의 기본 틀에 "검사만 하는 최소 CI"(Ruff·pytest·ESLint·Prettier·Vitest·빌드)로 먼저 넣는다. 3.7에서 약속 파일 비교·취약점 검사·배포 연결을 더한다. (추천: 10/23 팀원 PR부터 검사가 돌고, 3.7의 몫은 남음)
B. 3.7까지 기다리고 뼈대 기간에는 각자 로컬에서 같은 명령을 돌린다.
C. 전체 CI(배포 포함)를 지금 만든다(호스팅 미정이라 불가).
X. Other (please specify)

[Answer]: A
