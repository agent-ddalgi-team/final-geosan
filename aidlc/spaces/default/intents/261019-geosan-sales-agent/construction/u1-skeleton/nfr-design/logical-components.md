# 논리 구성 요소 (Logical Components) — U1 뼈대 (u1-skeleton)

NFR 설계 결정이 어느 구성 요소에 붙는지, 실패가 어디까지 번지는지(장애 범위)를 적은 목록입니다. 인프라 설계(3.4)가 이 표를 받아 "어디에 띄우는가"를 정합니다. 뼈대는 **프로세스 하나 + 파일 셋(DB·로그·설정)** 이라 장애 범위가 사실상 하나이며, 그 안의 경계는 폴더(부품)로 나뉩니다.

## 1. 구성 요소 목록

| 구성 요소 | 종류 | 들어 있는 것 | 상태(데이터) | 실패하면 |
|---|---|---|---|---|
| 앱 프로세스 `geosan serve` | 프로세스 | FastAPI(API + 정적 화면), 부품 모듈 전부 | 없음(모두 파일·DB에) | 화면·API 전부 중단. 재시작 1분 이내. 데이터 손실 없음(WAL) |
| 명령 프로세스 `geosan <명령>` | 프로세스(짧게 실행) | 투입·평가·검증·설정 검사 | 없음 | 그 명령만 실패, 되돌림. 서버는 영향 없음(잠금 5초만) |
| 데이터베이스 파일 `data/geosan.db` (+ -wal, -shm) | 파일 | 테이블 접두사 7묶음(cfg_, cap_, opp_, ev_, eval_, q_, rec_) | 모든 업무 데이터 | 전부 중단. 복구 = 백업 파일 복사 |
| 설정 파일 `rule-config.yaml`, `app-settings.yaml` | 파일 | 규칙 수치(버전·해시), 담당자·활성 묶음·브랜드 | 설정 | 시작·평가 거부(키 지목). 되돌리기 = git |
| 예시·사례 파일 `examples/`, 팀원 사례 파일 | 파일(입력) | 거산 역량·가상 사례·실제 기업 | 입력 원본(저장소에 커밋) | 투입 거부(줄·항목·이유). DB는 영향 없음 |
| 로그 파일 `logs/geosan.log` | 파일 | JSON 한 줄 로그 | 관측 | 로그만 손실, 동작 영향 없음 |
| 브라우저 | 클라이언트 | React 화면, localStorage(담당자명·접힘 상태) | 편의 정보만 | 새로고침으로 복구 |

## 2. 프로세스 안의 경계 (부품 = 폴더 = PR 경계)

```
[브라우저] ──HTTP──▶ api/ ──▶ workflows/flow_evaluate ──▶ evaluation/ ──▶ rules/ (순수)
                      │                                  ├──▶ capability/ (활성 묶음만)
                      │                                  ├──▶ opportunity/, evidence/
                      │                                  └──▶ questions/ (후보 저장)
                      └──▶ records/ (의견)          commands/ ──▶ 위와 같은 흐름·투입 함수
                                                    storage/ (연결·세션·마이그레이션) ← 모든 부품
```

- 쓰기 경계: 각 부품은 자기 접두사 테이블만 쓴다(C6). 교차 참조는 ID만.
- 실패 경계: 한 흐름 = 한 트랜잭션. 흐름 밖 부품 실패(예: 설정 읽기)는 시작 거부로 바뀌어 부분 상태가 생기지 않는다.
- 변경 경계(팀원 분업): `rules/`(유동렬) ↔ `storage/`·`api/`·`commands/`·부품 모델(이강욱) ↔ `web/`(고선주). 함께 고치는 것은 `contracts/`(PM)와 `web/src/labels/`(추가만).

## 3. NFR 패턴이 붙는 자리

| NFR 설계 | 구성 요소·폴더 |
|---|---|
| 요청 로그·ref·중단 한도 | `api/` 미들웨어·예외 처리기 |
| 담당자 키 검증 | `api/` 의존성 함수 |
| 파일·설정 검사기, 연락처 패턴 | `config/validators`(공용), `commands/` |
| 묶음 분리(datasetKind 필수 인자) | `capability/` 조회 함수 |
| 트랜잭션·되돌림 | `workflows/`, `storage/` 세션 |
| 결정성·HALF_UP | `rules/` |
| 평가 시점 계산 저장(순위·문구) | `evaluation/` |
| FORBIDDEN 제외 | `evidence/` 조회 함수, 로그 포매터 |
| 색인·마이그레이션 | `migrations/`, `storage/` |
| 띠·다섯 상태·접근성·대응표 | `web/src/components`, `web/src/labels` |

## 4. 공유 자원

| 자원 | 공유하는 것 | 규칙 |
|---|---|---|
| SQLite 파일 | 서버 프로세스 + 명령 프로세스 | WAL, busy_timeout 5초, 쓰기는 짧은 트랜잭션 |
| 설정 파일 | 서버·명령 | 시작 때 읽음, 바꾸면 재시작(뼈대). 규칙 설정은 해시 대조 |
| `contracts/` | 모든 PR | PM 확인 뒤에만 변경, `export-contracts`는 사람이 실행 |
| 대응표 `web/src/labels/` | 화면 PR 전부 | 추가만, 기존 키 변경 금지 |

## 5. 장애 범위 요약

- 뼈대의 장애 범위는 "앱 프로세스 하나"이며, 그 안의 어떤 부품 실패도 트랜잭션 되돌림으로 데이터 일관성을 지킨다. 데이터 파일 손상만이 전체 복구(백업 복사)를 요구한다.
- 11월: U8이 호스팅·접속 보호·백업 명령을, U2가 외부 호출 경계(타임아웃·재시도 1회·전송 보호)를 각자의 폴더(`api/session`, `evidence/adapters`, `transfer/`)에 더한다. 이 표의 경계는 바뀌지 않는다.

## 상류 문서와의 연결

- NFR 설계 5개 문서(이 폴더), 기술 묶음 2장 저장소 구조.
- 작업 단위 U1 확장 지점 규칙, 부품 목록 15개 중 뼈대 10개(최소형).
- 계약 C2(흐름 = 트랜잭션), C6(접두사 소유·공유 자원).
