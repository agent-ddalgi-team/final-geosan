# 성능 설계 (Performance Design) — U1 뼈대 (u1-skeleton)

성능 요구(`../nfr-requirements/performance-requirements.md` NFR2.x·NFR8.x)를 어떻게 지킬지의 설계입니다. 뼈대는 단일 프로세스·SQLite 한 파일·팀 노트북이라 "적게 읽고, 미리 계산해 저장하고, 쪽 단위로 보인다"가 전부이며, 캐시는 두지 않습니다(확인된 답변 Q1).

## 1. 설계 원칙

1. **평가 때 계산, 조회 때 읽기만**: 순위(originalRank)·분류·점수 문구(scoreDisplay)·막는 조건(blocksApproval·blockerText)·추천 이유·다음 할 일은 평가 시점에 확정해 EvaluationRun에 저장한다(규칙 BR10.1~10.3). 목록·상세 조회는 계산을 하지 않는다.
2. **쪽 단위 읽기**: 목록은 20건(최대 50건)만 읽고 전체를 메모리에 올리지 않는다(NFR3.10).
3. **캐시 없음**(Q1 A): 갱신 시각·재평가됨 표시가 항상 맞게 유지된다. 측정에서 목표(3초)를 넘을 때만 다음 단위에서 검토한다.
4. **긴 작업은 명령으로**: 전체 평가·파일 투입은 명령줄에서만 돌고 화면 요청 경로에서는 1초 넘는 작업이 없다.

## 2. 조회 경로 설계

| 경로 | 읽는 것 | 설계 | 목표 |
|---|---|---|---|
| 목록 `GET /opportunities` | 최신 FULL 묶음 1행 → 그 묶음의 EvaluationRun 20행(순위순) → 기회·고객 이름 → 각 기회의 최신 확정 평가(부분 재평가 반영) → 현재 의견 | 조회 4~5개를 한 연결에서 순서대로. 색인: (batchId, originalRank), (oppId, runStatus, createdAt), (oppId, version) | 서버 1초, 화면 3초(NFR2.1) |
| 상세 `GET /opportunities/{oppId}` | 기회·고객·최신 평가·항목 판정 8행·요구 판정·공정 연결·근거(FORBIDDEN 제외)·질문 연결·현재 의견 | 영역별 구성 함수가 각각 한 번씩 조회(총 8개 안팎). 스냅샷 JSON은 읽지 않고 저장된 열만 | 서버 1초(NFR2.2) |
| 설정 `GET /config/ui` | 앱 설정(담당자·브랜드·대응표) | 서버 시작 시 읽어 메모리에 두고 파일 변경 시 재시작(뼈대) | — |

## 3. 평가 경로 설계

- 전체 평가는 기회를 하나씩 순서대로 계산한다(단순·결정적). 기회당 조회(스냅샷 재료)는 6~8개, 저장은 평가 1행 + 항목 8행 + 요구 판정 N행 + 근거 연결 + 공정 연결 갱신 + 질문 upsert.
- 묶음 하나 = 트랜잭션 하나이므로 2,000건 전체 평가도 한 트랜잭션이다. 10분 안(NFR2.5)을 지키기 위해 기회당 300ms를 목표(NFR3.11)로 하고, 거산 값 스냅샷(활성 묶음의 공정·자격·범위)은 묶음 시작 때 한 번만 읽어 모든 기회에 재사용한다.
- 규칙 엔진은 순수 함수라 입력 구조체를 넘기면 수 ms에 끝난다. 병목은 DB 쓰기이며 WAL + 한 트랜잭션으로 묶어 fsync를 묶음당 1회로 줄인다.

## 4. 화면 성능

- React 번들은 Vite 기본 분할만 쓰고 Ant Design은 필요한 부품만 가져온다(트리 셰이킹). 목표 1MB 이하(NFR2.10).
- 목록·상세 요청은 10초 중단 한도(AbortController), 1초 뒤 자리표시, 5초 뒤 "조금 오래 걸리고 있습니다"(NFR2.11·2.12).
- 의견 저장은 낙관적 표시 없이 응답 뒤에 "저장됨"을 보인다(NFR2.13). 500ms 목표라 체감 차이 없음.

## 5. 측정 설계

- 서버는 요청마다 소요 ms를 로그에 남긴다(관측 설계). 체크포인트 때 가상 50건 + A정밀로 10회 측정해 p95를 `tests/perf-notes.md`에 적는다(NFR2.1~2.4·2.6~2.10).
- 목표를 넘으면 순서대로 본다: 색인 누락 → 조회 수(N+1) → 스냅샷 크기 → 그 다음에야 캐시.

## 상류 문서와의 연결

- 성능 요구 NFR2.1~2.15, NFR8.1~8.4; 규모 요구 NFR3.10·3.11·3.13; 기술 묶음(Vite·Ant Design·SQLite WAL).
- 기능 명세 W3·W5·W6·W7, 규칙 BR10.1~10.3.
- 계약 C1(쪽 단위), 3장(응답 시간 목표 vs 중단 한도).
